\title{A Materialised Three-Way Merge for AegisSheet\\
  \large Exploratory research note}
\author{FP Launchpad}
\date{2 September 2026}
\begin{document}
\maketitle

\begin{abstract}
The verified AegisSheet model stores the whole event history and merges by
union; each event carries the timestamp set of its causal past, so state is
quadratic in history length. This note asks whether the ancestor argument of
a three-way merge can replace that metadata. We define a materialised state
with a componentwise three-way merge and test it differentially against the
existing model on random version DAGs. No counterexample appears in 3000
executions when a removal names the tokens it kills; clearing tokens instead
converges but breaks commutation. Three hand-derived witnesses, checked by
the executable reference, show that the last position of a removed row or
column cannot be dropped while a concurrent revival is possible, so the
retention residue includes one register per axis identifier ever positioned;
no register collector is certified. Python stored-item measurements are
consistent with linear rather than quadratic growth over the measured range.
Under the current model's purge semantics a mask of cutoff and
coordinates per marker is needed, because that model deliberately masks
writes concurrent with the marker and below its cutoff; under decision D2,
which keeps such writes, purge is plain deletion with no residue, because the
framework's merge base is canonical for the exact intersection of the branch
histories. No acknowledgement protocol is needed either way: dead identifiers
can be retired immediately once the register is kept. Lean proves conditioned
Join, replay adequacy, and purge-free state/replay correspondence with the
union model. This is not equivalence of admitted executions: inverse writes
have stricter issuance, and the converse requires honest undo. The datatype's
own-fold certificate and evidence-free retirement are machine-checked;
retirement also preserves the complete issuance guard. The Python campaign
provides separate validation evidence, not a proof about a deployed runtime.
\end{abstract}

\section{Goal, hypotheses, and status}

\paragraph{Goal.} Re-encode AegisSheet as a genuine three-way MRDT with a
materialised state so that the lowest-common-ancestor argument of $\merge$
replaces the per-event causal set, the append-only event log, and, where
possible, the roster-acknowledged purge protocol, while preserving every
observation of the current model.

\paragraph{Hypotheses and falsifiers.}
\begin{description}
\item[H1] Cells and axes forget. A state of live keep tokens, latest-position
registers, active cell versions, and active range versions, merged
componentwise by the rule $\mvr(l,a,b)=(l\cap a\cap b)\cup(a\setminus l)
\cup(b\setminus l)$ for sets and last-writer-wins for registers, yields the
same observation as the union model at every reachable version.
Falsifier: a version DAG on which the observations differ, two merge
topologies over one event set that disagree, or a merge that differs from
replaying the union.
\item[H2] The latest position of a removed axis identifier can be dropped
once no live range names it. Falsifier: two histories with identical live
sheets whose continuations require different positions for the identifier.
\item[H3] Purge dissolves into ordinary version deletion once state is
materialised. Falsifier: a late concurrent write that revives content the
paper requires to stay purged.
\end{description}

\paragraph{Status.} Table~\ref{tab:status} uses the evidence vocabulary
conjectured, refuted, machine-checked, validated, measured, specified, and
staged. The witnesses of Sections~\ref{sec:h2} and~\ref{sec:undo} are
machine-checked as SPOTs against the current model
(\lean{Instances/AegisSheetRetentionSPOT.lean}). The port's proved claims and
their hypotheses are listed in Section~\ref{sec:mech}; state/replay
correspondence does not identify the two issuance languages.
The Python reference is validated against the Lean model only on the

\section{The reference model}
\label{sec:reference}

The displays below transcribe the Lean definitions named in each definition's
title. The purge marker's fields and its masking clause are stated in
Section~\ref{sec:h3} rather than displayed here (labelled compression).

\begin{definition}[events and state; \lean{SheetOp}, \lean{D}]
An event is $e=(t,r,\langle\seen,\mathit{cmd}\rangle)$ with Lamport
timestamp $t$, replica $r$, a finite set $\seen$ of timestamps, and a command
that is either a direct action or $\mathsf{undo}(t',\mathit{inv})$ carrying
an inverse action. The effect $\mathsf{action}(e)$ is the direct action or
$\mathit{inv}$. Actions are
\[
\begin{aligned}
&\mathsf{axis}(\mathit{kind},\alpha,\mathit{id},\mathit{before},\mathit{after})
 &&\alpha\in\{\Row,\Col\},\ \mathit{kind}\in\{\mathsf{insert},\mathsf{move},\mathsf{remove},\mathsf{restore}\},\\
&\mathsf{cell}(\rho,\gamma,\mathit{before},\mathit{after},\mathit{overwrites})
 &&\mathit{before},\mathit{after}\text{ finite value sets},\ \mathit{overwrites}\text{ timestamps},\\
&\mathsf{range}(\mathit{id},\mathit{before},\mathit{after},\mathit{overwrites})
 &&\mathit{before},\mathit{after}\in\mathsf{Option}(\mathit{RangeSpec}).
\end{aligned}
\]
The MRDT state is a finite set $E$ of events; $\mathsf{do}(E,e)=E\cup\{e\}$;
$\merge(\_,a,b)=a\cup b$. The ancestor argument is unused.
\end{definition}

\begin{definition}[axis liveness; \lean{keepsAxis}, \lean{removesAxis}, \lean{axisLive}]
An event $e$ \emph{keeps} $(\alpha,\mathit{id})$ when it is an axis update of
that identifier with $\mathit{after}\neq\bot$, or a cell update whose
$\alpha$-coordinate is $\mathit{id}$. It \emph{removes} $(\alpha,\mathit{id})$
when it is an axis update of that identifier with $\mathit{after}=\bot$.
\[
\begin{aligned}
\mathsf{keepTimes}_E(\alpha,\mathit{id})&=\{t(e)\mid e\in E,\ e\text{ keeps }(\alpha,\mathit{id})\},\\
\mathsf{removed}_E(\alpha,\mathit{id},\tau)&\Longleftrightarrow
 \exists e\in E.\ e\text{ removes }(\alpha,\mathit{id})\land\tau\in\seen(e),\\
\live_E(\alpha,\mathit{id})&\Longleftrightarrow
 \mathsf{known}_E(\alpha,\mathit{id})\land
 \exists\tau\in\mathsf{keepTimes}_E(\alpha,\mathit{id}).\ \neg\mathsf{removed}_E(\alpha,\mathit{id},\tau),
\end{aligned}
\]
where $\mathsf{known}_E$ holds when some axis update of the identifier is in
$E$. A removal defeats exactly the keep tokens it observed; a keep it did not
observe survives it.
\end{definition}

\begin{definition}[positions, cells, ranges; \lean{axisPositions}, \lean{cellValues}, \lean{rangeValues}]
A candidate for $(\alpha,\mathit{id})$ is an axis update with
$\mathit{after}\neq\bot$; $\mathsf{positions}_E(\alpha,\mathit{id})$ is the
set of $\mathit{after}$ values of candidates with no later candidate, a
singleton or empty. A cell version $e$ at $(\rho,\gamma)$ is overwritten when
some cell update in $E$ lists $t(e)$ in its $\mathit{overwrites}$;
$\cells_E(\rho,\gamma)$ is the union of $\mathit{after}$ over non-overwritten
versions when both axes are live, and $\emptyset$ otherwise. Range versions
are analogous, and $\ranges_E(\mathit{id})$ collects their non-$\bot$
$\mathit{after}$ specifications.
\end{definition}

\begin{definition}[range resolution; \lean{resolveRange}]
For a specification $(\rho_1,\rho_2,\gamma_1,\gamma_2)$, a live endpoint
resolves to itself. A dead first endpoint resolves to the live identifier at
the least live position greater than the endpoint's last position; a dead
last endpoint to the live identifier at the greatest live position less than
it. Resolution fails when an endpoint has no position or the resolved
rectangle is inverted.
\end{definition}

\begin{definition}[issuance; \lean{applicableB}, \lean{validUndo}, \lean{inverseFor}]
An event is issuable at $E$ when $t(e)\notin\mathsf{times}(E)$,
$\seen(e)=\mathsf{times}(E)$, $t(e)$ exceeds every timestamp in $E$, and its
before-image and $\mathit{overwrites}$ list equal the current values at $E$
(compressed: the per-kind clauses of \lean{directApplicable}). An undo is
issuable when its target is in $\seen(e)$, was issued by the same replica,
and the carried inverse equals $\mathsf{inverseFor}$ of the target, which
swaps before and after and sets $\mathit{overwrites}=\{t(\text{target})\}$
for cells and ranges. No clause requires the axes of an undone cell write
to be live.
\end{definition}

The clause $\seen(e)=\mathsf{times}(E)$ is the cost this note attacks: every
event stores the timestamp set of its entire causal past.

\section{The candidate design}
\label{sec:design}

\begin{definition}[materialised state]
\[
\begin{array}{ll}
\mathsf{known}:\{\Row,\Col\}\to\mathcal P(\mathit{Id}) & \text{grow-only identifier sets},\\
\tok:(\{\Row,\Col\}\times\mathit{Id})\to\mathcal P(\mathit{Ts}) & \text{live keep tokens},\\
\pos:(\{\Row,\Col\}\times\mathit{Id})\rightharpoonup\mathit{Ts}\times\mathit{Position} & \text{latest position register},\\
\cells:(\mathit{Id}\times\mathit{Id})\to\mathcal P(\mathit{Ts}\times\mathcal P(\mathit{Value})) & \text{active cell versions},\\
\ranges:\mathit{Id}\to\mathcal P(\mathit{Ts}\times\mathsf{Option}(\mathit{RangeSpec})) & \text{active range versions}.
\end{array}
\]
A removal carries $\mathit{kills}$, the live tokens of its identifier at
issuance (the \emph{named} variant); the \emph{clearing} variant carries
nothing and empties the token set.
\end{definition}

\begin{definition}[update]
\[
\begin{aligned}
\mathsf{axis}(\_,\alpha,\mathit{id},\_,p\neq\bot)&:\ \tok(\alpha,\mathit{id})\mathrel{+}=\{t\},\quad
 \pos(\alpha,\mathit{id}):=\max_{\mathrm{ts}}(\pos(\alpha,\mathit{id}),(t,p)),\quad \mathsf{known}\mathrel{+}=\mathit{id};\\
\mathsf{axis}(\_,\alpha,\mathit{id},\_,\bot)&:\ \tok(\alpha,\mathit{id})\mathrel{-}=\mathit{kills}
 \quad(\text{clearing: }\tok(\alpha,\mathit{id}):=\emptyset);\\
\mathsf{cell}(\rho,\gamma,\_,v,\mathit{ov})&:\ \tok(\Row,\rho)\mathrel{+}=\{t\},\ \tok(\Col,\gamma)\mathrel{+}=\{t\},\\
 &\quad\cells(\rho,\gamma):=\{x\in\cells(\rho,\gamma)\mid \mathrm{ts}(x)\notin\mathit{ov}\}\cup\{(t,v)\};\\
\mathsf{range}(\mathit{id},\_,s,\mathit{ov})&:\ \ranges(\mathit{id}):=\{x\in\ranges(\mathit{id})\mid\mathrm{ts}(x)\notin\mathit{ov}\}\\
 &\qquad\cup\{(t,s)\}.
\end{aligned}
\]
\end{definition}

\begin{definition}[merge]
For $\mvr(l,a,b)=(l\cap a\cap b)\cup(a\setminus l)\cup(b\setminus l)$,
\[
\begin{aligned}
\merge(l,a,b).\mathsf{known}&=l.\mathsf{known}\cup a.\mathsf{known}\cup b.\mathsf{known},\\
\merge(l,a,b).\tok(k)&=\mvr(l.\tok(k),a.\tok(k),b.\tok(k)),\\
\merge(l,a,b).\pos(k)&=\max_{\mathrm{ts}}\{x.\pos(k)\mid x\in\{l,a,b\},\ k\in\mathrm{dom}(x.\pos)\},\\
\merge(l,a,b).\cells(k)&=\mvr(\ldots),\qquad
\merge(l,a,b).\ranges(k)=\mvr(\ldots).
\end{aligned}
\]
The observation is computed as in Section~\ref{sec:reference} with
$\live(\alpha,\mathit{id})\Leftrightarrow\mathit{id}\in\mathsf{known}(\alpha)
\land\tok(\alpha,\mathit{id})\neq\emptyset$ and the register in place of the
latest candidate.
\end{definition}

The design has no cross-component rule. The reference's update-wins policy
(a concurrent write or move defeats a removal) is already token-based: the
write's token is not in the ancestor, so $\mvr$ keeps it. Every component is
an observed-remove set or a last-writer-wins register.

\section{H1: differential campaign}
\label{sec:h1}

\begin{conjecture}[H1]
For every legal execution of the version-DAG semantics with the
canonical virtual merge base, the materialised design with named removal has
the same observation as the union model at every version.
\end{conjecture}

\paragraph{Method.} The harness (\lean{model.py}) runs the Python
reference and each materialised variant in lockstep on random version DAGs.
Operations are generated from the reference state so that before-images,
overwrite lists, and killed-token lists are those the issuance predicate
demands; identifiers are fresh by construction and timestamps come from
per-replica Lamport clocks, so a stale replica can issue events below another
replica's cutoff. Replica $0$ issues purge markers under the Lean rule
\lean{purgeApplicable}, with roster acknowledgements from frontier evidence.
Two to four replicas perform one to three operations each per round for three
to eight rounds; a merge between two heads occurs with probability $0.7$ per
round; with probability $0.5$ one laggard replica never merges until the
forced convergence rounds, which then merge all heads along different
topologies.
When a recorded version's event set equals the heads' intersection it is the
ancestor; otherwise the ancestor is the fold of the intersection in
timestamp order, which is the canonical virtual merge base. At every version
the harness compares observations, compares observations of versions
reached by different topologies over the same event set, and compares the
merge result with the timestamp-order replay of the union. Every generated
event, after erasing $\mathit{kills}$, is checked against a transcription of
\lean{applicableB} and \lean{clockedB}; all 90{,}859 events of the three
seeds pass, so the executions are honest in the Lean sense and not only in
the generator's. The generator applies decision D1
(Section~\ref{sec:undo}): an inverse cell write is issued only while its
axes are live.

\paragraph{Result.} Table~\ref{tab:campaign} reports three seeds of 1000
executions; an execution counts against every design that fails in it. The
named-removal design with purge masks has no failing execution. The clearing
variant matches the reference and converges but fails the replay comparison:
a removal that clears all tokens and a concurrent keep do not commute, so
replay order matters and a Lean proof would need the arbitration arm of the
replay policy. The named variant makes every \emph{concurrent} pair commute.
Causally ordered pairs still do not: a keep followed by the removal that
names its token leaves the token absent, the reverse order leaves it
present, and the same holds for an overwrite and the version it names. So
universal commutation fails and the all-commuting proof route is
unavailable; Section~\ref{sec:mech} gives the conditioned route instead.

\section{H2: the last position of a dead axis is load-bearing}
\label{sec:h2}

Each witness is hand-derived from the definitions of
Section~\ref{sec:reference}, checked by evaluating the Python reference
(\lean{h2\_witnesses}, \lean{h2\_pair3}), and machine-checked by
\lean{native\_decide} against the Lean model in
\lean{Instances/AegisSheetRetentionSPOT.lean}, each with the legality of
every step and a FAIL companion pinning the tempting wrong answer.
Identifiers: rows $r_0,r_1,r_2$ at positions $10,20,30$, column $c_0$.

\begin{counterexample}[range resolution]
Let $L$ insert $r_0,r_1,r_2,c_0$ and a range $(r_0,r_2,c_0,c_0)$. History
$W_1$ removes $r_0$. History $W_2$ moves $r_0$ to position $25$ and then
removes it. Both leave live rows $\{r_1,r_2\}$ at unchanged positions and
the same range specification. The reference resolves the range to
$(r_1,r_2,c_0,c_0)$ after $W_1$ and to $(r_2,r_2,c_0,c_0)$ after $W_2$. A
state that forgets $r_0$'s last position cannot give both answers.
\end{counterexample}

\begin{counterexample}[eager re-anchoring]
From the same $L$, branch $A$ removes $r_0$ and branch $B$ concurrently
inserts $r_3$ at position $15$. The reference resolves the merged range to
$(r_3,r_2,c_0,c_0)$. Rewriting the range to $r_0$'s successor at removal
time gives $(r_1,r_2,c_0,c_0)$. Lazy resolution over the dead position is
part of the specification, not an implementation choice.
\end{counterexample}

\begin{counterexample}[update-wins revival]
Let $L$ insert $r_0$ at $10$ and $c_0$, and write cell $(r_0,c_0)$. Branch
$A_1$ moves $r_0$ to $52$ and then removes it; branch $A_2$ only removes it.
Both branch states have identical live sheets: $r_0$ is dead. Branch $B$
concurrently writes $(r_0,c_0)$. In both merges the write's token revives
$r_0$; the reference places it at $52$ after $A_1$ and at $10$ after $A_2$.
The merge receives identical $L$ and $S_B$, so if $S_{A_1}=S_{A_2}$ it
cannot answer both. The information lives only on the removing branch.
\end{counterexample}

The third counterexample does not involve ranges or undo, and it survives
the D1 issuance rule (35 to 41 failing executions of 1000 per seed for the
register-dropping variant). The
implemented retention rule keeps one position register per identifier ever
positioned. These witnesses refute dropping it at removal; they do not prove
that causal stability is sufficient to collect it. Range resolution can
still read a dead endpoint, and the legacy undo rule can revive it even
after observing the removal. D1 excludes that undo revival but does not
establish a register collector. The certified collector drops only dead
\lean{known} entries, leaving the register unchanged.

\section{Finding: undo revives a causally later removal}
\label{sec:undo}

\begin{finding}
In the current model, with row $r_0$ and column $c_0$ and a write at $t=3$,
removing $r_0$ at $t=4$ and then undoing the $t=3$ write at $t=5$ is a legal
history on one replica: the undo's target is observed and was issued by the
same replica, and no issuance clause requires the axes to be live. The undo
is a cell event and therefore a keep token for $r_0$ with a timestamp the
removal did not observe. The row becomes live again at position $10$ with an
empty cell. Reproduced by \lean{undo\_revival\_witness} and machine-checked
as \lean{undo\_revives\_later\_removal}.
\end{finding}

Table~4 of the paper covers undo against a \emph{concurrent} removal; it
does not say what undoing an edit should do to a row removed causally later.
The behaviour is a consequence of representing undo as a cell event. If it is
unintended, the fix is an issuance clause (undo of a cell write requires live
axes) or a non-keeping inverse; either changes the public sequential
specification.

\paragraph{Decision D1.} No revival, as an issuance rule: an inverse cell
write is legal only while its row and column are live. The legacy revival
behaviour stays documented by this finding and its SPOT. The converse in
Section~\ref{sec:mech} starts from issued port executions and additionally
requires honest undo. The forward theorem produces a materialised fold even
for legacy union histories; it does not assert that those operations are
issuable by the port.

\section{H3: purge and retirement}
\label{sec:h3}

The harness generates purge markers under the current model's issuance rule
and transcribes the marker semantics of \lean{AegisSheetGC.lean}: a marker
carries a cutoff, a set of dead coordinates, the covered cell versions, and
roster acknowledgements; it masks every cell version at those coordinates
with timestamp at or below the cutoff, including versions that arrive later
from a stale branch. The Python reference reproduces the five marker fixtures
of that file (the marker is issuable after the removal, a restored row shows
no purged content, a post-cutoff write is issuable and visible).

\paragraph{Strict deletion is refuted under the current semantics.} A materialised purge that deletes
the covered versions and stores nothing diverges from the reference in $6$,
$3$, and $3$ executions per 1000. Every case has the same shape: a replica
that has not observed the marker writes into a purged coordinate with a
Lamport timestamp at or below the cutoff; the reference masks the write
permanently, the strict design keeps its version, and the write's keep token
revives the axis so the difference is visible. This is the current model's
chosen semantics for a late concurrent edit, and the $\mvr$ rule alone
cannot express it because the write is absent from the ancestor.

\paragraph{A mask suffices for the current semantics.} Keeping, per marker,
the pair (cutoff, coordinates) and filtering versions through the accumulated
masks at apply and at merge reproduces the current model with no failing
execution. The marker's covered entries are unnecessary because tokens live
in their own component, and its acknowledgements are unnecessary for the
merge.

\paragraph{Under D2 nothing is retained.} Decision D2 keeps a write
concurrent with a purge and below its cutoff; the marker then masks exactly
the versions it covered. Against that reference, plain deletion with no
stored mask has no failing execution in 3000, including 461 merges at a
virtual base, and a covered-set tombstone design is likewise clean but
unnecessary. The reason is a framework theorem rather than a property of the
sheet: the merge base is canonical for the exact intersection of the two
branch histories (\lean{gca\_events\_of\_storeInv},
\lean{virtualMergeBaseState\_canonical}), so a purged version that reached
the other branch is present in the base, absent from the purging branch, and
removed by $\mvr$. The compact cutoff mask, run against the D2 reference,
fails on exactly the concurrent writes D2 keeps ($6$, $3$, $3$ per 1000),
which is the whole difference between the two semantics.

\paragraph{Retirement needs no acknowledgements.} Three retirement rules
for a dead identifier were tested: immediately when dead; when every roster
member has authored any event (frontier evidence, the rule
\lean{frontierAcknowledgements} encodes); and when every roster member has
authored the removal or an event whose causal past contains it (descendant
evidence). All three drop the identifier's token set and \lean{known} entry
and keep its position register, and all three have no failing execution. The
reason is structural: a stale branch on which the identifier is still live
carries its own \lean{known} entry and tokens, and the merge unions
\lean{known} and applies $\mvr$ to tokens, so a late concurrent keep revives
the identifier correctly whatever the other branch forgot. Dropping the
register instead fails (Table~\ref{tab:campaign}), and dropping it only when
no live range names it fails too, because an undone range edit can name the
identifier again and the decision would then depend on the order in which
references appeared rather than on the event set.

\paragraph{D1 is load-bearing for retirement.} Under the legacy undo rule
(\lean{--legacy-undo}, seed 7) immediate retirement fails $53$ of 1000 and
descendant retirement $2$ of 1000: an undone cell write revives an identifier
whose \lean{known} entry is gone, so the reference shows it live and the
materialised state does not. The no-retirement baseline stays clean under
both rules.

\paragraph{Consequence.} The roster acknowledgement protocol of the current
model plays no role in the materialised design's convergence, masking, or
retirement. The port deliberately requires neither acknowledgements nor a
designated issuer. Its guard requires covered versions present in the state,
valid cutoff/coordinate metadata, and dead coordinates. These conditions
apply even when the carried command is an inverse; a purge cannot bypass
them by using the undo constructor.
Decision D2 (taken): keep a write concurrent with a purge and below its
cutoff. The materialised purge is then plain deletion, and the sequential
specification of the port masks exactly the covered versions. The harness
follows D2 by default; \lean{--legacy-purge} restores the current model's
cutoff clause as a control, under which the cutoff-mask design is the one
that is clean.

\paragraph{Lean status.} The materialised design is a product of
observed-remove sets and one last-writer-wins register. Because causally
ordered pairs do not commute, the all-commuting route is closed; the port
went through \lean{JoinOn} under the honesty predicate \lean{Honest} on the
replay context (every removal's $\mathit{kills}$, every overwrite's
$\mathit{overwrites}$, and every purge's covered entries lie in the issuer's
causal past), discharged from issuance by \lean{IssuanceEstablishes}.
Update preservation needed a premise absent from the first statement: an
arbitrary event set may carry overwrites at foreign coordinates or causal
summaries outside its own timestamps, and for such sets the claim is false.
\lean{HonestHistory} names the four invariants that every history reached by
applicable insertions has (causal summaries within the history's timestamps,
timestamps identifying events, valid metadata, covered entries naming cell
events), and \lean{HonestHistory.insert} shows applicable insertion preserves
them. Under it the union model's coordinate-blind overwrite clause becomes
the materialised per-coordinate filter (through \lean{metadataValidB} and
timestamp uniqueness), and a token is live after an insertion exactly when it
was live before and the event does not remove its identifier, or the event
keeps the identifier at its own timestamp
(\lean{mem\_liveAxisTokens\_insert}); the purge marker's contribution to the
keep set is absorbed because every covered entry names a cell event already
present.

The concurrent case generalises the past: for an honest history $E$, a
past $P \subseteq E$, and an event $e$ applicable at $P$ with a timestamp
fresh in $E$, $\mathsf{do}(\mathit{canon}(E), \mathit{toM}(P,e)) =
\mathit{canon}(E \cup \{e\})$. The register needs a last-writer argument (a
latest candidate sits in the canonical register), and the tokens need one
bridge: a token live in $E$ is live in $P$ exactly when $P$ knows its
timestamp (\lean{live\_past\_iff}), so the removal's $\mathit{kills}$
computed at $P$ kill exactly the tokens the union model's
$\mathit{seen}$-based removal kills. An issue-ordered history pairs each
event with such a past; \lean{Issued.fold} folds it to the canonical state.
\lean{cross\_model} then takes every version of a certified execution of the
union model, sorts its events by timestamp (visibility respects timestamps),
pairs each with its causal past from \lean{MintHonest}, and obtains the
materialised fold as the version's canonical state, with equal observations
on purge-free versions. The package \lean{verified : VerifiedMRDT M} closes
the framework side with the datatype's own fold as sequential machine, as
the other flat instances do.

The converse direction holds on purge-free executions with honest undo.
The port's issuance is \lean{mEffect} together with, for direct commands,
\lean{mBefore}: the union model's guards \lean{currentAxisPositions},
\lean{cellValues}, and \lean{rangeValues} against the operation's recorded
before-image, read through the materialised observers. An undo has no
before-image clause; the union model validates an undo against its event set
(\lean{validUndo}), which no materialised state decides, so \lean{UndoHonest}
is a premise on the execution: every undo names an operation of the issuer's
causal past, by the same issuer, whose computed inverse it carries. The
port's replay witnesses are not causal (its proof order relates only
non-commuting pairs), so the proof sorts a version's events by timestamp,
shows by \lean{fold\_eq\_of\_enums} that any two order-respecting
enumerations of one set fold to the same state at an honest context, and
aligns the sorted list prefix by prefix with an issue-ordered union-model
history, lifting each event at the lift of its mint-time past
(\lean{applicable\_of\_mApplicable} transfers the guard). Purges are
excluded by design on both sides: under D2 the port deletes covered
versions while the union model masks by cutoff, and the two observations
differ on concurrent sub-cutoff writes. The union model's own sequential
specification already materialises: \lean{clientSpec} runs a token,
position, cell, range, and purge state with causal-origin legality; the
design here promotes that sequential state to the replicated state.
\lean{no\_view\_only\_step} shows the visible sheet is insufficient as a
state, and \lean{row\_tokens\_distinguish\_future},
\lean{cell\_versions\_distinguish\_future}, and
\lean{range\_versions\_distinguish\_future} fix that tokens, cell version
identities, and range version identities must be retained, which the
materialised state does.

\section{Open obligations}

\begin{enumerate}
\item Decision D1 is implemented. Selective undo of one among several active
cell or range versions remains refused by the port, unlike the union model.
Changing that restriction requires a separate specification decision.
\item Decision D2 (keep) is taken; the Lean port's purge is plain deletion
and its sequential specification masks exactly the covered versions.
\item \lean{JoinTarget}, the replay-adequacy certificate,
\lean{ObservationEquivalence}, \lean{UpdatePreservesCanon} with issuing
pasts, \lean{Issued.fold}, \lean{cross\_model}, and \lean{verified} are
proved, and so are \lean{converse} and \lean{retirement}. The residue of the
port is exact: live tokens and versions and one register entry per
identifier ever positioned. Adoption in place of the union model is a
product decision, to be preceded by a measurement in the target runtime,
which has no spreadsheet today.
\item Extend the harness to merges between non-head versions and to undo of
undo; report the generator's coverage.
\end{enumerate}

\paragraph{Retirement and issuance.} The old freshness test used only
\lean{known}, so retiring a dead identifier made it appear fresh. The new
test also consults the retained position register. The representation
invariant requires every known identifier to have a position; this holds
initially and is preserved by issued updates and three-way merges.
\lean{Represents.applicable\_iff} proves equality of the entire issuance
decision between compact and full states, and
\lean{update\_represents\_of\_compact} covers operations admitted on the
compact state. The register itself is unchanged by collection.

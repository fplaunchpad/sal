\begin{abstract}
Mergeable replicated data types let users update independent branches and
reconcile them with a three-way merge. Their correctness argument must explain
the state of every stored version, including old versions that later become
merge bases. We show that a published induction for this purpose is unsound:
an event outside the version under consideration can remove an ordering
constraint that the version still needs. We mechanize a counterexample and a
corrected proof in Lean~4. The correction establishes a unique replay result
for each stored event set, then relates that internal result to an independent
single-user specification that checks which operations clients may create and
what queries must return. We also verify local collection of asynchronously
fetched version histories. A replica may discard the root and intermediate
ancestor paths while preserving the reachability and merge-base answers that
future execution needs. This collector composes with datatype-specific removal
of metadata inside retained states. Together, the results give a
machine-checked account of execution, client-visible correctness, and history
reclamation, with an explicit boundary around the unverified runtime.
\end{abstract}

\section{Problem, result, and evidence boundary}

An MRDT stores immutable versions in a Git-like directed acyclic graph
(DAG)~\cite{kaki2019mrdt}. An update extends one replica head. A merge of branch
states $a$ and $b$ reads the state $l$ at their common ancestor and computes
$\merge(l,a,b)$. The state at each registered version should match some
single-user ordering of exactly that version's operations, and its queries
should agree with the datatype's independent sequential specification.

Figure~\ref{fig:execution-shape} is the running execution shape. The graph is
not decoration: apply creates a one-parent version, merge creates a two-parent
version, and a later merge may use an old version as its base. This is why the
correctness invariant ranges over the store rather than only the current
heads.

The development has three results. First, it repairs the replay induction and
extends the proof to histories with several maximal common ancestors. Second,
it connects those internal replay witnesses to legal histories and observations
of an independent sequential datatype. Third, it proves that two forms of
collection preserve the uncollected execution: one removes obsolete versions,
and the other removes datatype metadata inside a retained version.

This boundary matters. A theorem about a semantic MRDT does not by itself
verify an editor widget, a wire decoder, or crash recovery. The JavaScript
runtime is tested against the model-facing fixtures, but it is not extracted
from Lean. Its evidence manifest names the exact Lean package associated with
each released datatype and labels representation experiments separately.

\section{Raw MRDT semantics}

\subsection{The datatype signature}

\begin{definition}[MRDT signature]
An MRDT signature $D$ contains a state type $\state$, an initial state
$\init$, application-operation type $O$, query type $Q$, result type $R$, and
total functions
\[
 \mathsf{do}:\state\to(\mathbb N\times\mathbb N\times O)\to\state,
 \quad \mathsf{query}:\state\to Q\to R,
 \quad \merge:\state\to\state\to\state\to\state.
\]
An event $e=(t,r,o)$ contains a globally unique Lamport timestamp, replica
identifier, and application operation. The execution semantics requires
$e_1\vis e_2$ to imply $t(e_1)<t(e_2)$. In $\merge(l,a,b)$, $l$ is the
common-ancestor state and $a,b$ are the branch states. This function handles
every merge.
\hfill\lean{MRDTSig}
\end{definition}

These functions define the datatype-level computation. The next section lifts
them to executions over version DAGs.

\subsection{Configurations and transitions}

A configuration contains the semantically relevant state
\[
\begin{gathered}
  C=\langle S,H,P,\vis\rangle,\qquad
  \mathit{Timestamp}=\mathit{Replica}=\mathit{Version}=\mathbb N,\\
  \mathit{Event}=\mathit{Timestamp}\times\mathit{Replica}\times O,\\
  S:\mathit{Version}\rightharpoonup
    \bigl(\state\times\mathcal P(\mathit{Event})\bigr),\qquad
  H:\mathit{Replica}\rightharpoonup\mathit{Version},\\
  P:\mathit{Version}\to\mathsf{List}(\mathit{Version}),\qquad
  \vis\;\subseteq\mathit{Event}\times\mathit{Event},\\
  \mathsf{state}:\mathsf{dom}(S)\to\state,\qquad
  \events:\mathsf{dom}(S)\to\mathcal P(\mathit{Event}),\qquad
  S(v)=\bigl(\mathsf{state}(v),\events(v)\bigr)
    \quad(v\in\mathsf{dom}(S)).
\end{gathered}
\]
where $S$ is a partial version store, $H$ maps replicas to heads, $P$ maps a
version to its parents, and $\vis$ is event visibility. Every finite execution
allocates only finitely many entries of $S$. The functions $\mathsf{state}$ and
$\events$ are its state and event-set projections on allocated versions. If
$H(r)=v$, the state and event set at active replica $r$ are
$\mathsf{state}(v)$ and $\events(v)$.

A valid configuration also satisfies the following conditions:
\begin{enumerate}
\item every visibility endpoint occurs in an active event set, visibility is
causally closed at each active replica, and same-replica events are visible in
one direction;
\item distinct stored events have distinct timestamps, and
$e_1\vis e_2$ implies $t(e_1)<t(e_2)$;
\item parent versions have smaller version numbers, version~0 stores
$(\init,\varnothing)$, and every active head names a stored state and event set;
\item if $v_T$ is a greatest common ancestor (GCA) of stored $v_1,v_2$, then
\[
  \events(v_T)=\events(v_1)\cap\events(v_2).
\]
\end{enumerate}
The last condition is part of this semantic model, rather than a property of an
arbitrary Git DAG. The transition rules preserve it.

If $H(r)=v$, applying a fresh event $e=(t,r,o)$ extends visibility from every
event at the issuer head to $e$:
\[
  \vis'\;=\;\vis\ \cup\bigl(\events(v)\times\{e\}\bigr).
\]
Merge does not add an event and therefore leaves visibility unchanged.

Figure~\ref{fig:raw-semantics} gives the four transition forms.
The notation $C[v\mapsto(s,E);r\mapsto v;P(v)\mapsto\pi]$ updates the version
store, replica head, and parent list while preserving all other entries.
The raw \textsc{Apply} rule accepts any application operation with a fresh
timestamp; Section~\ref{sec:generation} later restricts which operations a
client may create. Write $\mathsf{freshTime}(C,t)$ when no event at an active
replica or stored version has timestamp $t$. Checking the store matters because
an old version need not remain an active head. Because the resulting
configuration must also satisfy causal timestamp monotonicity, every event at
the issuer head has timestamp less than $t$.

Here $\mathsf{GCA}_P(v_1,v_2)=v_T$ means that $v_T$ is a common ancestor
reached by every other common ancestor. It is unique if it exists. A history
may instead have several incomparable maximal common ancestors; ordinary
\textsc{Merge} is then unavailable, and Section~\ref{sec:virtual-base} uses all
of those maximal merge bases to construct a virtual base.

The initial configuration has one active replica, numbered~0, at version~0.
\textsc{Fork} creates a fresh child of the source head, with the same state and
event set and with the source version as its sole parent. Apply adds visibility
edges from the issuer's entire current event set to the new event. Merge writes
its result at $r_1$ and leaves $r_2$ unchanged. Thus fork preserves shared
history, merge is not broadcast, and neither fork nor merge introduces an
event or visibility edge. Version numbers also serve as topological ranks. The
premises $v<v'$ in \textsc{Fork} and $v_1,v_2<v_m$ in \textsc{Merge} preserve
the condition that every parent has a smaller number than its child; they do
not order application events.

\section{Why the earlier induction fails}

The published bottom-up induction~\cite{soundarapandian2025automatic} derived
one replay order from every event in the configuration, then used that order
to explain the smaller event set stored at an old version. Consider concurrent,
noncommuting events $e_1,e_2$ and a later event $e_3$ with $e_2\vis e_3$. The
global order sees $e_3$ and removes the edge $e_1\to e_2$. An old version
containing only $\{e_1,e_2\}$ then admits both replay orders even though the
two folds produce different states.

\begin{proposition}[global-order convergence is false]
There is a two-operation add-wins signature and a legal configuration with a
backward-closed event set $E$ such that two enumerations of $E$ both respect
the configuration-global arbitration relation but fold to different states.
\hfill\lean{convergence\_over\_backward\_closed\_subsets\_false}
\end{proposition}

The checked countermodel is in
\code{Metatheory/Join/Convergence\_CounterModel.lean}. The defect is not an
exotic property of that datatype: it is a mismatch between the events used to
define the order and the events being replayed.

The repair defines the replay order relative to both the configuration $C$ and
the set $E$ under consideration. Fix a proof-local replay policy
$\mathsf{rc}(e_1,e_2)\in
\{\mathsf{first},\mathsf{second},\mathsf{either}\}$. Write
$e_1\parallel_C e_2$ when neither event sees the other,
$e_1\rightleftarrows e_2$ when their updates commute, and
$e_1\mathrel{\mathsf{rc}}e_2$ as an abbreviation for
$\mathsf{rc}(e_1,e_2)=\mathsf{first}$. The set-relative replay relation is
then
\begin{align*}
e_1\mathrel{\lo_{C,E}}e_2\quad\Longleftrightarrow\quad
 &\bigl(e_1\vis e_2\land\neg(e_1\rightleftarrows e_2)\bigr)\\
 {}\lor{}&\bigl(e_1\parallel_C e_2\land
 e_1\mathrel{\mathsf{rc}}e_2\land
 \neg\exists e_3\in E.\ e_2\vis e_3\land
   \neg(e_2\rightleftarrows e_3)\bigr).
\end{align*}
In the Lean sources, this relation is \lean{loOn C E}. Only an absorber inside
$E$ may erase an edge needed to replay $E$. We reserve $\lo_C$ for the
configuration-global relation \lean{lo C}, whose absorber existential ranges
over every event in $C$.

The set-relative order repairs the scope of arbitration, but the published
bottom-up construction has a separate failure: state-correct witnesses for the
two inputs need not expose an event that can be peeled through merge.

\begin{example}[The defeater]
\label{ex:defeater}
Let $X$ be the element type and fix $x\in X$. In the published add-wins OR-set case
study~\cite{soundarapandian2025automatic}, a state is a finite set
$S\subseteq\mathbb T\times X$. An event $(t,r,\mathsf{add}(x))$ inserts the
uniquely timestamped record $(t,x)$. An event
$(t,r,\mathsf{rem}(x))$ removes every record $(t',x)$ currently in the state,
regardless of $t'$. A remove and an add of the same element therefore do not
commute; when they are concurrent, the replay policy orders the remove first,
giving add-wins behavior. The three-way merge is
\[
 \merge(l,a,b)=(l\cap a\cap b)\cup(a\setminus l)\cup(b\setminus l).
\]

Let
\[
 A_p=(1,p,\mathsf{add}(x)),\quad A_q=(2,q,\mathsf{add}(x)),\quad
 R_p=(3,p,\mathsf{rem}(x)),\quad R_q=(4,q,\mathsf{rem}(x)).
\]
Replica $q$ first forks from the initial version. Replicas $p$ and $q$ then
issue $A_p$ and $A_q$, respectively. A staging replica $s$ forks from $p$'s
one-add version and merges $q$'s one-add version, producing $v_s$ with
$E(v_s)=\{A_p,A_q\}$. Replica $p$ issues $R_p$ while its causal past is only
$\{A_p\}$, then merges with $v_s$. Symmetrically, $q$ issues $R_q$ with causal
past $\{A_q\}$, then merges with $v_s$. Figure~\ref{fig:defeater} contracts the
snapshot-preserving versions introduced by the two forks.

The final merge is GCA-legal: its GCA is $v_s$, and
\[
 E(v_s)=\{A_p,A_q\}
       =E(\mathsf{head}_p)\cap E(\mathsf{head}_q).
\]
Writing $S(v)$ for the OR-set state at version $v$, the merge calculation is

  state/.style={draw,rounded corners,align=center,inner sep=4pt,font=\small},
  >=Stealth]

Thus every state-correct replay of $p$'s head places $R_p$ before $A_q$ and
ends in $A_q$; symmetrically, every state-correct replay of $q$'s head ends in
$A_p$. A replay of the final union that produces the empty state must instead
end in a remove.
But applying $\mathsf{rem}(x)$ always produces a state containing no record for
$x$, whereas both side heads contain one. Neither head is therefore in the
image of $\mathsf{rem}(x)$, so the bottom-up rules cannot peel the required
final event.

The merged version itself does have a valid witness:
$[A_p,R_p,A_q,R_q]$ folds to $\varnothing$. Its restriction to $q$'s events is
$[A_p,A_q,R_q]$, which also folds to $\varnothing$, not to
$S(\mathsf{head}_q)=\{(1,x)\}$. The merged witness therefore cannot be assembled
from state-correct side witnesses, which is the step required by the published
bottom-up induction.
\end{example}

Associativity, commutativity, and idempotence of merge do not repair the proof.
A different checked countermodel satisfies the core update laws and a bounded
join-semilattice merge but violates both the peel laws and the Join lemma.

These examples establish three boundaries: arbitration must be local to the
set being linearized, a merged witness cannot in general be assembled by
peeling state-correct side witnesses, and convergence needs a contextual bridge
between merge and update history.

\section{Internal replay adequacy}
\label{sec:convergence}

\subsection{Canonical states}

For a list $\pi=[e_1,\ldots,e_n]$, let
$\mathsf{perm}(\pi,E)$ mean that $\pi$ enumerates exactly $E$ without
duplicates. Let $\mathsf{respects}(\pi,R)$ mean that no later list element is
required by $R$ to precede an earlier element. Canonicality is then the
following state predicate:
\[
 \mathsf{Canonical}(C,E,s)\quad\Longleftrightarrow\quad
 \exists\pi.\ \mathsf{perm}(\pi,E)\land
 \mathsf{respects}(\pi,\lo_{C,E})\land
 \mathsf{fold}(\init,\pi)=s.
 \tag*{(Canonical)}
\]
This is \lean{IsCanonicalState}. The update-layer lemmas prove that any two
such enumerations have the same fold under the supplied update conditions.

\begin{definition}[canonical configuration]
$\mathsf{CanonicalConfig}(C)$ holds when every registered version contains a
canonical state of its event set, visibility is transitive and irreflexive,
and every stored event set is supported and causally closed.
\hfill\lean{CanonicalConfig}
\end{definition}
The definition ranges over all versions, not only replica heads, because later
merges may read an older version as their GCA.

Canonicality also yields a witness for the configuration-global replay
relation $\lo_C$, because
$\lo_C|_{E\times E}\subseteq\lo_{C,E}$:
\[
 \begin{aligned}
 \mathsf{ReplayWitness}(C)\quad\Longleftrightarrow\quad
 &\forall v,s,E.\ S(v)=(s,E)\Rightarrow {}\\
 &\exists\pi.\ \mathsf{perm}(\pi,E)\land
 \mathsf{respects}(\pi,\lo_C)\land
 \mathsf{fold}(\init,\pi)=s.
 \end{aligned}
 \tag*{(Replay)}
\]
This per-version replay theorem is an internal adequacy result. It explains an
implementation state as a fold of its operations, but it does not yet prove
that the fold is legal for clients, agrees with an independent abstract state,
or preserves queries. Section~\ref{sec:generation} states the client-facing
theorem that adds those requirements.

\subsection{The ternary Join obligation}

The hypotheses of Join are easy to understate, so we name them explicitly.
Let $\mathsf{WF}(C)$ mean that $\vis$ is transitive and irreflexive. For an
event set $E$, define
\begin{align*}
 \mathsf{Supported}_C(E)
   &\equiv \forall e\in E.\ e\in C.\mathsf{events},\\
 \mathsf{WeakClosed}_C(E)
   &\equiv \forall a,b.\ a\vis b\land\neg(a\rightleftarrows b)
          \land b\in E\Rightarrow a\in E.
\end{align*}
Weak closure retains visible predecessors only when their updates do not
commute. Full causal closure drops the noncommutation premise.

\begin{definition}[contextual ternary Join]
$\mathsf{JoinAt}(D,C)$ holds when, for all $E_1,E_2,s_0,s_1,s_2$,
\[
\begin{array}{l}
 \mathsf{WF}(C),\quad
 \mathsf{Supported}_C(E_1),\quad\mathsf{Supported}_C(E_2),\quad
 \mathsf{WeakClosed}_C(E_1),\quad\mathsf{WeakClosed}_C(E_2),\\[1mm]
 \mathsf{Canonical}(C,E_1\cap E_2,s_0),\quad
 \mathsf{Canonical}(C,E_1,s_1),\quad
 \mathsf{Canonical}(C,E_2,s_2)
\end{array}
\]
imply
\[
 \mathsf{Canonical}\left(C,E_1\cup E_2,
                    \merge(s_0,s_1,s_2)\right).
 \tag*{(Join)}
\]
\hfill\lean{JoinAt}
\end{definition}

its merge-preservation obligation have been defined.

\lean{Join} is $\forall C.\mathsf{JoinAt}(D,C)$. The restricted form
$\mathsf{JoinOn}(D,G)$ is
$\forall C.\,G(C)\Rightarrow\mathsf{JoinAt}(D,C)$. These definitions differ
only in scope: \lean{JoinAt} remains the single merge-preservation obligation.
All-context Join supplies Join under every predicate, and
$\mathsf{JoinOn}(D,\lambda\_.\mathsf{True})$ is equivalent to
$\mathsf{Join}(D)$.
Section~\ref{sec:generation} explains how certified execution can establish
the condition $G$.

\begin{theorem}[ordinary replay adequacy]
If a datatype satisfies \lean{Join}, every configuration reachable from
\lean{initConfig} by \lean{Step} has a valid replay witness at every
registered version.
\hfill\lean{replayWitness\_of\_join}
\end{theorem}

The proof first establishes $\mathsf{CanonicalConfig}(C)$ and then obtains
$\mathsf{ReplayWitness}(C)$ by projecting its canonical-state field and weakening
$\lo_{C,E}$ to $\lo_C$. The induction carries two invariants. \lean{StoreInv} says that parents are
allocated, event sets grow along parent edges, and every event has an allocated
origin version that reaches every version containing it. The origin property
proves the non-obvious half of
$E_T=E_1\cap E_2$: a shared event's origin reaches both branches, hence reaches
their GCA. $\mathsf{CanonicalConfig}$ is the second invariant. Apply appends
its fresh event to a canonical fold; merge invokes Join with the GCA equality;
query and fork preserve both invariants.

The framework packages the eight-condition route as
\lean{CanonicalJoinLaws}. Its components are \lean{JoinCoreLaws},
\lean{FeasibleDeltaLaws}, and \lean{CausalDeltaLaw}. Datatypes may construct
this contract from stronger arbitrary-state equations or prove \lean{Join} or
\lean{JoinOn} directly. A complete
datatype certificate depends on the resulting merge property, not on one
particular decomposition.

\subsection{One reusable proof method for all-context Join}

Join is the semantic convergence obligation. The framework offers a sufficient
decomposition for delta-shaped ternary merges; an implementer may instead
prove Join directly. We state the decomposition fully because its contextual
premises are exactly what an arbitrary-state algebraic account loses.

Recall the proof-local replay policy $\mathsf{rc}$ fixed above. Write
$e\mathrel{\#}e'$ for distinct timestamps and
$\mathsf{rep}(e)\ne\mathsf{rep}(e')$ for different issuers. The three
\lean{ReplayLaws} obligations are:
\begin{align*}
 e_1\#e_2\land\mathsf{rep}(e_1)\ne\mathsf{rep}(e_2)
 &\Rightarrow
 \bigl(\neg(e_1\rightleftarrows e_2)\iff
   \mathsf{rc}(e_1,e_2)=\mathsf{first}\lor
   \mathsf{rc}(e_2,e_1)=\mathsf{first}\bigr),
 \tag*{(U1)}\\
 e_1\#e_2\land e_2\#e_3
 &\Rightarrow\neg\bigl(
   \mathsf{rc}(e_1,e_2)=\mathsf{first}\land
   \mathsf{rc}(e_2,e_3)=\mathsf{first}\bigr),
 \tag*{(U2)}\\
 \mathsf{rc}(e,e')=\mathsf{first}\land
 \neg(e'\rightleftarrows e'')
 &\Rightarrow
 \mathsf{do}(\mathsf{fold}(\mathsf{do}(\mathsf{do}(s,e'),e),\pi),e'')
 \nonumber\\[-1mm]
 &=\mathsf{do}(\mathsf{fold}(\mathsf{do}(\mathsf{do}(s,e),e'),\pi),e'').
 \tag*{(U3)}
\end{align*}
Equation~(U3) also assumes pairwise-distinct $e,e',e''$. These obligations
belong to this reusable proof constructor, not to \lean{MRDTSig} or the public
client interface. \lean{JoinCoreLaws} packages (U1)--(U3) and branch symmetry
\[
  \merge(l,a,b)=\merge(l,b,a).
  \tag*{(M1)}
\]

To state the remaining four obligations, define
\[
 \downarrow_C e=\{x\mid x=e\lor
   \mathsf{TransGen}(\lambda a\,b.\ a\vis b\land
       \neg(a\rightleftarrows b))\ x\ e\}
\]
and let $\mathsf{Adm}(C,E_1,E_2,e)$ abbreviate:
\begin{enumerate}
\item $\mathsf{WF}(C)$, support and weak closure of $E_1,E_2$;
\item $e\in E_1\cup E_2$; and
\item union maximality,
$\forall x\in E_1\cup E_2.\ x\ne e\Rightarrow
\neg(e\mathrel{\lo_{C,E_1\cup E_2}}x)$.
\end{enumerate}
The feasible unit law is
\[
 \mathsf{Supported}_C(E)\land\mathsf{Canonical}(C,E,s)
 \Rightarrow \merge(\init,\init,s)=s.
 \tag*{(M2)}
\]
For the local redistribution law, assume
$\mathsf{Adm}(C,E_1,E_2,e)$, $e\in E_1$, $e\notin E_2$, and
\begin{align*}
 \mathsf{Canonical}(C,E_1\cap E_2,s_0),\quad
 &\mathsf{Canonical}(C,\downarrow_Ce\setminus\{e\},B),\\
 \mathsf{Canonical}(C,E_1\setminus\{e\},t_1),\quad
 &\mathsf{Canonical}(C,E_2,s_2).
\end{align*}
Then
\[
 \merge\bigl(s_0,\merge(B,t_1,\mathsf{do}(B,e)),s_2\bigr)
 =\merge\bigl(B,\merge(s_0,t_1,s_2),\mathsf{do}(B,e)\bigr).
 \tag*{(M3)}
\]
For shared redistribution, assume
$\mathsf{Adm}(C,E_1,E_2,e)$, $e\in E_1\cap E_2$, and canonical states
\[
 t_0:\,(E_1\cap E_2)\setminus\{e\},\quad
 B:\,\downarrow_Ce\setminus\{e\},\quad
 t_1:\,E_1\setminus\{e\},\quad t_2:\,E_2\setminus\{e\}.
\]
The required equation is
\[
 \begin{aligned}
 &\merge\bigl(\merge(B,t_0,\mathsf{do}(B,e)),
                \merge(B,t_1,\mathsf{do}(B,e)),
                \merge(B,t_2,\mathsf{do}(B,e))\bigr)\\
 &\qquad=\merge\bigl(B,\merge(t_0,t_1,t_2),\mathsf{do}(B,e)\bigr).
 \end{aligned}
 \tag*{(M4)}
\]
Equations (M2)--(M4) form \lean{FeasibleDeltaLaws}. ``Feasible'' is
load-bearing: every state named above is a canonical state of the exact event
set at that position in the proof.

Finally, \lean{CausalDeltaLaw} considers any supported, weakly closed $U$ and
$\lo_{C,U}$-maximal $e\in U$. If
\[
 \mathsf{Canonical}(C,U\setminus\{e\},A),\qquad
 \mathsf{Canonical}(C,\downarrow_Ce\setminus\{e\},B),
\]
then
\[
  \merge(B,A,\mathsf{do}(B,e))=\mathsf{do}(A,e).
  \tag*{(M5)}
\]

\begin{theorem}[VC adequacy for replay]
Obligations (U1)--(U3) and (M1)--(M5), equivalently
\lean{CanonicalJoinLaws}, imply
\lean{Join}, which in turn implies an internal replay witness for every
version of every reachable raw configuration.
\hfill\lean{CanonicalJoinLaws.join},
\lean{replayWitness\_of\_join}
\end{theorem}

\paragraph{Why these equations suffice.}
Choose a $\lo_{C,E_1\cup E_2}$-maximal event. If it is local to one side, (M5)
peels the inner causal delta, (M3) moves it through the outer merge, and the
induction hypothesis joins the smaller event sets. If it is shared, (M5)
peels it from the GCA and both branches, and (M4) moves the shared delta out
once. (M2) closes the empty case; (M1) exchanges branches. The update laws
justify swapping adjacent replay events and guarantee that the maximal-event
decomposition is well founded. This is the checked proof structure behind
\lean{CanonicalJoinLaws.join}; the displayed obligations do not claim
necessity.

\section{Issuance, sequential meaning, and safety}
\label{sec:generation}

RGA insertion illustrates why a plain signature still needs a client
protocol. An insertion carries an anchor and a fresh identifier. Raw delivery
can apply that record anywhere, but honest minting requires the issuer to have
seen the anchor and to choose an identifier above its causal past. This is a
historical fact about the minting state, not a shape predicate on an arbitrary
later delivery state.

\begin{definition}[issuance]
An \lean{Issuance D} supplies the predicate
\[
\begin{array}{ll}
\mathsf{CanIssue} &: \mathsf{Op}\to\state\to\mathsf{Prop}.
\end{array}
\]
\end{definition}

\lean{IssuedStep} checks \lean{CanIssue} only for an apply transition and
checks it at the issuer's current materialized head. Non-apply transitions
retain their raw semantics. Define the visible past of event $e$ by
$\mathsf{Past}_C(e)=\{x\in C.\mathsf{events}\mid x\vis e\}$. The persistent
honesty assertion is
\[
 \mathsf{MintHonest}_I(C)\equiv
 \forall e\in C.\mathsf{events}.\ \exists\pi.\
 \mathsf{perm}(\pi,\mathsf{Past}_C(e))\land
 \mathsf{respects}(\pi,\vis)\land
 I.\mathsf{CanIssue}(e,\mathsf{fold}(\init,\pi)).
 \tag*{(Mint)}
\]
A final configuration does not store all former issuer heads. Consequently,
\lean{MintCertifiedReach} records that (Mint) held before and after every
issued step rather than attempting to reconstruct a deleted origin state from
the final heads. \lean{MintCertifiedReachV} is the virtual-merge-base counterpart.
Datatype proofs may derive persistent history properties from this witness.

\small
\[
\Rule{Certified-Apply}{
  C\xrightarrow{\mathsf{apply}(t,r,o)}C' \quad H(r)=v
  \quad S(v)=(s,E) \quad I.\mathsf{CanIssue}((t,r,o),s)
}{
  C\xRightarrow[I]{\mathsf{apply}(t,r,o)}C'
}
\]
\[
\Rule{Certified-Other}{
  C\xrightarrow{\ell}C' \quad \ell\ne\mathsf{apply}(-,-,-)
}{
  C\xRightarrow[I]{\ell}C'
}
\]
\caption{Issuance-certified execution. Certification restricts minting at
the issuer head; it does not alter raw delivery or merge semantics. A
\lean{MintCertifiedReach} trace additionally retains the historical mint
witness needed after the issuer moves to a later head.}
\label{fig:certified-semantics}
\end{figure}

\begin{definition}[sequential specification]
A \lean{SequentialSpec D} supplies an abstract state, initial state,
deterministic step, query function, and
\[
  \mathsf{Legal}:\mathsf{List}(\mathsf{Op})\to\mathsf{Prop}.
\]
The legality predicate sees only the abstract event history. It cannot inspect
the implementation state. A total datatype sets it to true.
\end{definition}

\begin{definition}[semantic interaction]
An \lean{InteractionSpec D} classifies each ordered event pair as
\emph{independent} or as a \emph{conflict}. A conflict carries one concurrent
verdict: first-before-second, second-before-first, or unconstrained. Reversing
the event pair must flip the verdict. This policy refers to abstract events,
not arbitrary representation states.
\end{definition}

For a version event set $E$, \lean{interactionLoOn} orders every visible
conflict by visibility. It orders a concurrent conflict only when the policy
selects first-before-second and the second event has no later conflicting
absorber inside $E$. This public order is defined independently of the replay
relation used in Section~\ref{sec:convergence}. For example, an add-wins
observed-remove set orders a concurrent remove before an add, while visibility
orders an observed add before its later remove. One interaction policy
therefore explains both add-wins concurrency and ordinary observed removal.

The LWW register exposes the separation directly. Its concrete state stores
the greatest timestamped write, and both update and merge compute a maximum.
Concrete updates therefore commute, so the default proof-local replay relation
has no edges. The public interaction policy still orders unequal writes by
their timestamped keys. Sorting any internal replay witness by that key cannot
change the concrete fold, and causal timestamp monotonicity ensures that the
sorted list respects visible conflicts. The resulting list is an acyclic
timestamp order whose ordinary overwrite-register execution returns the value
stored by the MRDT.

\begin{definition}[specification linearizability]
Given interaction policy $A$, sequential specification $\mathit{Spec}$, and
representation relation
$\mathsf{Rel}\subseteq\state\times\mathit{Spec}.\mathsf{State}$,
$\mathsf{SpecLin}(D,A,\mathit{Spec},\mathsf{Rel},C)$ holds when every
$S(v)=(s,E)$ admits a list $\pi$ such that
\[
\begin{aligned}
 &\mathsf{perm}(\pi,E),\qquad
 \mathsf{respects}(\pi,\mathsf{interactionLoOn}(A,C,E)),\\
 &\mathit{Spec}.\mathsf{Legal}(\pi),\qquad
 \mathsf{Rel}(s,\mathit{Spec}.\mathsf{run}(\pi)),\\
 &\forall q.\quad
 D.\mathsf{query}(s,q)=
 \mathit{Spec}.\mathsf{query}(\mathit{Spec}.\mathsf{run}(\pi),q).
\end{aligned}
\tag*{(Spec-Lin)}
\]
\hfill\lean{IsSpecLinearizable}
\end{definition}

The first line constrains the explanation's events and ordering. The second
rules out a witness that the sequential ADT itself considers illegal. The
third rules out a representation relation that relates states but fails to
preserve observations. Internal replay linearizability establishes none of
these extra clauses automatically.

\begin{definition}[verified MRDT]
An implementer supplies:
\begin{itemize}
\item an issuance relation $I$;
\item an interaction policy $A$;
\item a convergence certificate proving internal replay linearizability for
every $I$-certified virtual-merge-base execution;
\item an independent sequential specification $\mathit{Spec}$ and representation
relation $\mathsf{Rel}$; and
\item one sequential-correctness certificate proving (Spec-Lin) from any
ordinary or canonical-virtual certified execution and its replay theorem.
\end{itemize}
\hfill\lean{VerifiedMRDT}
\end{definition}

At this point the framework responsibilities can be summarized without
anticipating undefined interfaces:

\begin{definition}[production package]
A \lean{PackagedMRDT} is a record $(n,D,V)$ containing a display name $n$, a

\lean{VerifiedMRDT.correctV} prove (Spec-Lin) for ordinary and virtual-merge-base

invariant not implied by sequential correctness. The bounded counter, for
example, proves that observable values remain non-negative by carrying a
global history invariant.

folding the maximal-common-ancestor frontier.

\lean{canonicalVirtualMergeBase} implements this resolver. The support decreases
under the version order, which justifies the recursion. The key theorem
\lean{virtualMergeBaseState\_canonical} proves that the synthetic state is canonical
for the union of the maximal ancestors' event sets. The store theorem
\lean{maximalCommonAncestorsWithAny\_events\_cover} shows that this union
covers every event shared by the two heads.

\lean{StepV} conservatively embeds every ordinary \lean{Step} and adds one
virtual merge constructor. For
$S(v_i)=(s_i,E_i)$ and resolver $\widehat S(C,v_1,v_2)$, that rule is
\[
\Rule{Virtual-Merge}{
 H(r_i)=v_i\ (i=1,2)\quad S(v_i)=(s_i,E_i)
 \\
 v_m\notin\mathsf{dom}(S)\quad v_1,v_2<v_m
}{
 \begin{aligned}
 C&\xrightarrow{\mathsf{merge}(r_1,r_2)}C',\\[-1mm]
 S'(v_m)&=(\merge(\widehat S(C,v_1,v_2),s_1,s_2),E_1\cup E_2),\\[-1mm]
 H'(r_1)&=v_m,\qquad P'(v_m)=[v_1,v_2]
 \end{aligned}
}
\]
It allocates only the result version. The maximal-common-ancestor frontier and
its recursively merged state are ghost semantic values, not virtual commits
that a runtime must store or later garbage-collect.

\begin{theorem}[virtual-merge-base replay adequacy]
The same \lean{Join} used for ordinary execution gives every version
reachable under \lean{StepV} a valid internal replay witness when the framework
uses the canonical resolver.
\hfill\lean{replayWitnessV\_of\_join}
\end{theorem}

The proof first establishes canonicality of $\widehat S$ for the union of the
maximal-common-ancestor event sets. It then applies the same Join premise used
by ordinary merge.
Therefore virtual merge bases introduce no new datatype merge law; they strengthen
only the framework's construction of the base state.

\section{Distributed commit-history garbage collection}

Replicas fetch immutable commits asynchronously, so each replica must decide
from its local holdings when history can be removed. The collector therefore
runs as a local transition alongside ordinary fetch and head synchronization.
Its specification baseline is the same asynchronous protocol with collection
steps erased, allowing each collection step to refine a stutter while network
steps retain their direct counterparts.

\subsection{Minimal local state}

For each replica, the logical collector stores
\[
  L=\{\mathsf{head}:\mathit{Version},\quad
      \mathsf{commits}:\mathcal P(\mathit{Version})\},
  \qquad \mathsf{head}\in\mathsf{commits}.
\]
The parent relation, fixed roster, and immutable optional author of each
version are protocol parameters. Apply-created versions may record their
origin replica; roots and merge versions are unauthored. Authorship establishes
progress evidence rather than authenticity against an adversary. An envelope
carries a commit set. Fetch unions that set into the receiver's holdings, and
head synchronization is a separate transition.
\hfill\lean{GC.Local}, \lean{GC.Envelope}

A distributed world is a replica-indexed family of these local records:
\[
  W:\mathit{Replica}\to\mathit{Local}.
\]
Frontier evidence is computed from these records and the fixed protocol
parameters.

Evidence is derived rather than stored. Replica $r$ has frontier evidence at
$L$ when $L$ retains a commit authored by $r$ that reaches $L.\mathsf{head}$.
Formally,
\[
 \mathsf{evidence}(L,r)=
 \{v\in L.\mathsf{commits}\mid
   \mathsf{author}(v)=r\land v\preceq L.\mathsf{head}\}.
\]
\lean{GC.EvidenceComplete} requires such evidence for every other roster
member. The negative control \lean{GC.EvidenceSPOT.missing\_author} confirms
that an unauthored merge head cannot stand in for a missing author's evidence.

\subsection{Collection certificate}

A \lean{GC.Certificate} supplies a keep set and a compressed reachability
relation $\preceq_K$. It contains the completeness proof, retains the local
head and one derived witness for every remote roster member, proves support in
the local holding, and preserves exact reachability and GCA answers between
retained versions. The canonical constructor
\lean{GC.Certificate.ofMaximalCommonAncestorClosed} takes $K$ closed under maximal common
ancestors and instantiates $\preceq_K$ with reachability in the original graph
restricted to retained endpoints.

For local record $L$ and keep set $K$, the certificate obligations are:
\begin{align*}
 &\mathsf{EvidenceComplete}(L),\qquad L.\mathsf{head}\in K,
 &&K\subseteq L.\mathsf{commits},\\
 &\forall r\in\mathsf{roster}.\ r=\mathsf{self}\ \lor\
   \exists v\in K.\ v\in\mathsf{evidence}(L,r),\\
 &a,b\in K\Rightarrow
   \bigl(a\preceq_K b\Longleftrightarrow a\preceq b\bigr),\\
 &v_1,v_2,v_T\in K\Rightarrow
   \bigl(\mathsf{GCA}_K(v_1,v_2,v_T)\Longleftrightarrow
         \mathsf{GCA}(v_1,v_2,v_T)\bigr).
\end{align*}

The compressed graph connects two retained versions when the original graph
reached between them. It need not retain intermediate paths or the old root.
Figure~\ref{fig:compressed-dag} shows the distinction between retaining a path
and retaining its reachability fact.

two retained heads may have a maximal common ancestor that collection would
otherwise erase, changing the next merge base. Keeping the entire ancestor
spine is sufficient but unnecessary; closure under maximal common ancestors
is the smaller semantic condition.

\subsection{Direct asynchronous refinement}

The collecting protocol has fetch, head synchronization, and local GC. Its
no-GC counterpart has the same network steps and no collection transition.
The simulation relates one full and one compact local store by equal heads and
commit-set inclusion:
\[
 \mathsf{StoreSim}(F,C)\;\equiv\;
 F.\mathsf{head}=C.\mathsf{head}\ \land\
 C.\mathsf{commits}\subseteq F.\mathsf{commits}\ \land\
 C.\mathsf{head}\in C.\mathsf{commits}.
\]

\begin{figure}[H]
\small
\[
\Rule{Fetch}{
  M=\mathsf{commits}(W(s))
}{
  W\longrightarrow W[d\mapsto
    \langle\mathsf{head}(W(d)),\mathsf{commits}(W(d))\cup M\rangle]
}
\]
\[
\Rule{Head-Sync}{v\in\mathsf{commits}(W(r))}{
  W\longrightarrow W[r\mapsto
    \langle v,\mathsf{commits}(W(r))\rangle]}
\]
\[
\Rule{Collect}{\mathsf{Certificate}(W(r),K)}{
  W\longrightarrow W[r\mapsto\langle\mathsf{head}(W(r)),K\rangle]}
\]
\caption{Asynchronous commit-history GC. Fetch is the ordinary remote-fetch
path and unions immutable commits. Head synchronization is explicit. Collect
is local and requires complete frontier evidence plus reachability/GCA
preservation for the keep set.}
\label{fig:distributed-gc-rules}
\end{figure}

Let $\mathsf{NoGCStep}$ contain only \textsc{Fetch} and
\textsc{Head-Sync}. The one-step simulation is
\[
 \mathsf{WorldSim}(F,C)\land C\longrightarrow_{\mathrm{GC}}C'
 \Longrightarrow
 \exists F'.\;F\longrightarrow_{\mathrm{NoGC}}^{0\text{ or }1}F'
 \land\mathsf{WorldSim}(F',C').
\]
The collection case chooses $F'=F$; network cases take their matching
no-GC step. Induction over the finite collecting trace gives the execution
theorem.

\begin{theorem}[distributed collection refines no-GC]
Every finite collecting execution is matched by a finite no-GC execution.
Fetch and head synchronization match their counterparts; collection
stutters. The final worlds have equal replica heads, so head-state reads are
unchanged.
\hfill\lean{GC.execution\_refines\_noGC}, \lean{GC.read\_preserved}
\end{theorem}

This store theorem deliberately says only that an already-taken collecting
trace has a no-GC match. To connect stores to the datatype semantics, define a
proof-level runtime $R=\langle C,W\rangle$. Well-formedness says every locally
held version is allocated in $C$, and every semantic head agrees with and is
present in its local holding. A visible step additionally proves that its
required versions are available: ordinary merge needs both heads and its GCA;
a virtual merge needs the resolver's declared read set. Visible steps contain
the actual \lean{Step} or \lean{StepV} derivation and install the new head in
the local holding. Fetch and collection leave $C$ unchanged.

\begin{theorem}[runtime history-GC refinement]
If
$R_0\xRightarrow{\lambda_1\ldots\lambda_n}_{\mathsf{runtime}}R_n$, then
erasing silent fetch and collection labels yields
\[
 R_0.C\xRightarrow{\mathsf{filterMap}(\lambda_1\ldots\lambda_n)}_{\mathsf{Step}}
 R_n.C.
\]
The analogous result holds for \lean{StepV} and an explicit virtual-resolver
read set.
\hfill\lean{GC.runtime\_refines\_core},
\lean{GC.runtime\_refines\_coreV}
\end{theorem}

The core configuration is ghost simulation state, not a second physical copy
required of an implementation. The theorem also makes the collector's trust
boundary concrete: malformed network data and Byzantine authorship are out of
scope; commits and authorship are immutable protocol facts.

The refinement is a trace-safety result, not a theorem that collection
preserves every transition that could have been taken later. A visible
\textsc{Fork} requires the source head to be present in the source holding. Its
store transition first receives the source's retained commits at the fresh
destination and then installs the newly allocated child head. Fork therefore
has the same shared-history shape after collection as it does in the raw
semantics, while placing no special retention obligation on version~0.

\section{Optional datatype-state garbage collection}

Commit GC removes versions from a replica's history. It cannot decide whether
an RGA tombstone, a Peritext mark boundary, or a TreeMove event can be removed
from the state stored at a retained version. That decision is datatype
specific.

\begin{definition}[state-GC protocol]
A \lean{StateGCProtocol D V} supplies
\[
\begin{array}{rcl}
\mathsf{Physical}&:&\mathsf{Type},\\
\mathsf{semantic}&:&\mathsf{Physical}\to\mathsf{Configuration}(D),\\
\mathsf{Valid}&:&\mathsf{Physical}\to\mathsf{Prop},\\
\mathsf{PhysicalStep}&:&
 \mathsf{Physical}\to\mathsf{Option}(\mathsf{Label})\to
 \mathsf{Physical}\to\mathsf{Prop}.
\end{array}
\]
It proves:
\begin{enumerate}
\item validity is invariant;
\item a silent physical transition leaves the semantic projection unchanged;
\item a visible transition refines a \lean{StepV} transition.
\end{enumerate}
\end{definition}

\begin{theorem}[state collection refines semantic execution]
Erasing silent labels from any valid finite physical trace yields a finite
\lean{StepV} trace between the projected configurations.
\hfill\lean{StateGCProtocol.refines}
\end{theorem}

The combined physical state contains the datatype protocol state and the
generic distributed commit stores. A combined transition is either a datatype
physical step or a silent fetch/commit-GC step.
Writing $P=\langle p,W\rangle$, the two cases are
\[
\Rule{Datatype}{p\xrightarrow{\lambda}_{S}p'\quad
  W\xrightarrow{\lambda}_{\mathsf{store}}W'}{
  \langle p,W\rangle\xrightarrow{\lambda}\langle p',W'\rangle}
\qquad
\Rule{History}{W\xrightarrow{\tau}_{\mathsf{fetch/GC}}W'}{
  \langle p,W\rangle\xrightarrow{\tau}\langle p,W'\rangle}.
\]
For $\lambda=\tau$, a datatype step leaves the commit store unchanged. For a
visible label, its store evolution installs the version created by the
semantic step. Both history transitions are silent at the datatype semantics.

\begin{theorem}[the two collectors compose]
For every valid finite combined trace, erasing state-GC, fetch, and commit-GC
labels yields an execution of the uncollected virtual-merge-base semantics.
\hfill\lean{GC.CombinedSteps.refinesV}
\end{theorem}

The ordinary corollary \lean{GC.CombinedSteps.refinesRaw} applies when every
visible datatype transition proves a raw \lean{Step}. Sided Peritext and
TreeMove provide concrete state-GC protocols. Other datatypes may omit the
interface entirely.

The text instances begin with the replicated growable array (RGA), a sequence
whose insertions name stable anchors and whose deletions retain identity-bearing
tombstones~\cite{roh2011rga}. EmbedRGA assigns immutable coordinates at
creation; SidedEmbedRGA adds a left/right band used by its ordering policy.
Peritext builds rich text from an underlying character sequence and formatting
spans whose endpoints refer to stable character boundaries~\cite{litt2022peritext}.
These packages make freshness and anchor visibility explicit in their issuance
predicates. The observed-remove set instead illustrates a directional
interaction policy. Its public sequential state is an ordinary finite set:
add inserts the named element and remove erases it, while observed-tag payloads
remain implementation metadata. Honest issuance is load-bearing in the proof
that the tagged representation refines this machine. The bounded counter uses
issuance to enforce available rights.

The LWW package uses unconditional issuance. Its state is either unset or a
timestamp--replica--value tuple; update and ternary merge take the tuple
maximum. Its independent sequential specification is a total overwrite
register over optional values. The checked witness construction sorts every
version's writes by the tuple order, proves that this list respects the public
interaction relation, and uses commutativity to preserve the stored maximum.

TreeMove represents a replicated tree whose nodes have stable identities and
whose conflict resolution prevents concurrent moves from creating cycles; it
follows the setting of highly available replicated-tree moves
\cite{kleppmann2022treemove}. Its sequential state is the ordinary tree, not a
copy of the replicated event set. AegisSheet models a collaborative spreadsheet
with stable row, column, cell, and range identities and conflict policies for
move, overwrite, range, and selective-undo operations
\cite{pfeil2026aegissheet}. Its sequential history is \emph{causal-origin
legal}: each operation must be valid in the causal context recorded when its
issuer created it. Requiring validity after the entire preceding sequential
prefix would reject two operations that were independently valid at
concurrent origins.

The theorem \lean{no\_view\_only\_step} exhibits two reachable AegisSheet
states with equal visible sheets whose responses to the same continuation
differ. The independent sequential state therefore retains the causal
identities needed to interpret later conflict handling, rather than reducing
to visible cells alone.

\paragraph{External implementation correspondence.}
We validated the public AegisSheet Scala implementation against its published
intent matrices and found four focused undo/range regressions at the audited
revision. These are implementation-correspondence observations, not Lean
counterexamples to the merge kernel. The reproducible audit and its revision
boundary are in \code{docs/aegissheet-scala-audit.md}.

The separate negative ledger checks intentionally refuted or incomplete
claims, including MVR/single-register and queue/FIFO counterexamples.
FugueMax's coordinate lemmas justify the ordering policy used by the verified
SidedEmbedRGA package but do not create a standalone production datatype. The
release gate rejects \lean{sorry} and \lean{sorryAx}, requires every
production entry to inhabit \lean{PackagedMRDT}, and checks the distributed
and composed GC capstones.

\section{Related work}

Conflict-free replicated data types obtain deterministic convergence without
synchronous coordination by constraining state joins or delivered operations
\cite{shapiro2011crdt}. Replication-aware linearizability strengthens a bare
convergence statement by asking for a sequential explanation of each replica
state~\cite{wang2019ralin}. Our client theorem uses the same broad explanatory
goal but separates the proof's replay order from the interaction order,
legality, abstract state, and observations that define the public datatype.

MRDTs adapt replicated datatypes to branch-and-merge stores with ancestor-aware
three-way merge~\cite{kaki2019mrdt}. Peepul verifies efficient MRDTs in F* using
replication-aware simulation relations~\cite{soundarapandian2022certified}.
The bottom-up replay method subsequently proposed for automated MRDT
verification~\cite{soundarapandian2025automatic} motivates our counterexample.
Our correction is set-relative because a version may exclude events that exist
elsewhere in the store, and it carries the invariant over every stored version
because an old version may later serve as a merge base.

The instance proofs connect the generic result to established collaborative
datatypes: RGA for ordered text~\cite{roh2011rga}, Peritext for rich-text
formatting~\cite{litt2022peritext}, highly available tree moves
\cite{kleppmann2022treemove}, and AegisSheet for spreadsheets
\cite{pfeil2026aegissheet}. The present artifact does not re-verify those
papers wholesale. It verifies the signatures and sequential specifications in
this repository and states any external scenario validation separately.

\section{Reproduction and residual boundary}

From the repository root, run the production proof and runtime gate with
\code{./scripts/check-mrdt-refactor.sh}. Build both papers and the declaration
ledger with \code{./scripts/check-working-papers.sh}.

The proved framework covers semantic MRDT executions, canonical virtual merge bases,
distributed commit-history collection, optional state-GC protocols, and their
composition. Same-replica crash recovery is not yet part of the verified or
tested continuation protocol. Forking a fresh destination from an existing
head is verified, but changing the fixed roster used by the collection
protocol is not. The JavaScript implementation uses indexes and cached metadata for efficiency; the
paper-facing logical GC state remains the minimal
$\{\mathsf{head},\mathsf{commits}\}$ record.

At the artifact boundary, Lean's \lean{Configuration} stores the version
store, replica heads, parent graph, and visibility relation used in
Section~2. The functions \lean{Configuration.headState} and
\lean{Configuration.headEvents} derive a replica's current observations from
its head. Replay-only packages and
alternative replay-policy hooks support migration and negative analysis in the
artifact; production registry entries are the complete packages of Section~5.

\section{Conclusion}

Correctness for a branch-and-merge datatype cannot be proved by ordering the
whole store and replaying arbitrary subsets of that order. The checked
counterexample identifies the missing locality, and the repaired induction
orders exactly the operations of the version it explains. Three-way merge then
has one precise task: preserve the resulting canonical state across the
ancestor and two branches.

That replay theorem is deliberately not the final client claim. A verified
package must also explain where operations could be created, which concurrent
interactions matter, which sequential histories are legal, how representation
states correspond to abstract states, and why queries agree. The same
separation clarifies reclamation: commit-history collection preserves the DAG
answers required by asynchronous execution, while datatype-state collection
preserves the semantic projection of retained versions. Their composition
connects compact physical traces to the same client-facing theorem.

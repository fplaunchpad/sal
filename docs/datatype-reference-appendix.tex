\section{Datatype Definitions and Sequential Specifications}
\label{app:datatypes}

This appendix defines the datatype implementations in Table~\ref{tab:implementation}.
For each implementation we give the concrete state space $\Sigma$, initial state
$\sigma_0$, update $\F{do}$, three-way merge, and query, followed by an
independent sequential machine. The concrete definitions are adaptations of
the cited designs; the source and adaptation boundaries are
stated where they affect the interface.

As in \S\ref{sec:opsem}, an event is $e=(t,r,o)\in\mathcal E$.
These implementations instantiate $\mathcal T=\mathbb N$ and
$\mathcal R=\mathbb N$; $o\in O_\tau$ is an update operation. Unless otherwise stated,
$\F{merge}(l,a,b)$ takes a common ancestor $l$ and two branch states $a,b$.
As in \S\ref{sec:ralin-new}, $e(\sigma)=\F{do}(\sigma,t,r,o)$.
Sets are finite when marked $\subseteq_{\rm fin}$, $\mathcal P_{\rm fin}$
or $\operatorname{Finset}$; Boolean predicates are interpreted pointwise.
$X\mathbin{+\!+}Y$ denotes list concatenation, $x::X$ cons,
and $[x\in X\mid P(x)]$ order-preserving list filtering.
Natural subtraction is truncated at zero; sums of signed quantities use
$\mathbb Z$. Write $\mathbb B=\{\mathsf{false},\mathsf{true}\}$.
$[P]\in\mathbb B$ is true
exactly when $P$ holds. Lexicographic order uses a proper prefix smaller
than its extension.

Each sequential specification is a labelled transition system
$\Spec=\langle L,\Phi,\phi_0,\longrightarrow\rangle$, as in
Definition~\ref{def:spec}. Query transitions are state preserving and
labelled $q\Rightarrow b$. For a unit-query interface we name its sole
query $\F{rd}$; an element-indexed read is $\F{rd}_x$.
Every finite admitted run starts at $\phi_0$, including runs with queries
between updates. A retained prefix $H$ in a guarded sequential machine
checks admission; it is not the replica-head map $H$ of a store
configuration. These sequential rules contain no three-way merge.

\paragraph{Event-label projections.}
The identified specifications below retain event metadata when their
labels need stable identities. This extends the payload-only label
convention of \S\ref{sec:ralin-new}; it does not identify all these
specifications with that convention. For an abstract update alphabet
$\mathcal U$, let $f:\mathcal E\to\mathcal U$ translate an event to its
update label, and define
\[
\F{ops}_{f}(e_1\cdots e_n)=f(e_1)\cdots f(e_n).
\]
The paper's $\F{ops}$ is the case $f(t,r,o)=o$. In a transition labelled
by the complete event $(t,r,o)$, take $f$ to be the identity; its timestamp
and replica remain in the label even when the transition ignores them.
The FugueMax section defines an identified-action projection. The Notion
section translates one event into an atomic command group; the group
remains one admitted update, with queries allowed only between groups.
A statement of sequential conformance for these machines uses
$\F{ops}_f$ and its stated projection.

The issuance guard is $G(e,s)$, as in Definition~\ref{def:issuance}.
Each displayed guard is evaluated on the original issuing state
$\pi_e(\sigma_0)$ of Definition~\ref{def:issuance}; local names such as
$O$, $S$ or $s$ denote that state in its datatype representation. The Notion section identifies
its retained reference-protocol state separately from the structural carrier.
The relation $\rcrel$ below is the selected application-operation policy.
The policy constrains concurrent conflicts as specified by
Definition~\ref{def:lo-local}; an empty policy adds no application precedence
edges. The mechanized sequential-conformance results also preserve visible
pairs whose specification updates do not commute.
Guards are checked when an event is created, at its original issuing state.
The results concern executions of the operational semantics with these guards,
globally fresh timestamps and honest origin metadata. Per-replica cumulative
implementations also require serialized issuance under each replica identity.
These execution assumptions apply to both ordinary and recursively constructed
merge bases; total update equations alone make no claim about unreachable states.

\subsection{Counter}
\label{app:dt-counter}

\noindent Source references: \cite{neem}.

Increment and decrement change one integer. Merge adds the two branches' changes since their common ancestor, so each change contributes once.

\paragraph{Concrete MRDT}
\textbf{State:} integer $z\in\mathbb{Z}$. \textbf{Initial:} $0$.

Payload: inc or dec. Delta: $\delta(\mathrm{inc})=1$; $\delta(\mathrm{dec})=-1$.

\textbf{Update:}

\[
e(z)=z+\delta(o)
\]

Timestamp and replica are ignored by the update.


\textbf{Three-way merge:}

\[
\F{merge}(l,a,b)=a+b-l=l+(a-l)+(b-l).
\]


\textbf{Query:} input $()$; return $z$.

\paragraph{Independent sequential specification.}
\textbf{State:} an integer $z\in\mathbb Z$, initially $0$. For $e=(t,r,o)$,
\[
z\xrightarrow{e}z+\delta(o).
\]

$\delta(\mathrm{inc})=1$, $\delta(\mathrm{dec})=-1$.

\textbf{Query:}
\[
z\xrightarrow{\F{rd}\Rightarrow y}z\qquad\text{when }y=z.
\]

Timestamp and replica are ignored.


\paragraph{Issuance.}
\[
G(e,O)\iff\top.
\]

\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$.


\paragraph{Source and adaptation.}
The integer-delta three-way counter uses ancestor subtraction; it is not a saturating natural-number counter.


\subsection{Grow-only set}
\label{app:dt-grow-only-set}

\noindent Source references: \cite{shapiro2011comprehensive}.

% Sal/MRDTs/Instances/AddStore.lean: D, generation, verified

% Sal/MRDTs/Paper1/SimpleEventPorts.lean: setMachine

% Sal/MRDTs/Paper1/SimpleConcretePorts.lean: gsetConditions, finiteAddConditions, booleanSetConditions, booleanMapConditions

% Sal/MRDTs/Paper1/SimpleEventPorts.lean: set_language_preserved, finite_language_preserved, boolean_language_preserved

Insertion permanently adds an element. Merge is union, so an element learned on either branch remains present.

\paragraph{Concrete MRDT}
\textbf{State:} a mathematical set $S\subseteq\mathbb{N}$. \textbf{Initial:} $\varnothing$.

The operation payload $o$ is an element of $\mathbb{N}$.

\textbf{Update:}

\[
e(S)=S\cup\{o\}
\]


Timestamp and replica do not affect the update.

\textbf{Three-way merge:}

\[
\F{merge}(l,a,b)=a\cup b
\]


The base $l$ is ignored.

\textbf{Query:} input $()$; return the whole set $S$.

\textbf{Representation variants.} The mathematical carrier uses $\mathrm{Set}(A)$; the enumerable carrier uses $\mathrm{Finset}(A)$ so clients can enumerate elements; the Boolean carrier uses $A\to\mathbb B$. All represent the same insertion-only membership abstraction. The Boolean implementation computes $l\lor a\lor b$ pointwise; on reachable merge inputs $l\subseteq a,b$, so this equals $a\cup b$. Peritext uses the enumerable representation for rendering.


\paragraph{Independent sequential specification.}
\textbf{State:} a mathematical set $S\subseteq\mathbb N$, initially $\varnothing$. For $e=(t,r,o)$,
\[
S\xrightarrow{e}S\cup\{o\}.
\]

Timestamp and replica are ignored.

\textbf{Query:}
\[
S\xrightarrow{\F{rd}\Rightarrow y}S\qquad\text{when }y=S.
\]

Finite-set and Boolean variants use a finite set, returning the collection or its characteristic function. These are representations of the same grow-only-set abstraction.


\paragraph{Issuance.}
\[
G(e,O)\iff\top.
\]

\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$.


\paragraph{Source and adaptation.}
The three carriers implement one grow-only-set abstraction. They are three implementation configurations displayed in one row of Table~\ref{tab:implementation}.

\subsection{Last-writer-wins register}
\label{app:dt-lww-register}

\noindent Source references: \cite{shapiro2011comprehensive}.

% Sal/MRDTs/Instances/LWWRegister.lean: State, packedWrite, update, D, read, issuance, spec

% Sal/MRDTs/Paper1/GuardedLWWPort.lean: policy, language, history

Each write carries its event timestamp. The greatest write key wins after merge; with globally unique timestamps this is the greatest timestamp.

\paragraph{Concrete MRDT}
\textbf{State:} unset $\bot$ or a write key $(t,r,v)$, ordered lexicographically with $\bot$ least. \textbf{Initial:} $\bot$.

Payload: write(v), $v\in\mathbb{N}$.

\textbf{Update:}

\[
e(S)=\max\bigl(S,(t,r,v)\bigr)
\]


\textbf{Three-way merge:}

\[
\F{merge}(l,a,b)=\max(a,b)
\]


The base $l$ is ignored.

\textbf{Query:}
\[
q(\bot,())=\operatorname{none},\qquad q((t,r,v),())=\operatorname{some}(v).
\]

\paragraph{Independent sequential specification.}
\textbf{State:} $s\in\operatorname{Option}(\mathbb N)$, initially $\operatorname{none}$.
\[
s\xrightarrow{(t,r,\operatorname{write}(v))}\operatorname{some}(v).
\]

\textbf{Query:}
\[
s\xrightarrow{\F{rd}\Rightarrow y}s\qquad\text{when }y=s.
\]

The abstract update ignores timestamp and replica. Every sequence of writes is admitted; no chronological legality condition restricts this machine.


\paragraph{Issuance.}
\[
G(e,O)\iff\top.
\]

\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$. The selected witness sorts writes by increasing $(t,r,v)$. Since timestamps increase along visibility, this witness respects visibility and its final write explains the stored maximum.


\paragraph{Source and adaptation.}
This maximum-key implementation refines an ordinary overwrite register using the chronological witness described above. Replica and value break ties only on states with repeated timestamps.


\subsection{Multi-value register}
\label{app:dt-mvr}

\noindent Source references: \cite{shapiro2011comprehensive}.

% Sal/MRDTs/Instances/MVRLive.lean: State, update, merge, D, canIssue, issuance, spec

% Sal/MRDTs/Instances/MVRContract.lean: clientStep, clientLegal, queryValues

% Sal/MRDTs/Paper1/CertifiedMVRHistory.lean: language

% Sal/MRDTs/Paper1/MVRClient.lean: prepare; issuance_prepare_iff; prepared_public_read; historical_issued_prepared_public_read

A write replaces the writes visible to its issuer. Concurrent writes survive together, because their identities are absent from each other's overwrite lists.

\paragraph{Concrete MRDT}
\textbf{State:} finite pairs (timestamp,value). \textbf{Initial:} $\varnothing$.

Payload $\operatorname{write}(v,W)$, $v\in\mathbb{N}$, where $W$ lists the timestamp IDs of superseded writes. Write $\langle W\rangle$ for the set of entries in $W$; replica IDs do not affect the update.

\textbf{Update:}

\[
e(S)=\{(t,v)\}\cup\{(n,w)\in S\mid n\notin W\}
\]


\textbf{Three-way merge:}

\[
\F{merge}(l,a,b)=(l\cap a\cap b)\cup(a\setminus l)\cup(b\setminus l)
\]


\textbf{Query:} input $()$; return $\{v\mid\exists n,\ (n,v)\in S\}$.

\paragraph{Independent sequential specification.}
\textbf{State:} $S\subseteq_{\rm fin}\mathbb N\times\mathbb N$, initially $\varnothing$. Track the update prefix $h$, initially $[]$, for history admission; it is not an extra concrete field. Let $T(h)=\{t_f\mid f\in h\}$ and $\langle W\rangle$ be the set of list entries in $W$. For $e=(t,r,\mathrm{write}(v,W))$,
\[
\begin{aligned}(h,S)&\xrightarrow{e}(h\mathbin{+\!+}[e],S')&&\text{when }t\notin T(h)\land\langle W\rangle\subseteq T(h),\\S'&=\{(t,v)\}\cup\{(u,w)\in S\mid u\notin\langle W\rangle\}.\end{aligned}
\]

Targets need not still be live; this admission guard does not require overwriting every live timestamp. The origin issuance guard does.

\textbf{Query:}
\[
(h,S)\xrightarrow{\F{rd}\Rightarrow y}(h,S)\qquad\text{when }y=\{v\mid\exists u,(u,v)\in S\}.
\]


\textbf{Value-only client request.} The client supplies $\operatorname{write}(v)$. At its local live state $S$, preparation supplies
\[
W=\operatorname{sort}(\{u\mid\exists w,(u,w)\in S\}),\qquad\operatorname{prepare}(S,v,t,r)=(t,r,\operatorname{write}(v,W)).
\]

For a fresh insertion identity, the prepared local update reads exactly $\{v\}$. This is checked for both compact and historical implementations, for states reached by the historical implementation. Concurrent writes still use the observed-overwrite history above; this local theorem does not turn the replicated register into a singleton register.


\paragraph{Issuance.}
Let $O\subseteq_{\rm fin}\mathbb N\times\mathbb N$ be the live origin state and $\langle W\rangle=\{u\mid u\text{ occurs in list }W\}$. For $e=(t,r,\mathrm{write}(v,W))$,
\[
G(e,O)\iff t\notin\{u\mid\exists w,(u,w)\in O\}\land\langle W\rangle=\{u\mid\exists w,(u,w)\in O\}.
\]

List order and duplicate overwrite IDs do not affect this guard. $W$ names only writes visible at the origin, so a concurrent write survives.


\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$. The supplied overwrite IDs retain the dependencies on observed writes.


\paragraph{Source and adaptation.}
The configuration uses compact live tagged writes. Overwrite IDs are prepared from the original live state; the abstract language preserves those supplied identities.


\subsection{Optional register}
\label{app:dt-optional-register}

\noindent Source references: \cite{neem}.

% Sal/MRDTs/Instances/OptionalRegister.lean: D, initial, update, mergePayload, mergeCell, merge, query, generation

% Sal/MRDTs/Paper1/OptionalRegisterVC.lean: fiveVC, representationJoin

% Sal/MRDTs/Paper1/OptionalRegisterHistory.lean: model, spec, sorted_refines, history_from_representation

% Sal/MRDTs/Paper1/OptionalRegisterCertificate.lean: certified, certifiedV, executions, executionsV

% Sal/MRDTs/Paper1/OptionalRegisterSourceValidity.lean: sourceWellFormed, sourceWellFormedV, sourceWellFormedOrdinary

% Sal/MRDTs/Paper1/OptionalRegisterPolicy.lean: policy

Set installs a value and Unset clears the values it has observed. A concurrent Set survives Unset; among surviving sets, the greatest timestamp determines the returned value.

\paragraph{Concrete MRDT}
The state is a finite partial map of replica rows:
\[
s:\mathbb N\rightharpoonup((\mathbb Z\times\mathbb B)\times(\mathbb N\times\mathbb N)),\qquad s_0=\varnothing.
\]

Write $s(r)=((c_r,b_r),(t_r,v_r))$; absent rows read as $z=((0,\mathsf{false}),(0,0))$. The domain remains part of the state. The implementation of~\citet{neem} additionally refines stored rows by $b_r=\mathsf{false}\iff(t_r,v_r)=(0,0)$; the total state space is broader, and this property holds in certified executions.
\[
\begin{aligned}
\F{do}(s,t,r,\mathrm{set}(v))&=s[r\mapsto((c_r+1,\mathsf{true}),(t,v))],\\
\F{do}(s,t,r,\mathrm{unset})(j)&=((c_j,\mathsf{false}),(0,0))&&\text{for }j\in\operatorname{dom}(s).
\end{aligned}
\]

Unset preserves the domain. Merge has domain $\operatorname{dom}(l)\cup\operatorname{dom}(a)\cup\operatorname{dom}(b)$. At each key, let the input rows be $((c_l,b_l),p_l)$, $((c_a,b_a),p_a)$, $((c_b,b_b),p_b)$. Then
\[
c_m=c_a+c_b-c_l,\qquad
b_m=\begin{cases}
\mathsf{true}&b_a\land b_b,\\
\mathsf{false}&\neg b_a\land\neg b_b,\\
[c_a>c_l]&b_a\land\neg b_b,\\
[c_b>c_l]&\neg b_a\land b_b.
\end{cases}
\]

For $p_a=(t_a,v_a)$ and $p_b=(t_b,v_b)$, define
\[
W(p_a,p_b)=\begin{cases}
(t_a,\lfloor(v_a+v_b)/2\rfloor)&t_a=t_b,\\
p_a&t_a>t_b,\\
p_b&t_a<t_b.
\end{cases}
\]

\[
p_m=\begin{cases}
(0,0)&\neg b_m,\\
p_b&b_m\land\neg b_a,\\
p_a&b_m\land b_a\land\neg b_b,\\
W(p_a,p_b)&b_m\land b_a\land b_b.
\end{cases}
\]

The merged row is $((c_m,b_m),p_m)$. The source’s equal-timestamp averaging branch is retained.

Let $A(s)=\{(t_r,r,v_r)\mid r\in\operatorname{dom}(s),\ b_r=\mathsf{true}\}$. Using lexicographic order,
\[
\operatorname{read}(s)=\begin{cases}
\operatorname{none}&A(s)=\varnothing,\\
\operatorname{some}(v)&(t,r,v)=\max_{\mathrm{lex}} A(s).
\end{cases}
\]

The replica/value tie-break makes the maximum unique. Issued timestamps are unique, so reachable equal-timestamp active payloads identify the same write.


\paragraph{Independent sequential specification.}
The independent state is $x\in\operatorname{Option}(\mathbb N)$, initially $\operatorname{none}$.
\[
\begin{aligned}
x&\xrightarrow{(t,r,\mathrm{set}(v))}\operatorname{some}(v)\\
x&\xrightarrow{(t,r,\mathrm{unset})}\operatorname{none}\\
x&\xrightarrow{\F{rd}\Rightarrow y}x&&\text{when }y=x.
\end{aligned}
\]

The specification has no replica rows, counters, or timestamps in its state. The witness places unsets and the sets they observed first, followed by surviving sets in timestamp order.


\paragraph{Issuance.}
\[
G(e,s)\iff \F{time}(e)>0.
\]

Positive timestamps ensure an active row never has payload $(0,0)$. Globally fresh timestamps, causal growth and serialized issuance at each replica ensure that equal-timestamp active payloads identify the same write.


\paragraph{Conflict-resolution relation.}
\[
\rcrel(o_1,o_2)\iff\exists v.\ o_1=\mathrm{unset}\land o_2=\mathrm{set}(v).
\]

A concurrent Set follows Unset. Sets at different replicas commute in the implementation because they update different rows. The independent scalar specification still distinguishes writes of different values, so the witness also respects specification-conflicting visibility.


\paragraph{Source and adaptation.}
The arithmetic and equal-timestamp averaging branch are retained from the source implementation. The source supplies no query; the query used here selects the greatest active timestamped payload.


\subsection{Enable-wins flag}
\label{app:dt-enable-wins-flag}

\noindent Source references: \cite{neem}.

% Sal/MRDTs/Instances/EnableWinsFlag.lean: D, enable, disable, generation

% Sal/MRDTs/Instances/EnableWinsFlag.lean: NeemFlag.initial, NeemFlag.update, NeemFlag.mergeFlag, NeemFlag.mergeCell, NeemFlag.merge, NeemFlag.active

% Sal/MRDTs/Paper1/EnableWinsFlagVC.lean: fiveVC, replayConditions

% Sal/MRDTs/Paper1/NeemFlagEvent.lean: machine, spec, simulation

% Sal/MRDTs/Paper1/EnableWinsFlagCertificate.lean: certified, certifiedV

% Sal/MRDTs/Paper1/EnableWinsFlagReplay.lean: policy

Enable sets the flag and Disable clears observed enables. A concurrent Enable wins: per-replica counters distinguish a fresh enable from an unchanged ancestor bit.

\paragraph{Concrete MRDT}
State is $s:\mathbb N\to\mathbb Z\times\mathbb B$, with $s(i)=(c_i,b_i)$ and $s_0(i)=(0,\mathsf{false})$ for every replica index. The source's constant map has universal domain.

For an event $(t,i,o)$,
\[
\begin{aligned}
\F{do}(s,t,i,\mathrm{enable})(j)&=\begin{cases}(c_i+1,\mathsf{true})&j=i,\\s(j)&j\ne i,\end{cases}\\
\F{do}(s,t,i,\mathrm{disable})(j)&=(c_j,\mathsf{false}).
\end{aligned}
\]


Merge is pointwise. For ancestor row $(c_l,b_l)$ and branch rows $(c_a,b_a),(c_b,b_b)$,
\[
c_m=c_a+c_b-c_l,
\]

\[
b_m=\begin{cases}
\mathsf{true}&b_a\land b_b,\\
\mathsf{false}&\neg b_a\land\neg b_b,\\
[c_a>c_l]&b_a\land\neg b_b,\\
[c_b>c_l]&\neg b_a\land b_b.
\end{cases}
\]

\[
\operatorname{read}(s)=[\exists i.\ b_i=\mathsf{true}].
\]

The counter test $c_a>c_l$ detects a fresh winning operation on branch $a$
since the ancestor (Enable for enable-wins, Disable for disable-wins). The
source application specifies updates and merge but no query; the query
observes whether a winning bit survives, complemented for disable-wins.


\paragraph{Independent sequential specification.}
State is a Boolean $v$, initially $\mathsf{false}$.
\[
\begin{aligned}
v&\xrightarrow{(t,i,\mathrm{enable})}\mathsf{true}\\
v&\xrightarrow{(t,i,\mathrm{disable})}\mathsf{false}\\
v&\xrightarrow{\F{rd}\Rightarrow y}v&&\text{when }y=v.
\end{aligned}
\]

Replica and timestamp are carried in update labels; they do not affect the Boolean transition. The implementation query returns the corresponding enabled/disabled value. A respecting history places the losing operation before the concurrent winning operation.


\paragraph{Issuance.}
\[
G(e,O)\iff\top.
\]

No datatype guard is added. Execution certification supplies unique events and serialized issuance at each replica. Full causal metadata retains the per-replica counter prefixes needed by the source merge.


\paragraph{Conflict-resolution relation.}
\[
\rcrel(o_1,o_2)\iff o_1=\mathrm{disable}\land o_2=\mathrm{enable}.
\]

Equal-operation updates commute. Enable and disable do not commute, in either the implementation or the independent Boolean specification. Here the winning operation is the one placed second by $\rcrel$. Each counter counts that operation at its replica; a true bit records an outstanding winning operation, or an initial true bit not yet reset. The same ternary merge applies to recursive merge bases.


\paragraph{Source and adaptation.}
The counter-and-bit update and ternary merge follow the source implementation. The source supplies no query; we add the surviving-winning-bit observation.

[c_b>c_l]&\neg b_a\land b_b.

The counter test $c_a>c_l$ detects a fresh winning operation on branch $a$

\begin{aligned}
v&\xrightarrow{(t,i,\mathrm{enable})}\mathsf{true}\\
v&\xrightarrow{(t,i,\mathrm{disable})}\mathsf{false}\\
v&\xrightarrow{\F{rd}\Rightarrow y}v&&\text{when }y=v.
\end{aligned}
\]

Replica and timestamp are carried in update labels; they do not affect the Boolean transition. The implementation query returns the corresponding enabled/disabled value. A respecting history places the losing operation before the concurrent winning operation.


\paragraph{Issuance.}
\[
G(e,O)\iff\top.
\]

No datatype guard is added. Execution certification supplies unique events and serialized issuance at each replica. Full causal metadata retains the per-replica counter prefixes needed by the source merge.


\paragraph{Conflict-resolution relation.}
\[
\rcrel(o_1,o_2)\iff o_1=\mathrm{enable}\land o_2=\mathrm{disable}.
\]

Equal-operation updates commute. Enable and disable do not commute, in either the implementation or the independent Boolean specification. Here the winning operation is the one placed second by $\rcrel$. Each counter counts that operation at its replica; a true bit records an outstanding winning operation, or an initial true bit not yet reset. The same ternary merge applies to recursive merge bases.


\paragraph{Source and adaptation.}
The counter-and-bit update and ternary merge follow the source implementation. The query complements the outstanding-disable observation to expose whether the flag is enabled.

\paragraph{Issuance.}

G(e,s)\iff\top.

\]

\paragraph{Source and adaptation.}
The source supplies updates and merge but no query. We expose an accumulating multimap lookup, whose independent state erases timestamps.


\subsection{Priority queue}
\label{app:dt-add-wins-priority-queue}

\noindent Source references: \cite{PriorityQueue2023}.

% Sal/MRDTs/Instances/PublishedAddWinsPriorityQueue.lean: State, Payload, Request, step, merge, recordTags, liveTags, observed, acquired, prepare, requestOf
% Sal/MRDTs/Instances/PriorityQueueSameRecord.lean: candidates, priority, elements, getMax, read, D, generation, prepareRmvMax, rmvMax, priority_selected_record, prepared_remove_effect, effects_commute

% Sal/MRDTs/Paper1/PriorityQueueSameRecordSpec.lean: SeqState, seqStep, seqRead, model, spec, seqRmvMax, project, rmvMax_refines, cross_key_commutes, total_update_controls
% Sal/MRDTs/Paper1/PriorityQueueSameRecordVC.lean: policy, fiveVC, representationJoin, canonicalVersions

% Sal/MRDTs/Paper1/PriorityQueueSameRecordAudit.lean: audit_same_record_priority_queue

Each addition creates an insertion record. An increment attaches to the
insertions visible at its issuer, and removal disables those observed
insertions; an unseen concurrent addition survives. The returned priority
uses the latest surviving insertion's innate value and that same record's
increments. Removing and reinserting an element therefore resets its priority.

\paragraph{Concrete MRDT}
Element IDs and event timestamps are natural numbers; innate priorities and
increments are integers. An insertion tag is $(x,u)$ for element $x$ and
its Add timestamp $u$. The state is three finite sets, initially empty:
\[
\begin{aligned}
\Sigma&=\mathcal P_{\rm fin}((\mathbb N\times\mathbb N)\times\mathbb Z)
 \times\mathcal P_{\rm fin}((\mathbb N\times\mathbb N)\times\mathbb N\times\mathbb Z)
 \times\mathcal P_{\rm fin}(\mathbb N\times\mathbb N),\\
\sigma&=(B,I,R),\qquad\sigma_0=(\varnothing,\varnothing,\varnothing).
\end{aligned}
\]
$B$ stores births $((x,u),v)$ with innate value $v$; $I$ stores increment
attachments $((x,u),t,n)$, recording increment identity $t$ and amount $n$;
$R$ stores removed insertion tags. Payloads are $\F{add}(x,v)$,
$\F{inc}(x,n,W)$ and $\F{remove}(x,W)$, where $W$ is the finite set of
observed insertion timestamps carried by the latter two operations.
\[
\begin{aligned}
\F{do}((B,I,R),t,r,\F{add}(x,v))
 &= (B\cup\{((x,t),v)\},I,R),\\
\F{do}((B,I,R),t,r,\F{inc}(x,n,W))
 &= (B,I\cup\{((x,u),t,n)\mid u\in W\},R),\\
\F{do}((B,I,R),t,r,\F{remove}(x,W))
 &= (B,I,R\cup\{(x,u)\mid u\in W\}),\\
\F{merge}(l,a,b)&=(B_a\cup B_b,I_a\cup I_b,R_a\cup R_b).
\end{aligned}
\]
Here $a=(B_a,I_a,R_a)$ and $b=(B_b,I_b,R_b)$; the ancestor is ignored.
All three effects are additions to immutable stores and commute. Repeated
receipt of one increment does not count it twice because attachments form a set.

\textbf{Same-record priority.} For insertion tag $(x,u)$, define
\[
\begin{aligned}
A_\sigma(x,u)&=\sum_{((x,u),t,n)\in I}n,\\
C_\sigma(x)&=\{(u,v)\mid((x,u),v)\in B,\ (x,u)\notin R\},\\
E_\sigma&=\{x\mid C_\sigma(x)\ne\varnothing\},\\
p_\sigma(x)&=\begin{cases}
\operatorname{none},&C_\sigma(x)=\varnothing,\\
\operatorname{some}(v+A_\sigma(x,u)),&(u,v)=\max_{\rm lex}C_\sigma(x).
\end{cases}
\end{aligned}
\]
The greatest insertion timestamp selects both the innate value and its
increment attachments. Innate value breaks a forged equal-timestamp birth
tie on raw states; globally unique issued timestamps exclude this fallback.
Attachments naming an unknown birth do not create a query candidate. In
states built by honest preparation from the initial state, every attachment
has a birth; this property is preserved by union merge and is not an extra
issuance guard. Removed births and their attachments remain stored, but
never contribute to a new insertion.

For finite support $E$ and optional priority map $p$, put
\[
\begin{aligned}
M(E,p)&=\{(v,x)\mid x\in E,\ p(x)=\operatorname{some}(v)\},\\
\operatorname{maximum}(E,p)&=\begin{cases}
\operatorname{none},&M(E,p)=\varnothing,\\
\operatorname{some}(x,v),&(v,x)=\max_{\rm lex}M(E,p).
\end{cases}
\end{aligned}
\]
Maximum ties select the greatest element ID. Negative priorities are allowed.
The query alphabet and tagged answers are
\[
\begin{aligned}
Q_\tau&=\{\F{empty},\F{getMax}\}\cup
 \{\F{lookup}(x),\F{getPri}(x)\mid x\in\mathbb N\},\\
Val_\tau&=\mathbb B\uplus\operatorname{Option}(\mathbb Z)
 \uplus\operatorname{Option}(\mathbb N\times\mathbb Z).
\end{aligned}
\]
\[
\begin{aligned}
q(\sigma,\F{empty})&=\F{boolean}([E_\sigma=\varnothing]),\\
q(\sigma,\F{lookup}(x))&=\F{boolean}([x\in E_\sigma]),\\
q(\sigma,\F{getPri}(x))&=\F{priority}(p_\sigma(x)),\\
q(\sigma,\F{getMax})&=\F{maximum}(\operatorname{maximum}(E_\sigma,p_\sigma)).
\end{aligned}
\]

\paragraph{Independent sequential specification.}
The independent state is a finite partial priority map
$m:\mathbb N\rightharpoonup_{\rm fin}\mathbb Z$, initially empty. All
updates are total; timestamp, replica and observed snapshots do not affect
the abstract transition:
\[
\begin{aligned}
m&\xrightarrow{(t,r,\F{add}(x,v))}m[x\mapsto v],\\
m&\xrightarrow{(t,r,\F{inc}(x,n,W))}
 \begin{cases}m[x\mapsto v+n],&m(x)=\operatorname{some}(v),\\
 m,&m(x)=\operatorname{none},\end{cases}\\
m&\xrightarrow{(t,r,\F{remove}(x,W))}m\setminus\{x\}.
\end{aligned}
\]
Add overwrites a present key; increment and removal of an absent key are
no-ops. These are admitted transitions even where the source issuer would
reject the corresponding client request. There is no insertion identity,
attachment store, retained history or timestamp order in this state. The
mechanization represents the map by finite support and optional cells;
the invariant $x\in\operatorname{dom}(m)\iff m(x)\ne\operatorname{none}$ is
preserved from the initial state.

The four queries use the same tagged equations as above with
$E=\operatorname{dom}(m)$ and $p=m$. Query transitions preserve the map
and return exactly those answers. Every finite run from the empty map is
admitted. The full-event label projection is $f=\operatorname{id}$.

\paragraph{Derived maximum removal.}
At issuance, an empty queue emits no event. Otherwise, for the maximum
pair $(x,v)$ observed in $\sigma$, prepare
\[
\F{prepareRmvMax}(\sigma,t,r)=
 \operatorname{some}((t,r,\F{remove}(x,W_\sigma(x))),(x,v)),
\]
where the observed set $W_\sigma(x)$ is defined below. The local client
returns $(x,v)$ and applies that ordinary observed Remove. It makes $x$
absent locally and preserves every other priority. The independent derived
client selects the maximum of $m$ and clears that key. Their returned pair
and resulting finite map agree.

Replication carries the selected identity and snapshot; it does not select
a new maximum during replay. Two replicas may select the same element
concurrently, and an unseen concurrent Add may survive. This is local
observation followed by removal, not a globally atomic extraction operation.

\paragraph{Issuance.}
Preparation preserves the source's exact live-record snapshot, including
its raw-state behavior for increment placeholders. Define
\[
\begin{aligned}
T_\sigma&=\{(x,u)\mid\exists v,((x,u),v)\in B\}
 \cup\{(x,u)\mid\exists t,n,((x,u),t,n)\in I\},\\
L_\sigma&=T_\sigma\setminus R,\qquad
W_\sigma(x)=\{u\mid(x,u)\in L_\sigma\}.
\end{aligned}
\]
For original issuing state $\sigma=\pi_e(\sigma_0)$,
\[
\begin{aligned}
G((t,r,\F{add}(x,v)),\sigma)&\iff W_\sigma(x)=\varnothing,\\
G((t,r,\F{inc}(x,n,W)),\sigma)&\iff
 W_\sigma(x)\ne\varnothing\land W=W_\sigma(x),\\
G((t,r,\F{remove}(x,W)),\sigma)&\iff
 W_\sigma(x)\ne\varnothing\land W=W_\sigma(x).
\end{aligned}
\]
Thus the client prepares Add only when absent, and Inc/Remove only when
present, with exactly the observed insertion IDs. Event timestamp freshness
comes from the execution model rather than an additional preparation test.
The guard is checked at original issuance, not at reordered sequential prefixes.

\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$: the immutable concrete effects commute, and addition
wins unseen removal through the retained insertion tags. The ordinary map
updates at one element need not commute, so explaining replicated answers
requires a separately selected sequential order.

\paragraph{Mechanization status.}
The five merge verification conditions establish replay and convergence
for the immutable carrier, including recursive merge bases. For every stored
version of an execution satisfying the issuance guards, a single sequential
history explains all four queries and preserves visible pairs that do not
commute in the specification. The proof derives the required insertion and
snapshot facts from the execution, then combines the per-element histories.
The local maximum-removal refinement also equates the returned pair and the
resulting priority map.

\paragraph{Source and adaptation.}
This is an intentional query repair of the cited add-wins priority queue,
marked as an adaptation in Table~\ref{tab:implementation}. Its Add, Inc,
Remove effects and original preparation snapshots preserve the published
algorithm's per-insertion structure. The published query chooses the latest
innate priority and independently a Most-Change-Win record's acquired priority;
this repair takes both from the same latest surviving insertion. It therefore
changes the source query rather than proving source equivalence. For example,
Add$(x,10)$; Inc$(x,5)$; Remove$(x)$; Add$(x,2)$ returns priority $2$,
not $7$: the previous insertion's acquired increment is retained as data but
cannot leak into the new insertion. Maximum ties use the greatest element ID.

\subsection{Bounded counter with rights transfer}
\label{app:dt-bounded-counter}

\noindent Source references: \cite{BalegasBoundedCounter}.

% Sal/MRDTs/Instances/BalegasBoundedCounter.lean: Action, State, initial, update, merge, localRights, value, query, applicable, generation

% Sal/MRDTs/Paper1/BalegasBoundedCounterVC.lean: scheme, representation, fiveVC, replayConditions

% Sal/MRDTs/Paper1/BalegasBoundedCounterEvent.lean: Accounts, machine, spec, project

% Sal/MRDTs/Paper1/BalegasBoundedCounterCertificate.lean: certified, certifiedV, versions_safe, versions_safeV

% Sal/MRDTs/Paper1/BalegasBoundedCounterGlobal.lean: globalValue, global_bound, global_boundV

Each replica may decrement only against its local rights and may transfer rights to another replica. Cumulative single-writer cells make pointwise maximum merge safe; missing incoming transfers only underestimate the available rights.

\paragraph{Concrete MRDT}
Fix replicas $I=\{0,\ldots,N-1\}$ and lower bound $K\in\mathbb Z$. State is $R:\mathbb N\times\mathbb N\to\mathbb N$, $U:\mathbb N\to\mathbb N$, initially zero. Only indices in $I$ can issue updates or receive transfers; other cells remain zero.

\[
V(R,U)=K+\sum_{i\in I}R_{ii}-\sum_{i\in I}U_i,
\]

\[
B_i(R,U)=R_{ii}+\sum_{j\in I\setminus\{i\}}R_{ji}-\sum_{j\in I\setminus\{i\}}R_{ij}-U_i.
\]


For $e=(t,i,o)$ and amount $a\in\mathbb N$, accepted effectors are
\[
\begin{aligned}
\F{do}((R,U),t,i,\mathrm{inc}(a))&=(R[(i,i)\mapsto R_{ii}+a],U),\\
\F{do}((R,U),t,i,\mathrm{dec}(a))&=(R,U[i\mapsto U_i+a]),\\
\F{do}((R,U),t,i,\mathrm{transfer}(a,j))&=(R[(i,j)\mapsto R_{ij}+a],U).
\end{aligned}
\]

The issuance conditions appear below. $R_{ii}$ records increments, $R_{ij}$ for $i\ne j$ records transfers, and $U_i$ records consumption. Only issuer $i$ changes row $i$ and $U_i$.

\[
\F{merge}(l,a,b)=(\max(R_a,R_b),\max(U_a,U_b))
\]

Here $a=(R_a,U_a)$ and $b=(R_b,U_b)$. Maximum is componentwise;
ancestor $l$ is unused. Queries return $V(R,U)$ or $B_i(R,U)$.

\paragraph{Independent sequential specification.}
The independent state is $(v,b)$ with $v\in\mathbb Z$ and $b:\mathbb N\to\mathbb Z$, initially $(K,0)$. For $a\in\mathbb N$,
\[
\begin{aligned}
(v,b)&\xrightarrow{(t,i,\mathrm{inc}(a))}(v+a,b[i\mapsto b_i+a])&&\text{when }i\in I,\\
(v,b)&\xrightarrow{(t,i,\mathrm{dec}(a))}(v-a,b[i\mapsto b_i-a])&&\text{when }i\in I,\ a\le b_i,\\
(v,b)&\xrightarrow{(t,i,\mathrm{transfer}(a,j))}(v,b[i\mapsto b_i-a,j\mapsto b_j+a])&&\text{when }i,j\in I,\ i\ne j,\ a\le b_i.
\end{aligned}
\]

\[
\begin{aligned}
(v,b)&\xrightarrow{\mathrm{value}\Rightarrow y}(v,b)&&\text{when }y=v,\\
(v,b)&\xrightarrow{\mathrm{localRights}(i)\Rightarrow y}(v,b)&&\text{when }y=b_i.
\end{aligned}
\]

The scalar is the client counter value; balances expose separate rights accounting. The representation is $v=V(R,U)$ and $b_i=B_i(R,U)$.

Certified histories preserve
\[
v=K+\sum_{i\in I}b_i,\qquad\forall i.\ b_i\ge0,\qquad v\ge K.
\]

For the global union $E$ of all issued events, even when no replica holds that union,
\[
K+\sum_{e\in E}\Delta(e)\ge K,\qquad\Delta(\mathrm{inc}(a))=a,\quad\Delta(\mathrm{dec}(a))=-a,\quad\Delta(\mathrm{transfer}(a,j))=0.
\]

\paragraph{Issuance.}
Let $O=(R,U)$ be the original issuing state, $e=(t,i,o)$ and $a\in\mathbb N$.
\[
\begin{aligned}
G((t,i,\mathrm{inc}(a)),O)&\iff i\in I,\\
G((t,i,\mathrm{dec}(a)),O)&\iff i\in I\land a\le B_i(O),\\
G((t,i,\mathrm{transfer}(a,j)),O)&\iff i,j\in I\land i\ne j\land a\le B_i(O).
\end{aligned}
\]

Execution certification serializes updates from each replica and records their causal past. Missing incoming transfers can underestimate local rights; an issuer must retain all its own preceding updates. Stale forks issuing concurrently under the same replica identity are excluded. Zero amounts are allowed; negative amounts are outside the operation domain.


\paragraph{Conflict-resolution relation.}
The application policy is empty:
\[
\rcrel=\varnothing.
\]

Raw arithmetic updates commute, but maximum merge relies on cumulative
single-writer cells. Each replica's events are visibility-ordered, and the
witness respects causal order, so its own preceding increments, decrements
and transfers are present when reconstructing a cell. The issuance guard
funds each decrease from rights available at its original state. The merge
laws and resulting bound hold in both ordinary and recursive-merge executions.

\paragraph{Source and adaptation.}
The effectors and componentwise maximum merge follow the escrow counter of Balegas et al.; nonnegative amounts and a fixed replica universe delimit the port.

Enqueue inserts after the live tail and dequeue removes the observed head. Coordinates retain the insertion ancestry across merge; descending coordinate order gives the FIFO order selected by these issuance rules.

\paragraph{Concrete MRDT}
For $e=(t,r,o)$, the concrete carrier and initial state are
\[
\begin{aligned}\Sigma&=\operatorname{List}(\mathbb N\times\mathbb N\times\operatorname{List}(\mathbb B)),\\\sigma_0&=[].\end{aligned}
\]

A record is $(id,value,coordinate)$. The coordinate construction is Embedded RGA with the unary code below; the public interface changes only the query. Payloads are $\operatorname{ins}(v,p,a)$ and $\operatorname{del}(x)$.

\textbf{Update.} Let $I(S)=\{z.id\mid z\in S\}$ be the set of live IDs, $\Gamma$ the unary code $\Gamma(d)=[\underbrace{\mathsf{true},\ldots,\mathsf{true}}_{d},\mathsf{false}]$ (including $\Gamma(0)=[\mathsf{false}]$), and $\operatorname{insert}_{\downarrow}$ descending-key insertion. Write $z=(t,v,p\mathbin{+\!+}\Gamma(t-a))$.
\[
e(S)=\begin{cases}S&t\in I(S),\ o=\operatorname{ins}(v,p,a),\\\operatorname{insert}_{\downarrow}(z,S)&t\notin I(S),\ o=\operatorname{ins}(v,p,a),\\\operatorname{filter}_{id\ne x}(S)&o=\operatorname{del}(x).\end{cases}
\]

Natural subtraction floors at zero. For a bit coordinate $c$, the comparison key is $K_Q(c)=\operatorname{map}(b\mapsto\mathrm{if}\ b\ \mathrm{then}\ 2\ \mathrm{else}\ 1,c)\mathbin{+\!+}[3]$. Keys use strict lexicographic order on natural numbers, with a proper prefix smaller than its extension; IDs and values do not break ties. Insertion places the new record before the first strictly smaller key; equal keys retain delivery order.

\textbf{Three-way merge.} For ancestor $l$ and branches $a,b$, define survivor lists, preserving input order:
\[
\begin{aligned}a^*&=[z\in a\mid z.id\in I(b)\lor z.id\notin I(l)],\\b^*&=[z\in b\mid z.id\notin I(l)\land z.id\notin I(a)],\\\F{merge}(l,a,b)&=\F{merge}_{\downarrow}(a^*,b^*).\end{aligned}
\]

The descending merge emits the larger head key; ties choose the right head. The ancestor distinguishes deletion of existing elements from new insertions. Values and coordinates remain immutable.

\textbf{Query.}
\[
\begin{aligned}\operatorname{query}_{Q}(S)&=\operatorname{map}(value,S),\\\operatorname{query}_{public}(S)&=\begin{cases}\operatorname{none}&S=[],\\\operatorname{some}(id,value)&(id,value,c)\text{ is the head.}\end{cases}\end{aligned}
\]

No deleted-element birth history is stored.

\textbf{Sorting is total on arbitrary lists.} Put $k(z)=K_Q(z.coordinate)$ and define the previously used insertion and merge by
\[
\begin{aligned}J(z,[])&=[z],\\J(z,y::Y)&=\begin{cases}z::y::Y&k(y)<_{\mathrm{lex}}k(z),\\y::J(z,Y)&\text{otherwise},\end{cases}\\M([],Y)&=Y,\qquad M(X,[])=X,\\M(x::X,y::Y)&=\begin{cases}x::M(X,y::Y)&k(y)<_{\mathrm{lex}}k(x),\\y::M(x::X,Y)&\text{otherwise}.\end{cases}\end{aligned}
\]

Here $\operatorname{insert}_{\downarrow}=J$ and $\F{merge}_{\downarrow}=M$.


\paragraph{Independent sequential specification.}
\textbf{Abstract state.} A retained update prefix $h$ and a FIFO list $B$ of birth-ID/value pairs,
with no implementation coordinates:
\[
\Phi=\mathcal E^*\times\operatorname{List}(\mathbb N\times\mathbb N),\qquad\phi_0=([],[]).
\]

\textbf{Total update helpers.} Enqueue uses event ID $t$ and ignores its carried anchor and coordinate:
\[
\begin{aligned}\operatorname{enq}(B,t,v)&=B+\!+[(t,v)],\\\operatorname{delete}(B,x)&=\operatorname{filter}_{id\ne x}(B).\end{aligned}
\]


\textbf{Legal histories.} Let $\operatorname{Born}(h)$ contain all earlier insertion IDs, including deleted ones, and let $B(h)$ be the abstract FIFO fold of update prefix $h$.
\[
\begin{aligned}\operatorname{legalEnq}(h,t)&\iff t\notin\operatorname{Born}(h)\land t\notin I(B(h)),\\\operatorname{legalDel}(h,x)&\iff x\in\operatorname{Born}(h)\land\\&\quad(x\notin I(B(h))\lor\operatorname{headId}(B(h))=\operatorname{some}(x)).\end{aligned}
\]

An absent deletion is legal only for an earlier allocation. There is no special root-delete exception. This legality predicate itself imposes no positivity or timestamp ordering.

\textbf{Admitted transitions.} Initially $(h,B)=([],[])$. Here $h$ retains full update events and $e=(t,r,o)$:
\[
\begin{aligned}(h,B)&\xrightarrow{e}(h+\!+[e],\operatorname{enq}(B,t,v))\\&\text{when }o=\operatorname{ins}(v,p,a)\land\operatorname{legalEnq}(h,t),\\(h,B)&\xrightarrow{e}(h+\!+[e],\operatorname{delete}(B,x))\\&\text{when }o=\operatorname{del}(x)\land\operatorname{legalDel}(h,x).\end{aligned}
\]

For internal or public reads respectively, define
\[
\begin{aligned}q_{\mathrm{internal}}(B)&=\operatorname{map}(value,B),\\q_{\mathrm{public}}(B)&=\operatorname{head?}(B),\\(h,B)&\xrightarrow{\F{rd}\Rightarrow a}(h,B)\\&\text{when }a=q_j(B),\quad j\in\{\mathrm{internal},\mathrm{public}\},\end{aligned}
\]

Here $j$ is fixed by the selected interface. The public head is the optional (ID,value) pair. Every finite run satisfying the displayed admission rules is accepted.

\textbf{Example.} Enqueue IDs $1,2$ with values $10,20$. The head is $\operatorname{some}(1,10)$; after deleting $1$ it is $\operatorname{some}(2,20)$. Deleting $1$ again is legal and changes nothing. Deleting $2$ while both are live is illegal; deleting never-allocated $3$ is also illegal.

The update labels retain full events, $f=\operatorname{id}$; the abstract effect ignores the carried anchor and coordinate.


\paragraph{Issuance.}
For $e=(t,r,o)$ and original issuing state $S$, write $H(S)$ for its optional head ID and $T(S)$ for its optional last (ID,coordinate) pair.
\[
G(e,S)\iff\begin{cases}a<t\ \land\bigl((S=[]\land a=0\land p=[])\lor T(S)=\operatorname{some}(a,p)\bigr)&o=\operatorname{ins}(v,p,a),\\H(S)=\operatorname{some}(x)&o=\operatorname{del}(x).\end{cases}
\]

Timestamp freshness and replica/causal constraints come from the execution model. This guard is checked at the original issuing state $\pi_e(\sigma_0)$,
not again at each prefix of a reordered abstract history.

\textbf{Client requests:} $\mathsf{enqueue}(v)$ and $\mathsf{dequeue}$ contain no identity or coordinate. Preparation reads the live tail for enqueue and the live head for dequeue. Empty dequeue generates no event. Enqueue preparation fails unless its clock exceeds the tail identity (or zero for an empty queue). Every message admitted by the original issuer is generated by one of these requests.

For a sorted issuing state with unique IDs and a fresh clock, preparation implements the local value-list transitions
\[
L\xrightarrow{\mathsf{enqueue}(v)}L\cdot[v],\qquad
L\xrightarrow{\mathsf{dequeue}}\operatorname{tail}(L)\quad\text{when }L\ne[].
\]

The concurrent history still removes the observed head identity: two replicas removing the same head do not consume two different elements.


\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$. The update and merge laws hold for the states and event prefixes arising in guarded executions. A sequential witness establishes the editor specification above.


\paragraph{Source and adaptation.}
This queue uses the embedded RGA coordinate kernel with FIFO issuance and a head query. Its abstract operations are enqueue and deletion of the named head.

An insertion names its predecessor, and a deletion records an identity permanently. Sorting insertion edges by timestamp reconstructs the insertion tree in newest-sibling-first order; filtering tombstones yields the visible identifier list.

\paragraph{Concrete MRDT}
Insertion uses timestamp $t$ as its identity; the replica is ignored by the effect. Raw effects are total.

On reachable states, $(A,T)$ consists of two finite sets: insertion edges
$(i,a)$ and deleted IDs. Initially $(A_0,T_0)=(\varnothing,\varnothing)$.
The total implementation represents both as Boolean predicates; the support
convention below also defines queries on predicates with infinite support.

\[
\begin{aligned}\F{do}((A,T),t,r,\operatorname{AddAfter}(a))&=(A\cup\{(t,a)\},T),\\\F{do}((A,T),t,r,\operatorname{Remove}(x))&=(A,T\cup\{x\}),\\\F{merge}(l,a,b)&=l\cup a\cup b\quad\text{componentwise}.\end{aligned}
\]


Define $\operatorname{supp}(f)=\{x\mid f(x)=\mathsf{true}\}$ when finite, and $\varnothing$ otherwise. Materialize each component independently. Let $P(B,0,t)=t::B$, $P([],a,t)=[]$ for $a\ne0$, and

\[
P(x::X,a,t)=\begin{cases}x::t::X&x=a\land a\ne0,\\x::P(X,a,t)&x\ne a\land a\ne0.\end{cases}
\]


Enumerate the finite edge support and stable-sort it by increasing first coordinate; call the resulting list $E$. Fold $P(B,a,i)$ over $(i,a)\in E$ starting at $[]$ to obtain $B_E$.

\[
q(A,T)=[i\in B_E\mid i\notin\operatorname{supp}(T)].
\]


Fix the finite-set enumeration used by the implementation; stable sorting retains that order on equal timestamps. Honest histories have unique insertion IDs, so such ties are absent. The infinite-support fallback defines the query on all Boolean predicates.


\paragraph{Independent sequential specification.}
State $(B,\mathcal I)$: live ID list and permanent allocation set; $(B_0,\mathcal I_0)=([],\varnothing)$. Use $P$ defined in the MRDT definition. The selected strict identified machine has these admitted transitions:

\[
\begin{aligned}(B,\mathcal I)&\xrightarrow{(t,r,\operatorname{AddAfter}(a))}(P(B,a,t),\mathcal I\cup\{t\})\\&\qquad\text{when }0<t\land t\notin\mathcal I\land(a=0\lor a\in B),\\(B,\mathcal I)&\xrightarrow{(t,r,\operatorname{Remove}(x))}([i\in B\mid i\ne x],\mathcal I),\\q(B,\mathcal I)&=B.\end{aligned}
\]


Every finite admitted run belongs to the event-spec language. $\mathcal I$ retains
deleted insertion IDs; deletion-event timestamps do not allocate IDs. There
is no increasing-ID guard. Remove is always admitted and is a no-op on a
non-live ID, unlike the stricter issuance guard below.

\textbf{Positional client boundary.} Let $V(S)=q(S)$ be the visible ID list.
A request $u$ inserts at a list index or deletes its element;
$\operatorname{edit}_t$ denotes that list edit with fresh insertion ID $t$.
At a certified source and an actual apply step, successful preparation satisfies

\[
\operatorname{prepare}(V(S),t,r,u)=e\quad\Longrightarrow\quad q(e(S))=\operatorname{edit}_t(V(S),u).
\]


Execution supplies finite birth support, unique positive IDs, timestamp freshness and the required live anchor. The theorem holds for ordinary and recursive certified executions; the global identified-history contract above remains separate.

\paragraph{Issuance.}
Let $\operatorname{born}(i)\iff\exists a, A(i,a)$. Then:

\[
\begin{aligned}G((t,r,\operatorname{AddAfter}(a)),(A,T))&\iff\big((a=0\land 0<t)\lor(\neg T(a)\land a<t\land\operatorname{born}(a))\big)\\&\quad\land\neg\operatorname{born}(t)\land\neg T(t),\\G((t,r,\operatorname{Remove}(x)),(A,T))&\iff\operatorname{born}(x)\land\neg T(x).\end{aligned}
\]


ID zero is reserved exclusively for the root. Every issued insertion has a positive ID; global execution freshness is separate.


\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$. The grow-only concrete updates commute. The strict editor specification is established for guarded executions.


\paragraph{Source and adaptation.}
The state-based RGA records insertion edges and deletion evidence. The query
returns an identifier sequence. Siblings use descending timestamps, with no
replica tie-break, unlike the timestamp/replica ordering of the source.

Fix $\operatorname{enc}:\mathbb N\to\{0,1\}^*$: for $1\le d<e$, $\operatorname{enc}(d)<_{\rm lex}\operatorname{enc}(e)$; distinct positive arguments have no prefix-related codewords. The terminator $3$ puts an ancestor before its descendants in descending

an ancestor and two children can have keys $[2,1,3]$,

then the newer child, then the older child.

\[
q(S)=[v\mid(i,v,c)\in S].

\textbf{Total editor helper.} For a list $B$ of pairs and new pair $z=(t,v)$, define:

\begin{aligned}P_s([],a,z)&=[],\\P_s(y::Y,a,z)&=\begin{cases}z::y::Y&y.i=a,\ s=L,\\y::z::Y&y.i=a,\ s=R,\\y::P_s(Y,a,z)&y.i\ne a.\end{cases}\end{aligned}
\]


This uses the first matching anchor; an absent anchor leaves the list unchanged. $B_0=[]$; define $P(B,a,z)=z::B$ if $a=0$, otherwise $P_R(B,a,z)$.

\[
\begin{aligned}V_e(B)&=\begin{cases}P(B,a,(t,v))&o=\operatorname{Ins}(v,\pi,a),\\{}[(i,v)\in B\mid i\ne x]&o=\operatorname{Del}(x),\end{cases}\\q(B)&=[v\mid(i,v)\in B].\end{aligned}

\begin{aligned}\operatorname{Admit}(h,(t,r,\operatorname{Ins}(v,\pi,a)))&\iff(\forall p\in\operatorname{InsEvents}(h),\ p.t<t)\\&\quad\land\big((a=0\land\pi=[])\lor\exists p\in\operatorname{InsEvents}(h),\ p.t=a\land c_p=\pi\big),\\\operatorname{Admit}(h,(t,r,\operatorname{Del}(x)))&\iff\exists p\in\operatorname{InsEvents}(h),\ p.t=x.\end{aligned}
\]


The admitted transition carries the history solely to check $\operatorname{Admit}$:

\[
(h,B)\xrightarrow{e}(h++[e],V_e(B))\quad\text{when }\operatorname{Admit}(h,e).
\]


This history language requires earlier allocation, permits repeated deletion and permits insertion after an anchor subsequently deleted. Thus legal histories can contain a missing-anchor no-op; the stronger sequential refinement premise also checks current-fold applicability. Prefix $\pi$ affects legality but not the editor effect.

\textbf{Positional client boundary.} Clients request insertion/deletion at an index; preparation supplies the generated anchor and coordinate prefix. \]

This physical-effect theorem derives sortedness, identity uniqueness, and the clock bound from the execution. It assumes no separately supplied legal replay history. The global history language displayed above remains distinct from this local client theorem.

These predicates restrict issuance, not the total raw effects.

\begin{aligned}\operatorname{Admit}(h,(t,r,\operatorname{Ins}(v,\pi,a,s)))&\iff(\forall p\in\operatorname{InsEvents}(h),\ p.t<t)\\&\quad\land\big((a=0\land\pi=[])\lor\exists p\in\operatorname{InsEvents}(h),\ p.t=a\land c_p=\pi\big),\\\operatorname{Admit}(h,(t,r,\operatorname{Del}(x)))&\iff\exists p\in\operatorname{InsEvents}(h),\ p.t=x.\end{aligned}
\]


The admitted transition carries the history solely to check $\operatorname{Admit}$:

\[
(h,B)\xrightarrow{e}(h++[e],V_e(B))\quad\text{when }\operatorname{Admit}(h,e).
\]


This history language requires earlier allocation, permits repeated deletion and permits insertion after an anchor subsequently deleted. Thus legal histories can contain a missing-anchor no-op; the stronger sequential refinement premise also checks current-fold applicability. Prefix $\pi$ affects legality but not the editor effect.

\textbf{Positional client boundary.} Clients request insertion/deletion at an index; preparation supplies the generated anchor and coordinate prefix. An index
less than the current length selects a left insertion before that element;
the end index selects a right insertion after the final element. Let $V$ erase coordinates from the physical records while retaining IDs and values, and let $\operatorname{edit}_t$ be the ordinary positional list edit, using $t$ as the new identity. For a certified source state and an actual apply step,
\[
\operatorname{prepare}(S,t,r,u)=e\quad\Longrightarrow\quad V(e(S))=\operatorname{edit}_t(V(S),u).
\]

This physical-effect theorem derives sortedness, identity uniqueness, and the clock bound from the execution. It assumes no separately supplied legal replay history. The global history language displayed above remains distinct from this local client theorem.

\[
\begin{aligned}G((t,r,\operatorname{Ins}(v,\pi,a,s)),S)&\iff a<t\land\big((a=0\land\pi=[])\lor\exists v',(a,v',\pi)\in S\big),\\G((t,r,\operatorname{Del}(x)),S)&\iff x\in I(S).\end{aligned}

\paragraph{Concrete MRDT}
\textbf{Carrier and records.} Fix a Boolean code $\Gamma:\mathbb N\to\operatorname{List}(\mathbb B)$ satisfying
\[
1\le d<e\Rightarrow\Gamma(d)<_{\mathrm{lex}}\Gamma(e),\qquad 1\le d,e\land d\ne e\Rightarrow\neg(\Gamma(d)\text{ is a prefix of }\Gamma(e)).
\]

Boolean lexicographic order has false < true. An event is $e=(t,r,(o,\ell,\rho,h))$, where $o=\operatorname{ins}(p,s)$ or $\operatorname{del}(x)$, $s\in\{L,R\}$, $\ell\in\mathbb N$, $\rho\in\operatorname{Option}(\mathbb N)$ and $h$ is a chain of entries $L(d)$ or $R(\tau,d)$ with $\tau\in\operatorname{List}(\mathbb N)$. Here $p$ is the structural parent, $s$ the child side, $\ell$ the visible left origin, $\rho$ the optional right origin, and $h$ the encoded ancestry chain.
\[
\Sigma=\operatorname{List}(\mathbb N\times\mathbb N\times\operatorname{List}(\mathbb N))\times\mathcal P_{\rm fin}(\mathsf{Birth}),\qquad\sigma_0=([],\varnothing).
\]

Write $S$ for live records, $B$ for births, and $\operatorname{ids}(S)=\operatorname{map}(id,S)$; membership uses this list's underlying set.

\textbf{Coordinate encoding.} Let $\bar b$ complement a Boolean bit and let $\mathbin{\ominus}$ denote truncated natural subtraction. Concatenation is $+\!+$.
\[
\begin{aligned}u_R(\mathsf{false})&=1,&u_R(\mathsf{true})&=2,\\u_L(\mathsf{false})&=4,&u_L(\mathsf{true})&=5,\\W(k)&=[\lfloor(8\mathbin{\ominus} k)/3\rfloor,(8\mathbin{\ominus} k)\bmod3],\\W^*(\tau)&=\mathop{+\!+}_{k\in\tau}W(k),\\D_s(d)&=\operatorname{map}(b\mapsto u_s(\bar b),\Gamma(d)),\\F(L(d))&=D_L(d),&F(R(\tau,d))&=W^*(\tau)+\!+D_R(d),\\C(h)&=\mathop{+\!+}_{v\in h}F(v),&K(c)&=c+\!+[3].\end{aligned}
\]

Empty concatenations are empty lists. Compare $K(c)$ by strict natural-number lexicographic order (a proper prefix is smaller); IDs and values do not break ties.

\textbf{Sorting helpers.} For record $z$, put $k(z)=K(z.coordinate)$. Define descending insertion $J$ and two-list merge $M$ recursively:
\[
\begin{aligned}J(z,[])&=[z],\\J(z,y::Y)&=\begin{cases}z::y::Y&k(y)<_{\mathrm{lex}}k(z),\\y::J(z,Y)&\text{otherwise},\end{cases}\\M([],Y)&=Y,\qquad M(X,[])=X,\\M(x::X,y::Y)&=\begin{cases}x::M(X,y::Y)&k(y)<_{\mathrm{lex}}k(x),\\y::M(x::X,Y)&\text{otherwise}.\end{cases}\end{aligned}
\]

Insertion passes existing equal keys; merge selects the right head on equal keys.

\textbf{Update, merge, query.} Let $z_g=(t,t,C(h))$ and $D_x(S)=[z\in S\mid z.id\ne x]$.

\begin{aligned}X&=[z\in S_a\mid z.id\in\operatorname{ids}(S_b)\lor z.id\notin\operatorname{ids}(S_l)],\\Y&=[z\in S_b\mid z.id\notin\operatorname{ids}(S_l)\land z.id\notin\operatorname{ids}(S_a)],\\\F{merge}(l,a,b)&=(M(X,Y),B_a\cup B_b),\\\operatorname{query}((S,B),())&=\operatorname{ids}(S).\end{aligned}

Deleted births persist. Each inserted ID is also its displayed value. The concrete list contains no root sentinel.

The current carrier observes identities rather than arbitrary character values.

\operatorname{PI}(r,t,i)=(t,r,o_i,a,\rho_i,h_i).

\subsection{Tree move}
\label{app:dt-tree-move}

\noindent Source references: \cite{TreeMove}.

% Sal/MRDTs/Instances/TreeMove.lean: Tree, Move, Event, eventKey, doMove, visibleTree, spec, SequentialLegal
% Sal/MRDTs/Instances/TreeMoveIncremental.lean: Rejects, sourceMove, candidate_safe_iff, LogEntry, RawState, push, undo, applyRaw, build, events, receive, canonical_tree
% Sal/MRDTs/Instances/TreeMoveIncrementalMRDT.lean: Coherent, State, update, mergeRaw, merge, query, D, sourceApplicable, generation, fiveVC
% Sal/MRDTs/Instances/TreeMoveIncrementalCertificate.lean: SourceClientLegal, sourceClientLegal_iff, sequentialSpec, history, certified, certifiedV, executions, executionsV, verified
% Sal/MRDTs/Instances/TreeMoveIncrementalReadSide.lean: source_comparison, applyRaw_eq_sourceApply, receive_eq_sourceApply, run_coherent, run_tree

A move $\mathrm{Move}(p,m,c)$ attaches child $c$ to parent $p$ with metadata
$m$. The implementation maintains a tree and an undo log. Late delivery
undoes newer moves, inserts the received move, then redoes the newer moves;
any move creating a cycle leaves the tree unchanged but remains in the log.

\paragraph{Concrete MRDT}
A tree is $T:\mathbb N\to\operatorname{Option}(\mathbb N\times\mathbb N)$,
where $T(c)$ stores the parent and metadata of child $c$. Root is $0$ and
trash is $1$. Write $x\to_T y\iff\exists m,T(x)=\operatorname{some}(y,m)$
and $\to_T^+$ for a nonempty finite path. For event
$e=(t,r,\mathrm{Move}(p,m,c))$, put $k(e)=(t,r,p,m,c)$ and
\[
f(T,e)=\begin{cases}
T,&c=p\lor p\to_T^+c,\\
T[c\mapsto\operatorname{some}(p,m)],&\text{otherwise}.
\end{cases}
\]
On an acyclic tree this test is equivalent to requiring that the new tree
be acyclic: $c\ne p$ and $c$ is not an ancestor of $p$.

\textbf{Log and state.} A log entry $q=(e,u)$ stores its event and the
previous parent/metadata $u\in\operatorname{Option}(\mathbb N^2)$ of that
event's child. A state $s=(Q,T)$ has a newest-first log $Q$ and a maintained
tree $T$. Define the helpers
\[
\begin{aligned}
\operatorname{push}((Q,T),e)&=((e,T(c))::Q,f(T,e)),\\
\operatorname{undo}((e,u),T)&=T[c\mapsto u].
\end{aligned}
\]
Both accepted and rejected moves record their previous parent. Redo calls
$\operatorname{push}$ again, recomputing that old parent.

To state log consistency precisely, let
\[
\begin{aligned}
\operatorname{build}([])&=([],T_0),\qquad T_0(x)=\operatorname{none},\\
\operatorname{build}(e::E)&=\operatorname{push}(\operatorname{build}(E),e),\\
\operatorname{events}(Q,T)&=\{e\mid(e,u)\text{ occurs in }Q\},\\
\mathcal C(E)&=\operatorname{build}(\operatorname{sort}_{k\downarrow}(E)).
\end{aligned}
\]
The state space and initial state are
\[
\Sigma=\{s=(Q,T)\mid s=\mathcal C(\operatorname{events}(s))\},
\qquad\sigma_0=([],T_0).
\]
Thus logs have distinct events in descending key order, each undo edge is
consistent with its older log suffix, and the maintained tree is their
oldest-first result. The function $\mathcal C$ defines this invariant;
operational updates and queries do not call it.

\textbf{Update and delivery.} Define insertion into a log by
\[
\begin{aligned}
\operatorname{applyRaw}(e,[],T)&=\operatorname{push}(([],T),e),\\
\operatorname{applyRaw}(e,q::Q,T)&=\begin{cases}
\operatorname{push}(\operatorname{applyRaw}(e,Q,\operatorname{undo}(q,T)),q.e),
 &k(e)<k(q.e),\\
\operatorname{push}((q::Q,T),e),&\text{otherwise}.
\end{cases}\\
\operatorname{receive}(s,e)&=\begin{cases}
s,&e\in\operatorname{events}(s),\\
\operatorname{applyRaw}(e,s.Q,s.T),&\text{otherwise},
\end{cases}\\
e(s)&=\operatorname{receive}(s,e).
\end{aligned}
\]
The full key defines collision behavior on all states. With globally unique
timestamps, comparison is exactly the source algorithm's timestamp test.
Receive preserves log consistency and suppresses duplicate events.

\textbf{Three-way merge.} Deliver the other branch's log to the first branch:
\[
\F{merge}(l,a,b)=\operatorname{foldl}
 (\operatorname{receive},a,[q.e\mid q\in b.Q]).
\]
The ancestor is ignored. Merge performs the same undo/insert/redo delivery
as update, preserving log consistency; it does not replay the tree from
scratch. Its event set is $\operatorname{events}(a)\cup\operatorname{events}(b)$.

\textbf{Query.} Hide the trash node and descendants under trash:
\[
\begin{aligned}
\operatorname{hidden}(T,x)&\iff x=1\lor x\to_T^+1,\\
\operatorname{visible}(T)(x)&=\begin{cases}
\operatorname{none},&\operatorname{hidden}(T,x),\\T(x),&\text{otherwise},
\end{cases}\\
q((Q,T),())&=\operatorname{visible}(T).
\end{aligned}
\]
The query reads the maintained tree without sorting or traversing the log.

\paragraph{Independent sequential specification.}
The independent state is a tree $T$, initially $T_0$, together with an update
prefix $h$ used for admission. For $h=[e_1,\ldots,e_n]$, define
\[
\operatorname{Legal}(h)\iff\operatorname{Nodup}(h)
\land(\forall i<j,\ k(e_i)\le_{\rm lex}k(e_j))
\land\forall e\in h,\ e.c\ne0\land e.c\ne1.
\]
The admitted transitions are the ordinary in-place moves
\[
\begin{aligned}
(h,T)&\xrightarrow{e}(h\mathbin{+\!+}[e],f(T,e))
 &&\text{when }\operatorname{Legal}(h\mathbin{+\!+}[e]),\\
(h,T)&\xrightarrow{\F{rd}\Rightarrow y}(h,T)
 &&\text{when }y=\operatorname{visible}(T).
\end{aligned}
\]
A cycle-rejected move still extends the prefix. This machine has no undo
log. The selected witness sorts events by increasing $k$; Lamport timestamp
growth ensures that this witness respects visibility.

\paragraph{Issuance.}
For original issuing state $s$ and $e=(t,r,\mathrm{Move}(p,m,c))$,
\[
G(e,s)\iff
 (\forall(t',r',o')\in\operatorname{events}(s),\ (t',r')\ne(t,r))
 \land c\ne0\land c\ne1.
\]
The wrapper reserves root and trash as children and requires a fresh event
identifier. A destination need not exist or be visible; a hidden child may
be moved out of trash. There is no additional visibility guard on $p$ or $c$.

\paragraph{Conflict-resolution relation.}
$\rcrel=\varnothing$. Complete deliveries commute on the coherent state
space, including their undo metadata. The five merge verification conditions
and independent tree specification cover ordinary and recursive-merge
executions.

\paragraph{Source and adaptation.}
Update implements the source's incremental undo/insert/redo algorithm.
The MRDT adaptation exchanges state by delivering the other log, suppresses
duplicates, and reserves root/trash in the editor interface. Full event keys
totalize timestamp collisions; unique timestamps recover the source comparison.
The result establishes the mathematical algorithm and its maintained-tree
query, without an executable performance claim.

\textbf{Document-order rich query.} Let $Z$ be the retained ID/value list, $b=[i\mid(i,v)\in Z]$, $\ell=[i\in b\mid i\notin D]$, $n=|\ell|$. $\operatorname{idx}(X,a)$ is the first index of $a$ in $X$, or $|X|$ if absent. $\operatorname{cp}(a)$ is the value of the first pair in $Z$ with ID $a$, defaulting to $0$.

Thus an absent ID gives $R(a)=\bot$, while $L(a)$ scans all of $b$. For endpoint side $s$ define:

\[
\begin{aligned}T(a,s)&=\begin{cases}a&a\in\ell,\\R(a)&a\notin\ell,\ s=\mathrm{before},\\L(a)&a\notin\ell,\ s=\mathrm{after}.\end{cases}\end{aligned}
\]


For mark ID $u$, let $r_u(j)$ be the length of the initial contiguous run of IDs $>u$ in $\ell$ starting at $j$; $l_u(j)$ is that length in the reverse of the prefix of length $j$. Define $g_u(i)=i+1+r_u(i+1)$ and $h_u(i)=i-l_u(i)$. Resolved start $a=T(m.\mathrm{startID},m.\mathrm{startSide})$ and end $z=T(m.\mathrm{endID},m.\mathrm{endSide})$ yield:

\[
\begin{aligned}\alpha_m&=\begin{cases}\bot&a=\bot,\ \mathrm{startSide}=\mathrm{before},\\0&a=\bot,\ \mathrm{startSide}=\mathrm{after},\\\operatorname{idx}(\ell,a)&a\ne\bot,\ \mathrm{startSide}=\mathrm{before},\\g_{m.\mathrm{mid}}(\operatorname{idx}(\ell,a))&a\ne\bot,\ \mathrm{startSide}=\mathrm{after},\end{cases}\\\beta_m&=\begin{cases}\bot&z=\bot,\ \mathrm{endSide}=\mathrm{after},\\n&z=\bot,\ \mathrm{endSide}=\mathrm{before},\\g_{m.\mathrm{mid}}(\operatorname{idx}(\ell,z))&z\ne\bot,\ \mathrm{endSide}=\mathrm{after},\\h_{m.\mathrm{mid}}(\operatorname{idx}(\ell,z))&z\ne\bot,\ \mathrm{endSide}=\mathrm{before}.\end{cases}\end{aligned}
\]


$\bot$ is a missing optional boundary, not a numeric position. A mark covers $j$ exactly when both boundaries exist and $\alpha_m\le j<\beta_m$. Fix the implementation's enumeration of $F$. Among covering marks of requested type $k$, select maximum mid, retaining the earlier enumerated record on ties; if none, set the flag false. \Delta(k,\mathsf{bootstrap}(x))={}&B(\mathsf{initial},k,\mathsf{start},x)\\
&\cup\{\mathsf{created}(\mathsf{initial},\operatorname{none})\},\\
\Delta(k,\mathsf{create}(a))={}&\{\mathsf{created}(b_k,a)\},\\
\Delta(k,\mathsf{insert}(b,i,o,x))={}&B(i,k,o,x),\\
\Delta(k,\mathsf{erase}(b,i,X))={}&\{\mathsf{erased}(i,j)\mid j\in X\},\\
\Delta(k,\mathsf{split}(b,i,o))={}&\{\mathsf{birth}(i,(k,\mathsf{split},o)),\\
&\mathsf{created}(b_k,\operatorname{some}(b)),\mathsf{cut}(i,k,b_k)\}.
\end{aligned}
\]

All facts from one transaction enter atomically. Empty bootstrap still creates its block. Split's create, marker and ownership fact enter together.
\[
\F{do}(F,t,r,\tau)=F\cup\Delta(\tau),\qquad\F{merge}(l,a,b)=a\cup b.
\]

Receipt is idempotent and independent of arrival order, including a late lower-key transaction. Ordinary and canonical recursive merges use this same union; the ancestor argument is ignored.

\textbf{Rows, cuts and display.}
Fix injective names $\beta:K\to\mathbb N$, with
$\beta(\mathsf{initial})=0$, and $\nu$ for session lists. Their partial
inverses fail outside their images. These names need not preserve source-ID
order. Semantic addresses are
\[
 a(i,(c,u))=(\beta(i),\mathsf{event}(\nu(u),c)),\qquad
 a(i,\mathsf{start})=(\beta(i),\mathsf{start}).
\]
For instance $i$, let $T_i$ be the finite set of its birth rows after
changing a text row's deletion bit $d$ to
$d\lor[\mathsf{erased}(i,k)\in F]$.
A split row is unchanged. Enumerate $T_i$ in the chosen finite-set order;
write $n_i=|T_i|$, and let $\operatorname{row}_i(k)$ be the first row
with identity $k$, or absent. Let $\operatorname{children}_i(o)$ be the
row identities whose origin is $o$, sorted in descending source-ID order.
Define the fuel-bounded traversal
\[
\begin{aligned}
V_i(0,o)&=[],\\
V_i(n+1,o)&=\mathop{+\!+}_{k\in\operatorname{children}_i(o)}
\begin{cases}
[\operatorname{row}_i(k).\mathsf{item}]
 +\!+V_i(n,\mathsf{item}(k))&\operatorname{row}_i(k)\text{ exists},\\
[]&\text{otherwise}.
\end{cases}
\end{aligned}
\]
The physical list $P_i(F)$ starts with a virtual split atom at
$(\beta(i),\mathsf{start})$, followed by $V_i(n_i,\mathsf{start})$,
with each item $k$ addressed by $a(i,k)$. The fuel is sufficient on
honest closed rows; it also defines the raw query on malformed cycles.

Extract the finite owner/start record set
\[
\begin{aligned}
C(F)={}&\{(\beta(b),(\beta(b),\mathsf{start}))
       \mid\mathsf{created}(b,a)\in F\}\\
&\cup\{(\beta(b),a(i,k))\mid\mathsf{cut}(i,k,b)\in F\}.
\end{aligned}
\]
Enumerate $C(F)$ in the chosen finite-set order as $C^*(F)$.
For each $i$, traverse $P_i(F)$ and, at each atom, emit the first record
in $C^*(F)$ whose start equals that atom's address and whose start
instance is $\beta(i)$. This gives boundary records $c_1,\ldots,c_m$ in
physical order. For $c_j$, scan strictly after its first start occurrence
up to the first occurrence of $c_{j+1}.\mathsf{start}$, or END for $j=m$.
The resulting interval contains every intervening atom, including
tombstones. A missing start gives an empty interval; a missing next endpoint
retains the remainder of the physical list under the raw endpoint scan. Honest partitions supply all these boundaries exactly
once. Stops are derived from the present physical order.

For numeric block $b$, select the first record in $C^*(F)$ owned by $b$
whose start instance differs from $b$; if there is none, select the first
record owned by $b$. If neither exists, return $\operatorname{none}$.
Decode the selected start instance to its block key, failing with
$\operatorname{none}$ if decoding fails. Find its interval by the selected start
address, failing if absent. Emit the values of its live text atoms only.
This partial function is $\operatorname{blockText}(F,b)$.
Honest core shape makes the active record unique. Deleted anchors,
markers, and inactive title roots remain structural data.

Let $\Lambda(F)=\{(b,a)\mid\mathsf{created}(b,a)\in F\}$.
The creator key is $(1,[65])$ for $\mathsf{initial}$ and $k$ for
$\mathsf{issued}(k)$. Stable-sort the chosen enumeration of $\Lambda(F)$
by increasing creator key. Starting from $\mathrm{Ord}=[]$, fold each $(b,a)$:
if $\beta(b)\in\mathrm{Ord}$, leave $\mathrm{Ord}$ unchanged; otherwise insert $\beta(b)$
after the first occurrence of $\beta(a)$ when $a$ names a present
predecessor, and at the front when $a=\operatorname{none}$ or its predecessor is
absent. Call the result $\mathrm{Ord}(F)$. This fold reads creation links rather
than replaying transactions.
\[
\operatorname{query}(F)=\operatorname{mapM}
  \bigl(b\mapsto\operatorname{blockText}(F,b).\operatorname{map}
  (x\mapsto(b,x)),\ \mathrm{Ord}(F)\bigr).
\]
The result is $\operatorname{Option}((\mathbb N\times\mathbb N^*)^*)$;
any failed block read propagates $\operatorname{none}$. On honest closed versions,
the query equals the reference interpreter's reconstructed document.
The query computes from facts directly.

\paragraph{Independent sequential specification.}
\textbf{State.} A retained slot records an address, text atom and visibility bit:
\[
\begin{aligned}
\mathsf{Addr}&=\mathbb N\times(\{\mathsf{start}\}\uplus\mathbb N^2),\\
\mathsf{Slot}&=\mathsf{Addr}\times\mathbb N\times\mathbb B,\quad z=(a,v,\ell),\\
\Phi&=(\mathbb N\times\mathsf{Slot}^*)^*,\qquad D_0=[].
\end{aligned}
\]

Thus $D=[(b_1,L_1),\ldots,(b_n,L_n)]$ is an ordered block list. Define
\[
\operatorname{root}(j)=((j,\mathsf{start}),0,\mathsf{false}),
\]

\[
\operatorname{text}(L)=[\,v\mid(a,v,\mathsf{true})\text{ occurs in }L\,],
\]

\[
\operatorname{view}(D)=[\,(b_i,\operatorname{text}(L_i))\,]_{i=1}^{n}.
\]

Both comprehensions preserve list order. Deleted characters and cut markers
retain addresses. The following command rules are deterministic on every
ordered block list, including lists with repeated IDs or addresses. Let
$\operatorname{blocks}(D)$ list the block IDs and let
$\operatorname{owns}((b,L),a)$ mean that $L$ contains address $a$.
Write $\operatorname{owner}(D,a)$ for the first such block, if one exists.
Let $\operatorname{cut}(L,a)=(P,Q)$ cut immediately after the first
occurrence of $a$ in $L$, or return $(L,[])$ when it is absent. Freshness
of supplied slots is checked at issuance, not by an implicit command guard.

\textbf{Create.} Let $B=(b,[\operatorname{root}(j)])$; $\bot$ means no predecessor.
\[
D\xrightarrow{\operatorname{create}(b,j,\bot)}B::D
\quad[\,b\notin\operatorname{blocks}(D)\,].
\]
For a named predecessor $a$, define
\[
J_a(C)=\begin{cases}[C,B],&C.\mathsf{id}=a,\\{}[C],&\text{otherwise}.\end{cases}
\]
\[
D\xrightarrow{\operatorname{create}(b,j,a)}
\mathop{+\!+}_{C\in D}J_a(C)
\quad[\,b\notin\operatorname{blocks}(D),\ a\in\operatorname{blocks}(D)\,].
\]
Thus creation inserts after every block named $a$. A missing predecessor
or an already present new block ID admits no transition.

\textbf{Insert after an address.} For supplied slots $F$, define
\[
I_{a,F}(b,L)=\begin{cases}
(b,P\mathbin{+\!+}F\mathbin{+\!+}Q),&
 \operatorname{owns}((b,L),a),\ (P,Q)=\operatorname{cut}(L,a),\\
(b,L),&\text{otherwise}.
\end{cases}
\]
\[
D\xrightarrow{\operatorname{insert}(a,F)}
\operatorname{map}(I_{a,F},D)
\quad[\,\operatorname{owner}(D,a)\text{ exists}\,].
\]
Insertion edits every owning block, once after its first occurrence of the
address. A missing origin admits no transition.

\textbf{Erase named characters.} For a list of target addresses $X$,
\[
\operatorname{hide}_X(a,v,\ell)=\begin{cases}(a,v,\mathsf{false}),&a\in X,\\(a,v,\ell),&a\notin X.\end{cases}
\]

\[
D\xrightarrow{\operatorname{delete}(X)}
[\,(b_i,\operatorname{map}(\operatorname{hide}_X,L_i))\,]_{i=1}^{n}.
\]

Deletion is total: absent targets and previously hidden slots have no additional effect.

\textbf{Split at an address.} Select the first owner $(b,L)$ of $a$ and
put $(P,Q)=\operatorname{cut}(L,a)$. For a destination ID $d$ and hidden
marker $m$, define
\[
S_{b,d,P,Q,m}(j,L_j)=\begin{cases}
(j,P),&j=b,\\
(j,L_j\mathbin{+\!+}[m]\mathbin{+\!+}Q),&j=d,\\
(j,L_j),&\text{otherwise}.
\end{cases}
\]
\[
\begin{aligned}
D&\xrightarrow{\operatorname{split}(a,m,d)}
 \operatorname{map}(S_{b,d,P,Q,m},D)\\
&\quad[\,\operatorname{owner}(D,a)=(b,L),\ b\ne d,\
 d\in\operatorname{blocks}(D),\ m.\ell=\mathsf{false}\,].
\end{aligned}
\]
Thus the first owner supplies the prefix and suffix; every block with its
ID receives that prefix, and every block named $d$ appends the marker and
suffix. The rule allows an existing destination. In honestly prepared
splits, IDs and addresses are unique, and an atomic group first creates a
fresh destination immediately after the request's source block. The source
retains its prefix and the new block receives its suffix.

\textbf{Atomic updates and query.}
For $k=(c,u)$ and text $x=[x_0,\ldots,x_{n-1}]$, define the live slots
\[
\operatorname{slots}(i,k,x)=
 [(a(i,(c+j,u)),x_j,\mathsf{true})\mid0\le j<n].
\]
Let $b_k=\mathsf{issued}(k)$. The static event-label translation is
\[
\begin{aligned}
f(k,\mathsf{bootstrap}(x))={}&
 [\operatorname{create}(0,0,\bot),\\
 &\quad\operatorname{insert}((0,\mathsf{start}),
                   \operatorname{slots}(\mathsf{initial},k,x))],\\
f(k,\mathsf{create}(a))={}&
 [\operatorname{create}(\beta(b_k),\beta(b_k),a.\operatorname{map}(\beta))],\\
f(k,\mathsf{insert}(b,i,o,x))={}&
 [\operatorname{insert}(a(i,o),\operatorname{slots}(i,k,x))],\\
f(k,\mathsf{erase}(b,i,X))={}&
 [\operatorname{delete}([a(i,j)\mid j\in X])],\\
f(k,\mathsf{split}(b,i,o))={}&
 [\operatorname{create}(\beta(b_k),\beta(b_k),\beta(b)),\\
 &\quad\operatorname{split}(a(i,o),(a(i,k),0,\mathsf{false}),\beta(b_k))].
\end{aligned}
\]
The scalar predecessor in the last creation command abbreviates a present
optional predecessor. These are static labels, not calls to the concrete
renderer. The atomic label $\operatorname{upd}(e)$ denotes the group
$f(e)$; it is one update label. For $f(e)=[c_1,\ldots,c_k]$, update
admission requires every command in the group to succeed:
\[
\frac{D=D^{(0)}\xrightarrow{c_1}D^{(1)}\ \cdots\ \xrightarrow{c_k}D^{(k)}=D'}
{D\xrightarrow{\operatorname{upd}(e)}D'}.
\]

\[
D\xrightarrow{\F{rd}\Rightarrow\operatorname{some}(\operatorname{view}(D))}D.
\]

There is no query transition returning $\operatorname{none}$. Histories start at $D_0$ and may query only between complete update groups. This machine contains no transaction archive or sorting rule.

\textbf{Proved local positional effects.} For visible text $x$, inserted text $w$, and supported bounds:
\[
\begin{aligned}
\operatorname{insertAt}(x,i,w)&=\operatorname{take}(i,x)\mathbin{+\!+}w\mathbin{+\!+}\operatorname{drop}(i,x),\\
&\hspace{8pt}[\,0\le i\le |x|,\ w\ne[]\,],\\
\operatorname{splitAt}(x,i)&=(\operatorname{take}(i,x),\operatorname{drop}(i,x)),\\
&\hspace{8pt}[\,0\le i\le |x|\,],\\
\operatorname{eraseRange}(x,i,j)&=\operatorname{take}(i,x)\mathbin{+\!+}\operatorname{drop}(j,x),\\
&\hspace{8pt}[\,0\le i<j\le |x|\,].
\end{aligned}
\]

These are effects of actual local preparation, update and query on the
addressed block; all other blocks retain their contents and order. A split
places its new block immediately after the source. Concurrent histories carry
prepared identities rather than replaying numeric positions unchanged.


\paragraph{Issuance.}
\textbf{Original issuance authority.} Structural integration changes receipt, merge and observation. It retains the original protocol: explicit factory initialization, whole-version receipts, guarded ordinary requests and injective replica/session assignment $\eta$. Empty forks may precede initialization; later forks copy received snapshots. Bootstrap remains a separate factory action.

For $e=(t,r,\tau)$, $\tau=((c,u),p)$, reserve $w(\tau)=\max(1,\operatorname{itemCount}(p))$ counters and set $\operatorname{last}(\tau)=c+w(\tau)-1$. Insert/bootstrap count text atoms, split counts one marker, and create/erase count zero. With $S$ the reference transaction archive, the ordinary guard remains
\[
\begin{aligned}
G_\eta(e,S)\iff{}&u=\eta(r)\land c>0\\
&\land(\forall\tau'\in S.\ \operatorname{last}(\tau')<c)\\
&\land\operatorname{Prepared}(S,p).
\end{aligned}
\]

\[
\begin{aligned}
\operatorname{Prepared}(S,p)\iff\exists M,q.\quad
&\mathcal R(S)=\operatorname{some}(M)\\
&\land\neg\operatorname{earlyNoop}(q)\\
&\land\operatorname{prepareRequest}(M,q)=\operatorname{some}(p)\\
&\land\operatorname{OrdinaryEmits}(p).
\end{aligned}
\]

Here $\mathcal R(S)$ is the reference reconstruction from the archive sorted by source ID; preparation selects actual origins and checks request bounds. The ordinary-emission predicate excludes bootstrap and non-emitting empty requests. Preparation uses this reference state; direct positional preparation from
only the fact indexes is not established.

For completeness, the request preparation in this guard is the following
partial function. Let $\mathcal S_M(b)$ be the list of physical slices of
block $b$ in the reference interpreter's slice-tree preorder; failure to
find the block or extract a slice returns $\operatorname{none}$. A slice has a
retained start address and interior atoms. Let $X_M(b)$ be the concatenation
of its live text atoms, in this slice order. Put
\[
\operatorname{loc}_M(b,j)=
\begin{cases}
\operatorname{none}&\mathcal S_M(b)\text{ fails or }j>|X_M(b)|,\\
\operatorname{some}(X_M(b)_{j-1}.\mathsf{address})&0<j\le |X_M(b)|,\\
\operatorname{some}(s.\mathsf{start})&j=0,
\end{cases}
\]
where $s$ in the last case is the first slice with nonempty visible text,
or the last slice when all are empty; an empty slice list returns
$\operatorname{none}$. Address decoding inverts $\beta$ and the session encoding,
returning an instance key $i$ and origin $o$, or failing. The four
request forms prepare as follows:
\begin{itemize}
\item $\F{create}(a)$ returns $\mathsf{create}(a)$ for $a=\operatorname{none}$
  or a predecessor present in the reference forest; otherwise it fails.
\item $\F{insert}(b,j,x)$ fails for $x=[]$; otherwise it decodes
  $\operatorname{loc}_M(b,j)$ to $(i,o)$ and returns
  $\mathsf{insert}(b,i,o,x)$, failing if selection or decoding fails.
\item $\F{split}(b,j)$ uses the same selection and decoding, returning
  $\mathsf{split}(b,i,o)$.
\item $\F{erase}(b,j,k)$ fails when $j=k$ or when the selected list
  $Y=\operatorname{take}(k-j,\operatorname{drop}(j,X_M(b)))$ is empty.
  Decode every selected atom's address. The first must name a text item
  in an instance $i$, and every other target must name a text item in
  that same instance. Otherwise preparation fails. Return
  $\mathsf{erase}(b,i,\operatorname{sort}_{\rm source}(\mathsf{ids}(Y)))$.
  Sorting preserves duplicates; the source range compression followed
  by expansion is exactly this sorted list.
\end{itemize}
The early no-op predicate tests $x=[]$ for insertion and $j=k$ for
erasure, before reconstruction, and is false for create and split.
Ordinary emission excludes bootstrap and requires a nonempty inserted
text or erase-target list; create and split emit even with no text.
Deletion uses truncated subtraction and clamped list selection, and its
single-instance preparation fails on mixed-instance selections. The typed
core's closed shape proves the needed instance property for its supported
local requests; this is not a claim about the source's general
multi-instance grouping. Factory initialization is separately admitted
only while the source network is initial, at session $[65]$, using
bootstrap identity $(1,[65])$.

\paragraph{Mechanization and executable representation.}
The five merge verification conditions establish the fact carrier's laws.
A whole-document query refinement transfers the original protocol's
independent history theorem to this carrier, including canonical recursive
virtual merge bases. Issuance still depends on the original protocol and
reference interpreter. This protocol-scoped entry is outside the uniform
production registry. It is included in Table~\ref{tab:implementation},
whose counts include its protocol-specific proof dependencies.

\textbf{Compiled indexed refinement.} The executable core stores keyed births, erased IDs, cuts and creation links in hash maps/sets, plus exact descending child buckets and per-instance row counts. Queries use direct lookup/bucket callbacks and the checked creator fold. The engine additionally retains a transaction archive for identity checks and receipt/clock metadata. Thus the archive-free mathematical carrier and the executable engine have different state representations.

Let $\alpha(R)$ enumerate the core's four fact stores. Its proved invariant is
\[
\operatorname{Refines}(R,M)\iff\operatorname{Valid}(R)\land\operatorname{Valid}(M)\land\alpha(R)=\bigcup_{\tau\in M.\mathsf{archive}}\Delta(\tau).
\]

On successful core receipt and merge,
\[
\begin{aligned}
\alpha(R')&=\alpha(R)\cup\Delta(\tau),\\
\alpha(R_{A\sqcup B})&=\alpha(R_A)\cup\alpha(R_B).
\end{aligned}
\]

The engine preserves the displayed invariant while joining receipt metadata and checking archived transaction identities. Neither merge path replays archived payloads. Pure batches return either a complete state or an error; conflicting immutable keys are rejected. The end-to-end loading theorem starts at the actual empty engine, receives any ordering and duplicates of an honest closed version, and derives success, the invariant and the reference answer without caller-supplied acceptance or query-equality premises. The registered-query theorem connects native answers to versions of the MRDT. The compiled functions implement the native executable; external JavaScript/JSON conversion remains a tested boundary.


\textbf{Facts do not determine allocation.} The allocation counterexample gives two honestly issued erases with equal semantic fact sets but next counters 4 and 10. A function of facts alone cannot reconstruct the original allocator state. The executable therefore retains archive/reservation and local clock metadata. Receipt observes the transaction's reserved last counter; a local unused clock gap stays local and is not copied by merge or clone. These metadata rules do not weaken the issuance guard.

\paragraph{Boundary of the Notion result.}
The typed fragment omits the editor's merge-block and formatting requests.
The merge of replicated versions is a distinct operation from merge-block.
The pinned educational demo has three preserved failures after honestly
prepared merge-block requests: a later split at zero can move only part of
the visible suffix, a bold selection can leave both selected characters
plain, and a bold selection can affect an unselected character in another
block. Those traces use requests outside this fragment and do not refute
its create/insert/erase/split theorem. They are findings about the public
demo, with no established correspondence to Notion's production system.
The proof does not establish equivalence of the JavaScript number,
string, search-label or JSON decoder with the typed model.

\section{A New Definition of RA-Linearizability}
\label{sec:semantics}

RA-linearizability explains each query by a sequential execution of exactly
the updates visible at the queried version. Following the paper, we first
define the order that this execution must respect, relative to the event set
of that version, and then give its sequential specification. The formal
reference retains the paper's configuration predicate and also gives the
stronger criterion retaining specification conflicts used by the certified results.

\paragraph{Notation.}
For an event $e=(t,r,o)$, write $\doop(\sigma,e)$ for
$\doop(\sigma,t,r,o)$, and
$\pi(\sigma)$ for replaying a list.
The relation $\rcrel$ chooses the order of conflicting payloads;
$\visw$ records visibility in configuration $C$.

\begin{definition}[Events, effects, and payload policy]
\label{def:events}
Recall the MRDT signature $\mathcal D_\tau$ of the operational semantics:
its concrete states are $\Sigma$, its initial state is $\sigma_0$, and its
updates, queries, and answers are $O_\tau$, $Q_\tau$, and $Val_\tau$.
An event $e=(t,r,o)$ retains its timestamp and replica identifier.
Applying it is the total effector $\doop(\sigma,e)$; $\pi(\sigma)$ is
its left-fold extension to a list.
A payload policy is a relation $\rcrel\subseteq O_\tau\times O_\tau$; write
$a\xrightarrow{\rcrel}b$ for $\rcrel(a.o,b.o)$. It does not inspect the events' external
timestamps or replica identifiers.
A configuration supplies the event set $\mathcal E_C$ and visibility $\visw$ (with $C$ understood). Set
\[
 a\conc b\ \Longleftrightarrow\
 \neg(a\vis b)\land\neg(b\vis a),\qquad
 \operatorname{distinct}(a,b)\ \Longleftrightarrow\ a.t\ne b.t.
\]
Concrete raw commutation is
\[
 a\comm b\quad\Longleftrightarrow\quad
 \forall s\in\Sigma,\quad \doop(\doop(s,a),b)=\doop(\doop(s,b),a).
\]
\end{definition}
These are relations on full events, even though $\rcrel$ acts on payloads.
Throughout this reference, $\rcrel$ denotes only that operation relation or
its payload-only event lift. The generic Lean framework also accepts an
independently supplied \emph{event replay order}, which can inspect timestamps
and replica IDs. That interface is named \texttt{EventOrder}, with directed
predicate \texttt{replayBefore}; it is not another definition of $\rcrel$.
The paper1 certificates use the operation policy explicitly stated in their
hypotheses. A separate event replay order cannot be substituted silently.


\subsection{RA-Linearizability for MRDTs}
An absorber removes a concurrent $\rcrel$ edge only when it belongs
to the event set being ordered. This is the paper's version-local change to
the linearization relation. The invariant parameter below records a further
choice in the formalization: the concrete state domain on which commutation
is tested.

\begin{definition}[Invariant-scoped concrete commutation and closure]
\label{def:invariant}
For a fixed concrete state predicate $I:\Sigma\to\mathrm{Prop}$, define
\[
 a\mathrel{\comm_I}b\quad\Longleftrightarrow\quad
 \forall s\in\Sigma,\ I(s)\Longrightarrow
 \doop(\doop(s,a),b)=\doop(\doop(s,b),a).
\]
An invariant closure certificate at $C$ supplies
\begin{align*}
&I(\sigma_0),\\
&\forall s,e,\quad I(s)\land e\in\mathcal E_C\Longrightarrow I(\doop(s,e)),\\
&\forall l,a,b,\quad I(l)\land I(a)\land I(b)
 \Longrightarrow I(\F{merge}(l,a,b)).
\end{align*}
\end{definition}
Commutation here has no simultaneous-readiness or reissuability premise.
Closure includes replaying an already issued event out of causal order and
repeating it. A port must independently justify the predicate and its closure;
it cannot exclude a reachable state merely because that state refutes an equation.


\begin{definition}[Linearization relation and linear extension]
\label{def:order}
Fix a predicate $I:\Sigma\to\mathrm{Prop}$ and write $a\mathrel{\comm_I} b$ for
commutation on states satisfying $I$, as defined above.
For $E\subseteq\mathcal E_C$, use this \emph{same} predicate in both
noncommutation tests:
\begin{align*}
 a\mathrel{\operatorname{lo}^{C,I}_{E}}b\quad\Longleftrightarrow\quad
 &\bigl(a\vis b\land\neg(a\mathrel{\comm_I} b)\bigr)\\
 {}\lor{}&\bigl(a\conc b\land a\xrightarrow{\rcrel}b\land
 \neg\exists c\in E.\ b\vis c\land\neg(b\mathrel{\comm_I} c)\bigr).
\end{align*}
Only events in $E$ can suppress a concurrent policy edge as absorbers.
For $I(s)\equiv\mathrm{True}$ this is the raw order
$\loOn{E}$, using $\comm$ throughout.
A list $\pi$ is a \emph{linear extension} of $(E,R)$ when it lists each event
of $E$ exactly once, lists no other event, and places $a$ before $b$ whenever
$a,b\in E$ are distinct and $aRb$. We also say that $\pi$ enumerates $E$ and respects $R$.
\end{definition}
For an irreflexive relation this is the paper's linear-extension definition.
The checked list-order predicate compares distinct positions; it does not
reject a diagonal edge by itself. Therefore use the paper's usual definition
only after excluding such edges. The guarded no-chain law excludes payload
self-edges, and visibility is irreflexive. The direct lifting theorem states
order irreflexivity explicitly rather than requiring replay laws.
Neither order is the full visibility relation. In particular,
causal implementation-commuting events may be reordered by this order.
Readiness adds causal constraints to implementation replay; it does not
silently redefine the public semantic order.

\begin{definition}[Sequential specification and specification conflict]
\label{def:history}
For the operation alphabet $O_\tau$, let labels be
$\operatorname{upd}(x)$, $x\in O_\tau$, and $(q\Rightarrow v)$.
A history specification $\Spec$ is a prefix-closed set of finite label lists
containing the empty list. As in the paper, a labelled transition system
$\Spec=\langle L,\Phi,\phi_0,\longrightarrow\rangle$ gives such a
language: $\rho=\ell_1\cdots\ell_n$ is admitted when there are abstract states
$\phi_1,\ldots,\phi_n$ with $\phi_{i-1}\xrightarrow{\ell_i}\phi_i$.
Every finite run is admitted, so the language is prefix closed.
The formal interface does not assume determinism or totality; admission need
not determine a unique final abstract state.
Define contextual specification commutation by
\begin{align*}
 x\mathrel{\commS}y\quad\Longleftrightarrow\quad
 \forall\rho,\tau,\quad
 &\rho\cdot[\operatorname{upd}(x),\operatorname{upd}(y)]\cdot\tau\in\Spec\\
 &\Longleftrightarrow
 \rho\cdot[\operatorname{upd}(y),\operatorname{upd}(x)]\cdot\tau\in\Spec.
\end{align*}
Let $\F{ops}(\pi)=e_1.o\cdots e_n.o$ project the operation field
pointwise. The independent specification visibility relation is
\[
 a\mathrel{\operatorname{sv}^{\Spec}_C}b
 \quad\Longleftrightarrow\quad
 a\vis b\land\neg\bigl(a.o\commS b.o\bigr).
\]
\end{definition}

\paragraph{Prepared operation arguments.}
When a sequential rule needs an original input $x=(t,r,p)$, or an identified
action computed from it, prepare its arguments once at issuance:
\[
 o_x=(p,\operatorname{args}(x)),\qquad e_x=(t,r,o_x).
\]
The concrete update uses $(t,r,p)$ and ignores the added arguments; the
policy reads $p$, while the specification interprets the prepared arguments.
The issuance discipline checks both their consistency with the original input
and the original datatype guard. Full-input proof helpers use
$\operatorname{args}(x)=x$; payload-only specifications may omit redundant
packing. In every case $\F{ops}$ selects the complete operation field.

The checked transport maps source configurations and their stored event sets
through $x\mapsto e_x$, preserving states, visibility and implementation
order. Existing proofs using event-to-label maps remain history-construction
helpers; \nolinkurl{OperationLabels.ra} gives the pointwise-$\F{ops}$ criterion
for their mapped configurations. For invariant-scoped full-input proofs,
\nolinkurl{OperationLabelsInvariant.versionsRA} gives it at every mapped stored
version. These results concern the images of the certified source
configurations, not arbitrary executions over the enlarged operation alphabet.

\begin{definition}[Globally guarded replay laws]
\label{def:guards}
The replay assumptions are \textsc{rc-non-comm}, self-commutation,
\textsc{no-rc-chain}, and \textsc{cond-comm}. Write
$G_{\mathrm{raw}}(a,b)\equiv a.t\ne b.t\land a.r\ne b.r$ for the raw event guard.
The first two clauses split on equality of operation payloads, including
all operation arguments:
\begin{align*}
&G_{\mathrm{raw}}(a,b)\land a.o\ne b.o\quad\Longrightarrow\\[-3pt]
&\qquad\bigl(\neg(a\comm b)\ \Longleftrightarrow\
 a\xrightarrow{\rcrel}b\lor b\xrightarrow{\rcrel}a\bigr)
 &&\text{(\textsc{rc-non-comm})},\\
&G_{\mathrm{raw}}(a,b)\land a.o=b.o\quad\Longrightarrow\quad a\comm b
 &&\text{(self-commutation)}.
\end{align*}
No-chain retains its timestamp guards:
\[
 a.t\ne b.t\land b.t\ne c.t\quad\Longrightarrow\quad
 \neg(a\xrightarrow{\rcrel}b\land b\xrightarrow{\rcrel}c).
\]
For every $s\in\Sigma$, intervening event list $\beta$, and $a,b,c$ with
pairwise distinct timestamps, it also requires
\[
 a\xrightarrow{\rcrel}b\land\neg(b\comm c)\quad\Longrightarrow\quad
 \doop\bigl(\beta(\doop(\doop(s,b),a)),c\bigr)
 =\doop\bigl(\beta(\doop(\doop(s,a),b)),c\bigr).
\]
There is no different-replica guard on the last equation. Its absorber premise
is actual noncommutation, rather than the policy edge $b\xrightarrow{\rcrel}c$.
\end{definition}
The no-chain clause allows $a=c$ when the two adjacent timestamp guards hold;
therefore a payload self-edge is not rescued by external event freshness.
These global equations quantify over arbitrary concrete scratch states and
intervening lists. They are not the scoped laws below.
The split is equivalent to the former combined exactness law on the same
guarded domain: no-chain forbids a policy self-edge, so combined exactness
implies equal-payload commutation; conversely, the two payload cases recover
combined exactness. Self-commutation does not assert idempotence, nor does it
compare arbitrary same-replica instances. For certified datatypes use the
scoped formulation of Definition~\ref{def:scoped-laws}.

\paragraph{The paper's criterion.}
Let an active replica $r$ have head record $(\sigma,E)$ and let
$b=\F{query}(\sigma,q)$. The paper's Definition
``RA-linearizability'' requires, for every such $r$ and $q$, a list $\pi$ with
\[
 \pi\text{ a linear extension of }(E,\loOn{E}),\qquad
 \F{ops}(\pi)\cdot(q\Rightarrow b)\in\Spec,
\]
where $\F{ops}(\pi)=e_1.o\cdots e_n.o$. Executions satisfy this at every
configuration, and implementations at every execution. The global replay laws are assumptions of the paper's correctness argument,
rather than fields of the configuration predicate.

The certified interface strengthens this witness as follows. When operation
arguments have been added, use the mapped configuration and its event sets.
\begin{definition}[The invariant criterion with specification conflicts]
\label{def:ra}
For every allocated version $v$ with stored record $(s,E)$ and every query $q$,
there must exist \emph{one} list $\pi$ such that
\begin{enumerate}[nosep]
\item $\pi$ enumerates exactly $E$;
\item $\pi$ respects $\operatorname{lo}^{C,I}_{E}$;
\item $\pi$ respects $\operatorname{sv}^{\Spec}_C$;
\item $\F{ops}(\pi)\cdot
 [q\Rightarrow\F{query}(s,q)]\in\Spec$.
\end{enumerate}
\end{definition}
The universal invariant $I(s)\equiv\mathrm{True}$ recovers the raw
criterion, including specification visibility. Checking every allocated
version implies the corresponding guarantee for current replica heads.
The paper's Definition ``RA-linearizability'' instead checks active heads
and omits item~3. Both criteria use the same pointwise $\F{ops}$.
Prepared arguments retain original identities when the specification needs
them. Requiring the same witness to preserve specification conflicts
strengthens its order obligation.

An independent sequential simulation may use a relation, or an abstraction
function $\alpha:\Sigma\to\Phi$, to relate implementation states to the
\emph{specification's} states. This does not replace concrete equality in the
merge VCs, diamonds, or Definition~\ref{def:invariant}. Universal fold soundness
is one sufficient bridge. Certified Queue and RGA results instead establish
appropriate original-event witnesses for represented histories. Neither
implementation replay equality nor existence of an implementation fold alone
establishes item~4, and a specification-legal witness must also satisfy item~3.

\subsection{Canonical States and Certified Replay}
The paper's ``Uniqueness of the replayed state'' asserts both existence of a
linear extension and equality of the folds of \emph{all} linear extensions
for a supported, causally closed event set $E$
of its order under the three global replay assumptions. Its ``Canonical
state'' uses that assertion to define $\mathsf{can}_C(E)$, and ``Canonical
correctness'' requires every allocated version to store this state.
The checked scoped result below has a different domain: it compares legal,
visibility-respecting replays at represented prefixes. It supplies uniqueness
on that domain, rather than existence or uniqueness over all public-order
linear extensions.

\begin{definition}[Original issuance, certified executions, and readiness]
\label{def:issuance}
An issuance discipline is a predicate $G(e,s)$ checked at the materialized
replica head from which $e$ was minted. Mint honesty at $C$ requires, for every
$e\in\mathcal E_C$, a list $\pi_e$ satisfying
\[
 \pi_e\text{ enumerates }\{p\in\mathcal E_C\mid p\vis e\},\qquad
 \pi_e\text{ respects }\visw,\qquad G(e,\pi_e(\sigma_0)).
\]
An issued application is an actual raw store application with its original
head/version evidence and $G(e,s)$; non-application steps preserve the raw
fork/merge rule. A certified execution starts at the initial store and, at
every transition, retains mint honesty before and after the issued step.
The widened execution permits recursively synthesized virtual merge bases.
It has its own certified reachability relation, with the ordinary steps as its
base fragment.

A replay scope is $(C,F,R)$, where $F$ is its fixed eligible event set and
$R(H,s)$ records representation of the already replayed prefix $H$. Define
\[
 \operatorname{Ready}(H,e)\quad\Longleftrightarrow\quad
 e\in F\land e\notin H\land
 \forall p\in F,\ p\vis e\Longrightarrow p\in H.
\]
A replay is legal from $H$ by the inductive rules
\[
 \operatorname{Legal}(H,[]),\qquad
 \frac{\operatorname{Ready}(H,e)\quad
       \operatorname{Legal}(H\cup\{e\},\pi)}
      {\operatorname{Legal}(H,e::\pi)}.
\]
\end{definition}
The issuance guard is retained as evidence about the original mint. It is not
checked again when the effector is replayed at a different scratch state.

\begin{definition}[Scoped replay and policy obligations]
\label{def:scoped-laws}
The invariant replay laws require
\[
 R(H,s)\Longrightarrow I(s),\qquad
 R(H,s)\land\operatorname{Ready}(H,e)
 \Longrightarrow R(H\cup\{e\},\doop(s,e)).
\]
They also require the concrete diamond
$\doop(\doop(s,a),b)=\doop(\doop(s,b),a)$ whenever $R(H,s)$, both events are ready,
$a\conc b$, and neither direction of
$\operatorname{lo}^{C,I}_{F}$ orders them.
The accompanying policy laws split into
\begin{align*}
 a.o\ne b.o&\quad\Longrightarrow\quad
 \bigl(\neg(a\mathrel{\comm_I} b)\Longleftrightarrow
 a\xrightarrow{\rcrel}b\lor b\xrightarrow{\rcrel}a\bigr),\\
 a.o=b.o&\quad\Longrightarrow\quad a\mathrel{\comm_I}b.
\end{align*}
Both clauses quantify only over $a,b\in F$ that are concurrent, have distinct
timestamps, and come from different replicas. Commutation here quantifies over
\emph{every state satisfying $I$}, exactly as in
Definition~\ref{def:invariant}. No-chain is required for $a,b,c\in F$ with
$a.t\ne b.t$ and $b.t\ne c.t$, as in Definition~\ref{def:guards}.
The package consists of both replay laws and policy laws.
\end{definition}
An alternative represented-prefix commutation test instead quantifies over represented
prefixes where both events are ready. That definition is distinct from
$\mathrel{\comm_I}$; replacing the latter by readiness would make causal-pair tests
potentially vacuous. The same two-clause split applies to that alternative
using its represented-prefix commutation relation throughout. In either
formulation, no-chain makes the split equivalent to combined policy exactness.
If $F\subseteq\mathcal E_C$, the supported configuration's freshness and
per-replica visibility laws imply the metadata guards for distinct concurrent
events. They can then be left implicit, but membership and concurrency cannot.
Original issuance evidence restricts which events are eligible; state
reachability alone does not supply that restriction. The concrete replay
diamond above remains a separate obligation, as does the sequential-history
bridge in Section~\ref{sec:history-bridge}.

\begin{theorem}[Scoped implementation replay equality]
\label{thm:scoped-replay}
Suppose the replay laws of Definition~\ref{def:scoped-laws} hold,
$R(H,s)$, and $\pi_1,\pi_2$ enumerate the same event set $A$. If both lists are
legal from $H$ and each respects both $\visw$ and
$\operatorname{lo}^{C,I}_{F}$, then
\[
 \pi_1(s)=\pi_2(s).
\]
\end{theorem}
Its hypotheses are scoped replay laws, not the global class of
Definition~\ref{def:guards}. This theorem proves concrete implementation
agreement. Independent sequential legality is a further obligation.


\paragraph{Scoped canonical state.}
For a scope $(C,F,R)$, say that $\sigma$ is canonical from $\sigma_0$ when
there is a list $\pi$ enumerating $F$ such that
\[
 \operatorname{Legal}(\emptyset,\pi),\qquad
 \pi\text{ respects }\visw
 \text{ and }\operatorname{lo}^{C,I}_{F},\qquad
 \pi(\sigma_0)=\sigma.
\]
Under the replay laws and $R(\emptyset,\sigma_0)$, any two such states
are equal by Theorem~\ref{thm:scoped-replay}. Existence remains a witness
obligation.
This is the certified counterpart of the paper's canonical state; canonical
correctness still means concrete equality with a replay of the version's
own events. A separate bridge must show that the witness is admitted by
$\Spec$ and preserves its conflicts.

\section{Operational Semantics}
\label{sec:execution}

As in the paper's Section 3, the store is a labelled transition system
$\mathcal S_{\mathcal D}=(\mathcal C,\longrightarrow)$, parameterized by
\[
 \mathcal D_\tau=\langle\Sigma,\sigma_0,\F{do},\F{merge},\F{query},\rcrel\rangle,
 \qquad \tau=\langle O_\tau,Q_\tau,Val_\tau\rangle.
\]
Here $\F{do}(\sigma,t,r,o)$ applies an update, $\F{merge}$ takes an ancestor
state and two descendant states, and $\F{query}(\sigma,q)$ returns an answer.
The policy $\rcrel\subseteq O_\tau\times O_\tau$ is supplied on operations.
An event is $e=(t,r,o)\in\mathcal T\times\mathcal R\times O_\tau$; write
$\F{do}(\sigma,e)$ for $\F{do}(\sigma,t,r,o)$, and $e.t,e.r,e.o$ for its
components. The policy has no role in the transition rules; Section 4 uses it
to order events.

\begin{definition}[Configuration and execution]
\label{def:execution}
A configuration is $C=\langle S,H,P,\visw\rangle$, where
\begin{itemize}
\item $S$ maps allocated versions to pairs $(\sigma,E)$ of a concrete state
and an event set. Write $\sigma_v$ and $E(v)$ for these components.
\item $H$ maps active replicas to their head versions.
\item $P(v)$ lists the parents of $v$. Versions have natural-number ranks,
and each parent has smaller rank. Write $v\preceq w$ for reachability from
$v$ to $w$, including equality.
\item $\visw$ is event visibility; write $a\vis b$ when $a$ was visible to $b$.
\end{itemize}
Heads are allocated. Version $0$ stores $(\sigma_0,\varnothing)$.
Visibility endpoints occur in the union $\mathcal E_C$ of head event sets,
and each head contains the visible predecessors of its events. Distinct events
have distinct timestamps, $a\vis b$ implies $a.t<b.t$, and distinct events
from the same replica are visibility-comparable. Reachable stores additionally
have transitive visibility and causally closed histories at every allocated
version. The common-ancestor coherence property is justified below.

All rules preserve unmentioned components and map entries. In the following
rules $v$ is fresh, and its rank is larger than the rank of each listed parent.
The source and target must both satisfy the configuration conditions above.
\[
\inferrule*[left=\textsc{Apply}]{
 e=(t,r,o) \\ S(H(r))=(\sigma,E) \\
 t\text{ is fresh in }\mathcal E_C\text{ and every stored history} \\
 S'=S[v\mapsto(\F{do}(\sigma,t,r,o),E\cup\{e\})] \\
 H'=H[r\mapsto v] \\ P'=P[v\mapsto[H(r)]] \\
 \visw'=\visw\cup(E\times\{e\})
}{\langle S,H,P,\visw\rangle\xrightarrow{\F{apply}(t,r,o)}
  \langle S',H',P',\visw'\rangle}
\]
\[
\inferrule*[left=\textsc{Merge}]{
 S(H(r_1))=(\sigma_1,E_1) \\ S(H(r_2))=(\sigma_2,E_2) \\
 v_\top\text{ is a greatest common ancestor of }H(r_1),H(r_2) \\
 S(v_\top)=(\sigma_\top,E_\top) \\
 S'=S[v\mapsto(\F{merge}(\sigma_\top,\sigma_1,\sigma_2),E_1\cup E_2)] \\
 H'=H[r_1\mapsto v] \\ P'=P[v\mapsto[H(r_1),H(r_2)]]
}{\langle S,H,P,\visw\rangle\xrightarrow{\F{merge}(r_1,r_2)}
  \langle S',H',P',\visw\rangle}
\]
\textsc{Fork} takes an active source $r$ and fresh destination $r'$, creates a
fresh child $v$ of $H(r)$ with $S(v)=S(H(r))$, and sets $H(r')=v$.
The source head is unchanged. \textsc{Query} at $r$ returns
$\F{query}(\sigma_{H(r)},q)$ and leaves $C$ unchanged.

Initially only version $0$ and replica $0$ are allocated, $H(0)=0$, and
visibility and parent lists are empty. An execution is a finite sequence of
these transitions starting at this configuration.
\end{definition}
\paragraph{Changes to the paper's rules.}
Fresh timestamps must increase along visibility, not merely be distinct.
Fork allocates a child version holding the source snapshot. The ordinary merge
uses a greatest common ancestor in the precise sense below. Certified execution
adds an original-issuer premise $G(e,\sigma)$ to \textsc{Apply} and retains
evidence about the state at issuance (Definition~\ref{def:issuance}); the
unrestricted rule itself has no client guard.

\begin{definition}[Greatest common ancestor]
\label{def:gca}
A greatest common ancestor $g$ of $v_1,v_2$ satisfies
\[
 g\preceq v_1\land g\preceq v_2\land
 \forall w,\ (w\preceq v_1\land w\preceq v_2)\Longrightarrow w\preceq g.
\]
A maximal common ancestor need only have no strictly later common ancestor;
there may be several incomparable maximal common ancestors and no greatest one.
The store model carries the coherence property
$E(g)=E(v_1)\cap E(v_2)$ whenever an allocated greatest common ancestor exists.
\end{definition}

\begin{theorem}[Common-ancestor intersection; paper Lemma 3.1]
\label{thm:gca-intersection}
Suppose parents are allocated, histories grow along parent edges, and every
event has an allocated origin version containing it which is an ancestor of
\emph{every} version containing that event. Then for allocated $g,v_1,v_2$
with $g$ their greatest common ancestor,
\[
 E(g)=E(v_1)\cap E(v_2).
\]
\end{theorem}
The forward inclusion follows from history monotonicity. For a shared event,
its origin is common to both heads and therefore precedes $g$, proving the
reverse inclusion. The store-invariant proof supplies this justification for
the coherence field of Definition~\ref{def:gca}; it is not a statement about
arbitrary event labels attached to an arbitrary DAG.

\subsection{Multiple Merge Bases}

The ordinary rule does not cover a pair with several incomparable maximal
common ancestors. The following extension supplies a base for that case.

\begin{definition}[Recursive virtual merge base]
\label{def:virtual}
For a finite set of versions $T$ and a version $w$, let $M(T,w)$ be the list,
in increasing rank, of maximal elements of
\[
 \{x\mid x\preceq w\land\exists v\in T,\ x\preceq v\}.
\]
Write $\sigma_v$ for the stored state at $v$, using $\sigma_0$ as the total-function
default when unallocated; correctness uses allocated supports. Define the
base $B$ and scratch fold $F$ by
\begin{align*}
 B(T,w)&=
 \begin{cases}
 \sigma_0,&M(T,w)=[],\\
 F(\{v\},\sigma_v,\eta),&M(T,w)=v::\eta,
 \end{cases}\\
 F(T,\sigma,[])&=\sigma,\\
 F(T,\sigma,v::\eta)&=F(T\cup\{v\},\F{merge}(B(T,v),\sigma,\sigma_v),\eta).
\end{align*}
The virtual base of $v_1,v_2$ is $B(\{v_1\},v_2)$.
The widened merge step uses this state in place of $\sigma_g$ in
Definition~\ref{def:execution}, without requiring a greatest common ancestor.
Only the final merged version is allocated. The scratch folds do not create
replicas, events, or intermediate stored versions.
\end{definition}
The recursion is well-founded by the size of the joint ancestor support,
lexicographically with the pending list length. The execution theorem must
establish correctness of these recursive scratch states as well as ordinary
stored versions; replacing $g$ by an arbitrary maximal common ancestor is not
this construction.

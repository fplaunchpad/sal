\section{Correctness Against a Sequential Specification}
\label{sec:history-bridge}

Canonical correctness explains each stored state by a fold through the
implementation's own $\doop$. Together with replay determinacy it gives
convergence. To check the answers against a sequential specification, that same
sequence must also be admitted by the independent language $\Spec$ of
Definition~\ref{def:history}. This section states the paper's sequential lifting
theorem, distinguishes its literal RA criterion from the criterion retaining
specification conflicts, and gives an additional route for guarded operations.
Write $\pi(\sigma_0)$ for the merge-free fold of $\doop$ along $\pi$,
$\F{ops}_f(\pi)$ for its projected update labels, and $\loOn{E}$
for the raw implementation order of Definition~\ref{def:order}. The scoped bridge below also uses this raw order. Ports using the invariant
order $\F{lo}^{C,I}_E$ instead supply their own exact history witnesses.

\begin{example}[A convergent implementation which is not a set]
\label{ex:broken-set}
Take a one-element observed-remove set, represented by addition timestamps,
and change removal to the identity. Addition inserts its timestamp, and the
query reports whether the timestamp set is nonempty. Keep the merge
\[
 \F{merge}(l,a,b)=(l\cap a\cap b)\cup(a\setminus l)\cup(b\setminus l).
\]
Every pair of implementation updates commutes. With empty $\rcrel$,
$\loOn{E}$ is empty; replicas with the same events converge.
At one replica, perform
\[
 \mathsf{add}\ ;\ \mathsf{rem}\ ;\
 (\mathsf{rd}\Rightarrow\mathsf{true}).
\]
The implementation retains the addition timestamp, while the ordinary set
specification admits only $\mathsf{rd}\Rightarrow\mathsf{false}$ after this
sequence. It therefore fails the unrestricted sequential premise below.

There is a further distinction concerning the paper's literal RA definition.
The word $[\mathsf{rem},\mathsf{add}]$ enumerates the same events, respects the
empty implementation order, and explains the returned answer in the set
language. In fact this implementation satisfies the literal criterion on every
raw ordinary execution. In the set specification, addition and removal do not
contextually commute. Specification visibility requires the causal
addition-before-removal order, so the strengthened criterion rejects this
execution. The example refutes an identification of the two criteria; it does
not refute a lifting theorem with an unrestricted sequential premise.
\end{example}

\subsection{The paper's sequential lifting theorem}

\begin{theorem}[Lifting canonical correctness to literal RA]
\label{thm:sequential-lift}
Assume $\loOn{E}$ has no diagonal edge on each stored event set $E$.
Let every stored
version $(s,E)$ of $C$ have an exact canonical witness: a list $\pi$ enumerating
$E$, respecting $\loOn{E}$, with $\pi(\sigma_0)=s$.
Suppose also that, for every event list $\pi$ and every query $q$,
\begin{equation}
 \F{ops}_f(\pi)\cdot
 [q\Rightarrow\F{query}(\pi(\sigma_0),q)]\in\Spec,
 \qquad f(e)=e.o.
 \label{eq:total-fold-sound}
\end{equation}
Then every stored version, hence every replica head, satisfies the paper's
literal RA criterion with respect to $\Spec$.
\end{theorem}
This corresponds to Theorem 6.1 of the manuscript. Exact canonical witnesses
already respect the displayed raw order, so the lifting step needs no additional
replay laws. The conclusion here omits the extra specification visibility
clause in Definition~\ref{def:ra}.
% PaperPresentation.lean: uniform_versionsRA_of_paperOrder_witness.

\noindent\emph{Proof.}
Choose the exact canonical witness of the stored version. Substitute
$\pi(\sigma_0)=s$ into Equation~\eqref{eq:total-fold-sound}. The same word
provides the enumeration, implementation order, and admitted query answer.
The chosen word works for every query.\hfill$\square$

The premise ranges over arbitrary event lists, independently of any execution
or version. It compares two sequential machines and does not mention
$\F{merge}$. It does not claim that every permutation respects
$\loOn{E}$.

\paragraph{Discharging the premise.}
For a deterministic sequential specification with total updates and total
queries that leave the abstract state unchanged,
$\Spec=\langle L,\Phi,\phi_0,\rightarrow\rangle$, an abstraction
function $\alpha:\Sigma\to\Phi$ suffices if it satisfies
\begin{align*}
 &\alpha(\sigma_0)=\phi_0,\\
 &\alpha(\sigma)\xrightarrow{\ e.o\ }\phi'
   \quad\Longrightarrow\quad
   \alpha(\doop(\sigma,e.t,e.r,e.o))=\phi',\\
 &\alpha(\sigma)\xrightarrow{\ q\Rightarrow b\ }\alpha(\sigma)
   \quad\Longrightarrow\quad \F{query}(\sigma,q)=b.
\end{align*}
The last two clauses quantify over every concrete state, event, and query.
Totality supplies the displayed transitions; determinism fixes their targets
and answers. There is no issuance, freshness, or invariant premise.
Induction on $\pi$ relates its implementation fold to the abstract state reached
by $\F{ops}_f(\pi)$, and the query clause proves
Equation~\eqref{eq:total-fold-sound}. The checked simulation permits a relation
$R\subseteq\Sigma\times\Phi$ in place of a function: initially
$R(\sigma_0,\phi_0)$, each event preserves $R$, and related states agree on all
queries. The functional case takes $R(\sigma,\phi)$ to mean
$\alpha(\sigma)=\phi$.
% SequentialSimulation.lean: SequentialSimulation; SequentialSimulation.sound.

For an observed-remove set take
$\alpha(\sigma)=\{a\mid\exists t.\ (a,t)\in\sigma\}$.
Addition gains $a$, removal loses $a$, and membership queries agree.
For the implementation of Example~\ref{ex:broken-set}, removal leaves a
nonempty state unchanged while the abstract transition removes its element.
No abstraction function can satisfy these clauses: initialization and addition
force the resulting state to abstract to presence, while removal of that same
unchanged state forces it to abstract to absence. This contradiction explains
the failure of the sequential premise.

For both set implementations, a shared template now derives these projection
laws from record-level actions and their raw update equations. An addition may
replace tags for its own element, but must retain records for other elements;
removal filters all records for the removed element. Taking the image of the
record carrier then yields ordinary set insertion and removal. The frontend
checks the finite action laws and constructs the simulation. For Embedded RGA,
the shared induction instead assumes a legal selected history and a one-step
projection law. Proving insertion adjacency and deriving legality from the
certified execution remain datatype-specific obligations.

\paragraph{Retaining specification conflicts.}
For the stronger criterion of Definition~\ref{def:ra}, additionally require
\begin{equation}
 a\comm b
 \quad\Longrightarrow\quad
 f(a)\commS f(b).
 \label{eq:commutation-compatibility}
\end{equation}
Here $\comm$ is raw concrete commutation, as used in $\loOn{E}$; the right-hand relation is contextual language commutation.
By contraposition, every specification-conflicting visibility edge is an
implementation-conflicting visibility edge. Thus the same canonical word also
respects specification visibility. Equation~\eqref{eq:total-fold-sound} supplies
admission; compatibility supplies only the additional order obligation.
For an invariant-order variant, require the same implication with $\comm_I$
in place of raw commutation; raw compatibility alone does not discharge that
stronger premise. For full-event specifications take $f=\mathrm{id}$ and require the corresponding
full-event fold premise. Erasing event metadata is an explicit specification
choice, rather than a consequence of the bridge.

\subsection{Choosing a permitted history within a certified execution}

Global fold soundness can be unsuitable for a datatype whose public operations
have guards: an arbitrary word may name a nonexistent birth, reuse an identity,
or remove a live non-head. Restricting the implementation's representation
invariant does not automatically prove the independent language's guards.
A second route proves existence of a suitable history on the supported,
causally closed event sets of certified executions.

\begin{definition}[Execution-scoped history adequacy]\label{def:history-adequacy}
Fix an issuance discipline $G$, the raw implementation order $\loOn{E}$, and an independent
full-event language $\Spec$; take $f=\mathrm{id}$. They satisfy execution-scoped history adequacy when, for every
$G$-certified configuration $C$, every stored version $(s,E)$ and every query $q$,
there is a word $\pi$ such that
\begin{align*}
 &\pi\text{ enumerates }E\text{ exactly once},\\
 &\pi\text{ respects }\loOn{E}\text{ and }\operatorname{sv}^{f,\Spec}_C,\\
 &\F{ops}_f(\pi)\cdot
   [q\Rightarrow\F{query}(\pi(\sigma_0),q)]\in\Spec.
\end{align*}
The quantifier order is $\forall q\,\exists\pi$. The accepted answer describes the
merge-free fold, rather than the stored state $s$. Both order obligations and
language admission use the same $\pi$.
\end{definition}

\begin{theorem}[Representation and history bridge]\label{thm:history-bridge}
Fix the datatype, issuance discipline, independent language, and raw
implementation replay order. Define exact concrete canonicality by
\[
 \operatorname{Can}_{C,E}(s)\quad\Longleftrightarrow\quad
 \exists\pi.\ \pi\text{ enumerates }E\ \land\
 \pi\text{ respects }\loOn{E}\ \land\ \pi(\sigma_0)=s.
\]
This is an additional history-selection route, rather than a replacement for
the manuscript's unrestricted lifting premise. The concrete specialization
of the checked bridge has these assumptions:
\begin{enumerate}[nosep]
 \item the raw replay order has a proved uniqueness property: any two
       exact canonical states for the same supported event set are equal;
 \item every stored event set of the certified execution is supported, and its
       stored state is canonical for that set;
 \item execution-scoped history adequacy of
       Definition~\ref{def:history-adequacy} holds.
\end{enumerate}
Then every stored version satisfies the criterion with independent
specification visibility: one word enumerates its original events, respects
both required relations, and explains its stored query answer in $\Spec$.
Consequently all active heads satisfy that criterion. If the assumptions are
established at every configuration of a finite certified execution, the result
holds throughout that execution, including executions with recursively
synthesized virtual merge bases.
\end{theorem}

\noindent\emph{Proof.}
Adequacy supplies a word $\pi$ whose fold is canonical by its permutation and
order properties. Replay uniqueness identifies that fold with
the separately canonical stored state. Substitute this state equality in the
accepted history. Its word, permutation and two order properties do not change.
Apply the argument at each visited configuration for the execution claim.
The stored-state premise is where the merge argument enters; history adequacy
alone cannot discharge it.\hfill$\square$

This uniqueness assumption must be established for the chosen implementation
order; it is not automatic from scoped laws. For example,
Theorem~\ref{thm:scoped-replay} requires causally ready implementation replays;
it does not give equality of every pair of permutations respecting only the
invariant order. A concrete port may instead prove an exact representation
relation between its selected independent history and the stored live state,
as in Example~\ref{ex:queue}.

\begin{example}[Anchored enqueue with an independent FIFO]\label{ex:queue}
Enqueue records its issuer's observed tail and dequeue its observed head. The
implementation keeps ordered live records and carried coordinates; it stores
no removed birth records. The independent FIFO appends a fresh tagged value,
ignoring its recorded tail; it removes a named head, permits repeated removal
of an already removed identity, and rejects removal of a live non-head.
The absent-removal case requires a prior birth in the sequential prefix;
invented identities cannot be removed. Lack of tombstones does not mean lack
of metadata: carried coordinates preserve placement information and can grow
with their ancestry.

Head-only issuance implies that removed births form a causal downset among
enqueue events. Order the original dequeue events chronologically. Immediately
before an identity's first dequeue, emit its birth; emit subsequent duplicate
dequeues without another birth. Append the surviving births in their stored
coordinate order. The FIFO is empty between the removal blocks. The downset
property preserves causal enqueue conflicts, and surviving coordinates preserve
the remaining causal enqueue order. This one word has the exact final tagged
live list and satisfies both order obligations. The resulting theorem applies
to certified ordinary and recursive virtual executions with the unchanged
public tagged-head query.
\end{example}

\begin{example}[Fugue and a live-anchor specification]\label{ex:fugue}
The original Fugue issuer permits insertion naming a deleted birth. A certified
trace creates a birth, deletes it, then inserts a replacement anchored to that
birth. Its independent live-anchor language permits the replacement before the
deletion, but rejects it after the deletion. Specification visibility requires
the actual causal deletion-before-replacement order. No admitted word satisfies
that requirement, for any representation-state domain or arbitration policy.
The relevant implementation effectors nevertheless commute on the proved closed
invariant domain. Thus representation invariants repair an implementation-order
issue without repairing this issuance/specification mismatch. A successful
claim must reconcile those two interfaces explicitly.
\end{example}

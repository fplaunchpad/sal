## Main paper decisions

1. Count registry packages and case-study families separately. `Sal/MRDTs/Metatheory/ProductionLedger.lean` registers **18** exact `VerifiedMRDT` packages. `NotionCoreLedger` registers **one separately typed protocol entry**, imported into `RefactorLedger`. Published Balegas, the corrected Neem flags, anchored queue, and the three new Neem ports are further checked cases outside the uniform registry. The current measurement selects **26 configurations**, consolidated into **24 paper rows**; a paper total must say which catalogue it counts.
2. Do not write “previously unverified” for all adopted algorithms. FugueMax's source paper proves maximal non-interleaving; Peritext reports a convergence proof and property-based testing; TreeMove has Isabelle/HOL convergence/acyclicity proofs and an extracted implementation; Peepul/Neem already verified earlier families in F*. Sal's supported novelty is the specified Lean adaptation, its criterion and boundaries, reuse, source-specific semantic refinement, and ordinary/recursive histories. “First mechanization” also needs a dedicated prior-work search; this audit does not establish absence of earlier mechanizations.
3. Cite the actual source of a model and say when the representation is an adaptation. In particular, Sal's rich-text entries are not source-equivalence proofs for every original Peritext TypeScript operation; TreeMove uses canonical replay rather than the source undo/redo implementation; AegisSheet is a semantic reference for published intent tables, and equivalence to the pinned Scala artifact is refuted.
4. Notion is a particularly strong implementation-section case because it separates executable specification discovery from a checked positive theorem for a restricted typed model and preserves three bugs outside that fragment. Say “public educational demo”, never “verified Notion production”.

## Notion oracle method and exact positive theorem

`experiments/notion-oracle/run.py` downloads the seven official readable JavaScript modules into a temporary ES-module directory, rejects SHA-256 changes against `sources.json`, and executes first-party Node experiments with the unchanged modules. Third-party source is not committed. The seven modules are `replica.js`, `document.js`, `text-slice-tree.js`, `ids.js`, `rga.js`, `rich-text.js`, `search-labels.js`. Their official URLs and exact hashes are already in the manifest, observed 14 October 2026. This is a public-source behavioural oracle, not a simulator standing in for the demo and not a confirmed open-source-licence claim.

Experiments issue actual `Replica` client requests, compare local/merged views, exercise identity/clock/interval controls, and preserve literal transaction logs. Independent `positional-spec.mjs` and `identity-spec.mjs` provide comparison machines. Expected Lean SPOT answers remain hand-derived; oracle output is not their specification. The executable MRDT shell stores immutable identified transactions, checks base inclusion, unions payload-preserving branches, and reconstructs using source preparation/rendering. It therefore preserves the demo's observed failures; comparing this shell's renderer against the same source renderer does not independently prove renderer correctness.

The positive theorem is for **typed create/insert/delete/split**, an explicit factory/client protocol with injective session assignment, whole-version receipts, one allocator per session, and valid positions/bounded nonempty erase intervals. `NotionCoreMRDT.D` queries the actual typed interpreter and renderer with an `Option` result (execution failure is not replaced by empty text). `NotionCoreProtocol.versions_witness` derives one Sal event witness for every registered version, including ancestors: coverage, order, spec visibility, independent retained-slot document history, and actual query admission. `specification_ra` specializes to current heads. It covers ordinary and canonical recursive Sal version merges, which union transactions; these differ from user merge-block editing requests.

The proof derives freshness, origin providers, active-instance provenance, successful replay, interval partitions, normal root/leaf shape, inactive-title emptiness, local effects, labels, and common archive coupling from actual protocol reachability. These are not caller-supplied desired-output premises. Local insert/split/erase effects are connected to concrete MRDT update/query through `MRDTClient.issued_update` and effect theorems. Existing finite-store five VCs establish carrier representation; independent document history supplies meaning on the same witness. The claim is stronger than transaction-set convergence but remains within a source-audited typed boundary.

Excluded: JavaScript object/Map/JSON/exception extraction; arbitrary string/grapheme or oversized/clamped deletion behavior; unsafe numeric counters; unrestricted movement, removal, merge-block editing and formatting; production-service correspondence. Wire names are proved mathematically for positive safe-integer counters and UTF-16 session ordering; this is not a proof of JavaScript `Number.toString` extraction. Pre-factory empty peers are explicitly available, while post-factory forks copy snapshots and are not empty-source-replica creation.

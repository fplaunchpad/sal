# The (*) honesty-rebasing lemma: a re-coded configuration is honest modulo the order-embedding

*Design note for the single remaining obligation across the embed-GC
compaction stack (the shared single-epoch AnchorsFactorBeyond residue and
the multi-epoch CompatChain residue). Pen and paper; Python validation
owed then Lean. Self contained. No em-dashes.*

## 1. The obligation

Every embed-GC compaction theorem that preserves reads
(compactEliasDelta_settled_reads, eRecode_ra_transport,
multiEpoch_settled_reads) transports its witness through an order
embedding rather than re-deriving honesty. The one thing not discharged:
a re-coded configuration is not a native honest configuration. Compaction
renumbers sibling deltas to ordinals and fusion drops dead interior
levels, so the literal coordinates are no longer birth-chain telescopes
generated by the mint operations, and EHonest.chain_gen fails on them.
Yet the next compaction epoch, and the native (not by-transport)
RA-linearizability of a compacted epoch, both need eAnchored_exists,
which is currently stated from chain_gen. Call closing this (*).

## 2. The idea: track the structure eAnchored_exists consumes, not honesty

eAnchored_exists produces, for each live record, an anchor: its coordinate
factors as (an ancestor coordinate) ++ (a decodable code word), recursively
to the sentinel. That output is a property of the coordinate SET, not of
the operation history. Make it the invariant.

**I(C), the coded anchored forest invariant.** For configuration C with
live coordinate set L(C), there is a function anc : L(C) -> L(C) union
{sentinel} such that:

1. for every c in L(C), c = anc(c) ++ w for a nonempty tail w that
   decodes as one code word under the datatype's OrderedPrefixCode;
2. anc is well founded (iterating reaches the sentinel);
3. distinct live coordinates have distinct anc-paths (the forest is a
   tree per root; no two live nodes share a coordinate).

I(C) is exactly what eAnchored_exists returns, stated intrinsically.

## 3. The four steps

**(S1) EHonest implies I.** A native honest config's coordinates are birth
chains: coord(x) = coord(anchor(x)) ++ enc(delta). Take anc = nearest live
ancestor along the birth chain, w = the (possibly multi-level, if dead
ancestors intervene) tail. This is the content already in
eAnchored_exists / AnchorsFactorBeyond; refactor it to land in I rather
than in a bespoke ChainMintBeyond statement.

**(S2) StablePrefixMap preserves I (load-bearing).** Let F be a
StablePrefixMap (rank-renumber, or fusion, or their composition
StablePrefixMap.comp). Claim: I(C) implies I(F . C), with anc' the image
of anc.
- Rank-renumber: F(anc(c) ++ w) = F(anc(c)) ++ w', where w' = the
  renumbered edge (H3/ext gives F(p ++ e) = F(p) ++ (re-keyed e); the
  re-key is an order isomorphism on the sibling group, and the Elias-delta
  of an ordinal is a valid code word, so w' decodes). The tree structure
  (who is whose nearest live ancestor) is untouched.
- Fusion: a maximal dead unary spine collapses to its head. The invariant
  is over LIVE coordinates with nearest-LIVE-ancestor, and every collapsed
  node was dead, hence not in L(C). So for a live c whose birth chain
  passed through a fused dead spine, anc(c) (its nearest live ancestor)
  maps to a prefix of F(c): F(c) = F(anc(c)) ++ w'' where w'' is the fused
  edge (the surviving head code word plus c's own edge; a valid code word
  sequence). Nearest-live-ancestor is preserved because only dead
  interior levels were removed.
- H1 (injectivity, derived from H2) blocks two distinct live coordinates
  colliding under F, keeping condition 3.
- Composition: StablePrefixMap.comp is a StablePrefixMap (already proved),
  so I is preserved along a chain of epochs by induction.

**(S3) I implies eAnchored_exists.** Definitional once I is stated as the
output type of eAnchored_exists: anc is the anchor function.

**(S4) Discharge (*).** Single epoch: the bridge's AnchorsFactorBeyond is
re-derived from I directly (I is the ChainMintBeyond containment).
Multi-epoch: epoch-2 config C2 = F1 . C1 with C1 native honest gets I(C1)
by S1, I(C2) by S2, hence eAnchored_exists at epoch 2 by S3, closing
CompatChain's restG / mintG obligations. Both protocol halves fall to the
one invariant.

## 4. Why it is not circular

I is a structural invariant on the coordinate set. It is established from
EHonest for the FIRST epoch (S1) and PRESERVED by F thereafter (S2). It
never asks a re-coded configuration to be natively EHonest, which it is
not. The phrase honest modulo the order-embedding is precisely: carry I,
not EHonest, across epochs. The order embedding F is a forest isomorphism
on the live tree; I is the forest structure it preserves.

## 5. The genuine risk (what Python must stress)

The whole load is in S2's FUSION case: does fusion truly preserve
nearest-live-ancestor factorization, or can it break the edge decodability
or the tree structure? Specifically:
- (R1) after fusion, is every live coordinate still (nearest-live-ancestor
  image) ++ (a decodable code-word tail)? Fusion concatenates the dead
  head's code word with the surviving child's; check the concatenation is
  a valid code-word SEQUENCE the anchor walk can re-split (tail-attachment
  should give this, but validate).
- (R2) can two live coordinates that had distinct nearest-live-ancestors
  end up sharing one after fusion (a tree-structure break)? H1 says no in
  principle; validate empirically.
- (R3) the multi-epoch case: does I survive a SECOND fusion over already
  renumbered-and-fused coordinates (where deltas are ordinals, not
  original stamps)? This is the multi-epoch heart.

A countermodel to any of R1-R3 is a first-class result: it means I is too
weak and must be strengthened (the likely strengthening tracks the fused
dead head keys, which would connect (*) back to the chain-price retention
characterization: the living must remember the coordinates of the dead
they displaced). Validate on real editing traces (settled prefixes, where
compaction fires) and randomized honest states, single and multi epoch,
before any Lean.

## 6. Lean bill (after Python survives)

1. Define I (CodedAnchoredForest) over a configuration's live coordinates.
2. S1: ehonest_implies_I (refactor eAnchored_exists to conclude I).
3. S2: stablePrefixMap_preserves_I (the load-bearing lemma; the fusion

4. S3: I_implies_eAnchored (definitional bridge).
5. S4: re-state AnchorsFactorBeyond and CompatChain's restG/mintG from I,

## 7. Validation findings (Python, before Lean)

Harness: `whiteboard/litmus/honesty_rebasing_check.py`. It imports the
validated compaction model (`embed_compact_measure.py`: `AccountingReplay`,
`compact_cut`, `d_enc`, the same `entropy_measure.Replay` birth tree) and
adds nothing to it. I(C) is implemented as `check_I`, which reconstructs the
nearest-live-ancestor function PURELY from the live coordinate set (the
longest proper live-coord prefix, computed by a sorted-order stack walk),
decodes each tail with an inverse of `d_enc` (self-tested: it inverts
`d_enc(1..299)` and 2000 random code-word concatenations, and returns None on
truncation), and cross-checks the reconstructed forest against the ground
truth birth tree (`nla_tree` over `r.anchor`). F is `compact_cut`:
`fuse=False` is rank-renumber, `fuse=True` is renumber followed by spine
fusion (the composition; `compact.js` step 2 then 2b). Run with
`python3 whiteboard/litmus/honesty_rebasing_check.py`.

The checker has teeth (four negative controls, all correctly rejected): a
forced coordinate collision trips R2; a truncated code-word tail trips R1; a
forged spurious nesting trips the forest check; and the correct sibling coords
for the same tree pass. So the passes below are not a self-fulfilling oracle.

**Verdict: I is preserved under rank-renumber, fusion, their composition, and
a second epoch. No countermodel to R1, R2, or R3.** Per-case counts:

- S1 (EHonest implies I): 600/600 randomized honest states (real
  insert/delete op replay); 6/6 real editing traces (automerge-paper 104852
  live, seph-blog1 56769, friendsforever(_flat) 21362, clownschool(_flat)
  21148; sequential and concurrent). Native birth-chain coordinates
  reconstruct exactly the birth forest.
- S2 rank-renumber preserves I: 600/600 randomized, 6/6 traces. Injective
  (R2), and anc' is the image of anc (the nearest-live-ancestor NODE relation
  is identical before and after F).
- S2 fusion preserves I (R1 and R2 together): 600/600 randomized (fusion
  actually fired in 352), 6/6 traces (spines fused: automerge 941, seph 1394,
  the rest 15 to 39). R1 holds: a fused tail is a nonempty code-word SEQUENCE
  the anchor walk re-splits cleanly; the directed dead-spine case gives the
  tail `00` decoding to two words (the dead head's word plus the leaf's).
- R3 two-epoch: 500/500 both epochs. Fusion fired at epoch 1 in 253 trials
  and at epoch 2 in 342; every trial had a genuinely multi-code-word tail at
  epoch 2, so the second fuse over already-renumbered-and-fused coordinates is
  exercised, not vacuous.

### 7.1 Correction to condition 1 (the only change I owe the invariant)

Condition 1 as written ("w decodes as ONE code word") is falsified generically
and must read "w is a nonempty decodable code-word SEQUENCE (one or more whole
code words), well founded to the sentinel." The tail from a live node to its
nearest LIVE ancestor spans one word per intervening DEAD level, so it is
multi-word whenever a dead ancestor intervenes (native traces already, and
every fusion). S1 and the S2 fusion bullet already say "possibly multi-level",
so this only aligns the formal statement in section 2 with the rest of the
note. It is a wording fix, not a design change, and it does not touch S1, S3,
or S4.

### 7.2 I does NOT need the dead-head keys (the feared strengthening is not owed)

Section 5 anticipated that a countermodel would force I to track the fused
dead-head coordinates ("the living must remember the coordinates of the dead
they displaced"), connecting (*) to chain-price retention. The validation
shows this is unnecessary. R1 holds for a structural reason with no bookkeeping:
the code is prefix-free, fusion only concatenates WHOLE code words and only
deletes DEAD interior words, so any fused tail is a concatenation of whole
words and the anchor walk re-splits it by unique decodability alone. R2 holds
because a live node always contributes its own nonempty word (live nodes are
never fused) and prefix-freeness makes "longest live-coord prefix" coincide
with "nearest live tree-ancestor", so no two live coordinates collide and the
forest is the tree. I over the live coordinate set, with condition 1 read as a
sequence, is sufficient as stated; no dead-head-key field is needed.

### 7.3 R3 detail: "deltas are ordinals not stamps" is a non-issue, with the reason

The multi-epoch worry is that epoch 2 renumbers coordinates whose sibling
labels are a MIX of epoch-1 ranks (for pre-cut nodes) and birth deltas (for
nodes minted after the cut), so ranking by the stored label might disagree
with ranking by original timestamp and reorder or collide. The harness runs
epoch 2 both ways (`compact_cut` sorts by ts; `compact_cut_by_ordinal` sorts by
the stored label) and they produce identical coordinates in 500/500 trials.
The reason is a freshness inequality: a post-cut mint under a pre-cut parent P
has delta = t - ts(P) with t past the cut, and the number of P's pre-cut
children is at most the number of ticks in (ts(P), cut], so delta exceeds every
pre-cut rank of P. Hence in any mixed sibling group the new labels sort above
all old labels under either key, and label order equals ts order equals
current-coordinate order. Consequence for Lean: the epoch-2 renumber may sort
by the stored ordinal directly; it needs only this one-line freshness bound
(new delta greater than the pre-cut sibling count), not a re-derivation through
timestamps and not any strengthening of I.

### 7.4 Lean readiness

The design is Lean-ready as written, with the single wording change in 7.1
(condition 1: code-word sequence, not one word). The section 6 bill stands. The
fusion case of S2 (`stablePrefixMap_preserves_I`) rests on prefix-freeness plus
"live nodes are never fused", both already available; item 7.3 adds a small
freshness lemma to the multi-epoch corollary but no new invariant. Ties: the
concurrent traces reported zero (t, agent) ties in this replay, and injectivity
held regardless, so the ties caveat inherited from `embed_compact_measure` does
not bite I.
